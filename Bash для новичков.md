## 1. Что такое оболочка и терминал

### Оболочка (shell)

**Оболочка** — это программа-интерпретатор, которая принимает введённые вами команды, разбирает их и запускает. В Linux самая распространённая оболочка — **Bash** (Bourne Again SHell). Другие популярные: `zsh`, `fish`, `sh`, `ksh`. Bash встроена практически в каждый дистрибутив и является оболочкой по умолчанию.

Почему это важно понимать с самого начала: bash — это **не** то же самое, что терминал. Вы работаете с оболочкой, а терминал лишь доставляет ей набранный текст и показывает результат.

### Терминал

**Терминал** (точнее — эмулятор терминала) — это «окно», в котором вы печатаете команды. Выглядит как текстовое окошко с приглашением. Примеры терминалов: GNOME Terminal, Konsole, Kate, `xfce4-terminal`, `alacritty`, `kitty`, а также замаскированные под обычные окна терминалы вроде `tilix`.

### Как всё связано

```
┌──────────────────────────────────────────────────────────────────┐
│                          Эмулятор терминала                      │
│   окно, куда вы печатаете команды и видите вывод                 │
│                          │                                       │
│                          ▼                                       │
│   ┌─────────────────────────────┐                                │
│   │  Оболочка (bash/zsh/fish)   │   ← интерпретирует команды     │
│   └─────────────┬───────────────┘                                │
│                 ▼                                                │
│   ┌─────────────────────────────┐                                │
│   │  Ядро Linux (kernel)        │   ← управляет процессами,     │
│   └─────────────┬───────────────┘     файлами, железом           │
│                 ▼                                                │
│   ┌─────────────────────────────┐                                │
│   │  Железо (CPU, RAM, диски)   │                                │
│   └─────────────────────────────┘                                │
└──────────────────────────────────────────────────────────────────┘
```

### __Приглашение (prompt)

То, что вы видите перед курсором, — это приглашение оболочки. Оно обычно выглядит так:

```
user@hostname:~$
```

Обозначения:

- `user` — ваш логин;
- `hostname` — имя компьютера;
- `~` — текущая директория (знак `~` = ваш домашний каталог, например `/home/user`);
- `$` — вы обычный пользователь. Если вы root, будет `#`.

Проверить, какая оболочка вам досталась, можно командой:

```bash
echo $SHELL
```

### Зачем учить командную строку

- Скорость: многие операции в терминале выполняются быстрее, чем кликами в GUI;
- Автоматизация: те же действия легко записать в скрипт и выполнять по расписанию (cron, systemd);
- Работа на серверах: у удалённых серверов часто вообще нет графического интерфейса — только SSH и консоль;
- Гибкость: команды можно комбинировать в конвейеры, обрабатывая огромные объёмы данных одной строкой.

## 2. Как запустить терминал

### Локально

Самый быстрый универсальный способ в дистрибутивах на базе Ubuntu, Debian, Linux Mint:

```
Ctrl + Alt + T
```

В большинстве графических окружений терминал можно открыть и из меню приложений — набранное в поиске слово «Terminal» или «Konsole» сразу найдёт нужную программу.

### Удалённо (по SSH)

If вы работаете с сервером, терминал подключается по протоколу SSH:

```bash
ssh user@192.168.1.10
```

После ввода пароля (или при SSH-ключах — автоматически) вы окажетесь в командной строке удалённой машины. Подробнее о SSH — см. раздел про сеть.

### Проверка

После запуска терминала проверьте, что вы внутри:

```bash
whoami        # напечатает ваш логин
uname -a      # информация о ядре и системе
tty           # какой терминал к вам привязан
```

## 3. Структура команды

### Общий вид

```bash
имя_команды [опции (флаги)] [аргументы]
```

- **имя_команды** — что запускаем;
- **опции / флаги** — как настроить поведение (обычно начинаются с `-`);
- **аргументы** — над чем (или с чем) работает команда.

### Пример разбора

```bash
ls -l /home/user
│   │    │
│   │    └── аргумент: каталог, который показываем
│   └─────── опция -l: вывод в длинном формате
└────────── имя команды: список файлов
```

### Как bash читает команду

Каждая введённая строка проходит через несколько этапов:

```
Вы набираете:   ls -la /home/user
                     │
                     ▼
Bash разбивает строку на «слова»   →  ls | -la | /home/user
                     │
                     ▼
Bash понимает:  имя = "ls", опции = "-l -a", аргумент = "/home/user"
                     │
                     ▼
Bash ищет ls по переменной PATH   →  /usr/bin/ls
                     │
                     ▼
Ядро запускает процесс ls, который выводит результат в stdout
```

### Виды опций

| Вид | Пример | Пояснение |
| --- | --- | --- |
| Короткие | `-l` | одна буква, можно объединять: `-la` = `-l -a` |
| Длинные | `--all` | читаемые, с двумя дефисами |
| С аргументом | `-n 5`, `--lines=5` | значение через пробел или `=` |
| Конец опций | `--` | всё после `--` — аргументы, даже если начинается с `-` |

Пример: `ls -l --` покажет даже файл с именем, начинающимся с `-`.

### Полезные мелочи

- Разделяйте слова пробелами. Если имя файла содержит пробел — берите его в кавычки: `cd "Мои документы"` или экранируйте: `cd Мои\ документы`);
- Несколько команд в одной строке разделяются `;`: `cd /tmp; ls`;
- `&&` — выполнить следующую команду только если предыдущая успешна: `mkdir test && cd test`;
- `||` — выполнить следующую команду, если предыдущая завершилась с ошибкой.

## 4. Справка man, help, type, which, whereis

### man — главный справочник

Почти у каждой команды есть страница руководства:

```bash
man ls
man cp
man man          # справка о самой справке
```

Внутри man-страницы работают клавиши: `q` — выход, `Пробел` — страница вниз, `b` — назад, `/слово` — поиск по странице, `n` — следующее совпадение.

Поиск по всем man-страницам:

```bash
man -k "переменные"     # то же, что apropos поиск
apropos cpu             # что в системе связано со словом cpu
```

Разделы man (страницы нумеруются): 1 — команды пользователя, 5 — форматы файлов, 8 — команды администратора (требуют root). Например `man 5 crontab` расскажет о формате конфига, а `man 8 mount` — об административной команде.

### --help — быстрая справка

Почти каждая команда понимает `--help` или `-h`:

```bash
grep --help
cp --help
```

### help — для встроенных в bash команд

Некоторые команды (например `cd`, `pwd`, `export`) встроены в саму оболочку, и man-страниц у них нет. Для них работает `help`:

```bash
help cd
help export
```

### type, which, whereis, command

- `type` — показать, что такое команда: встроенная, алиас, внешняя программа;
- `which` — показать полный путь к командному файлу (если она внешняя);
- `whereis` — путь к файлу, исходникам и man-странице;
- `command -v` — надёжный способ проверить наличие команды в скриптах.

```bash
type ls
which python3        # /usr/bin/python3
whereis bash         # bash: /bin/bash /usr/share/man/man1/bash.1.gz
command -v curl
```

Полные пути особенно важны в cron и systemd — об этом будет ниже.

## 5. Навигация pwd, cd, ls

### pwd — где я

```bash
pwd        # печатает абсолютный путь текущего каталога
```

### cd — перейти в каталог

```bash
cd /etc          # абсолютный путь
cd documents     # относительный путь (от текущего каталога)
cd ..            # на уровень вверх
cd ../..         # на два уровня вверх
cd ~             # в домашний каталог
cd               # тоже в домашний каталог
cd -             # туда, где были до этого (печатает путь)
cd /             # в корень файловой системы
```

### Специальные имена

| Символ | Значение |
| --- | --- |
| `.` | текущий каталог |
| `..` | родительский каталог |
| `~` | домашний каталог текущего пользователя |
| `~влад` | домашний каталог пользователя `влад` |
| `/` | корень файловой системы |

### Общий вид файловой системы

```
/
├── /home      ← домашние каталоги пользователей (/home/user)
├── /etc       ← конфигурационные файлы системы
├── /usr       ← программы и библиотеки
├── /var       ← переменные данные: логи, очереди, кэш
├── /tmp       ← временные файлы (очищаются)
├── /bin, /sbin ← системные программы
├── /dev       ← устройства (диски, терминалы, /dev/null)
├── /proc      ← виртуальная ФС: информация о процессах и ядре
└── /run       ← runtime-данные о запущенных процессах
```

### ls — список файлов

```bash
ls              # просто имена
ls -l           # длинный формат: права, владелец, размер, дата
ls -a           # включая скрытые (с точкой)
ls -la          # комбинация: длинный формат + скрытые
ls -lh          # размеры «человеческим» размером (K, M, G)
ls -lt          # сортировка по времени изменения (новые сверху)
ls -lS          # сортировка по размеру
ls -lr          # обратная сортировка
ls -R           # рекурсивно по подкаталогам
ls -d */        # только каталоги
```

### Как читать вывод `ls -lh`

```
-rw-r--r-- 1 user group  12K июл  7 10:23 report.txt
drwxr-xr-x 2 user group 4,0K июл  6 09:00 projects

│            │    │      │    └─────────────── имя файла
│            │    │      └──────────────────── дата изменения
│            │    └─────────────────────────── размер
│            └──────────────────────────────── владелец и группа
└───────────────────────────────────────────── тип и права
```

- Первый символ: `-` обычный файл, `d` — каталог, `l` — символическая ссылка;
- Дальше три группы по три символа: права владельца, группы, всех остальных (`r` — чтение, `w` — запись, `x` — исполнение/вход в каталог, `-` — нет права);
- Количество ссылок на объект; владелец; группа; размер.

## 6. Работа с файлами cp, mv, rm, mkdir, touch, ln

### mkdir — создать каталог

```bash
mkdir projects            # создать один каталог
mkdir -p a/b/c/d          # создать сразу цепочку (промежуточные тоже)
mkdir -p лето/июль        # работает и с кириллическими именами
```

### touch — создать файл (или обновить дату)

```bash
touch notes.txt           # создать пустой файл
touch -t 202501011200 notes.txt   # выставить дату вручную
```

### cp — копирование

```bash
cp file.txt copy.txt          # копия в новое имя
cp file.txt /tmp/             # копия в другой каталог (то же имя)
cp -i file.txt /tmp/          # -i: спрашивать перед перезаписью
cp -r docs/ backup_docs/      # -r: рекурсивно (копировать каталог целиком)
cp -v file.txt other.txt      # -v: показывать, что делается
cp -p file.txt x.txt          # сохранить права и время
```

### mv — перемещение/переименование

```bash
mv old.txt new.txt            # переименовать
mv file.txt ~/docs/           # переместить в каталог
mv -i file.txt ~/docs/        # с подтверждением перезаписи
mv -v docs/ backup/           # показывать прогресс
```

### rm — удаление

```bash
rm file.txt                   # удалить файл
rm -i *.tmp                   # спросить по каждому файлу
rm -r каталог/                # рекурсивно удалить каталог
rm -rf каталог/               # рекурсивно и без вопросов
```

⚠️ **Осторожно с `rm -rf`!** Эта команда не спрашивает и не имеет корзины. `rm -rf /` удалит всю систему. Дважды проверяйте путь, попробуйте сначала `ls` по тому же пути.

### ln — ссылки

- **Символическая ссылка** (ярлык) указывает на имя файла. Если файл удалить, ссылка «порвётся».

```bash
ln -s /путь/файл  ссылка
ln -s /usr/bin/python3 python3_link
```

- **Жёсткая ссылка** — ещё одно имя для тех же данных. Работает, только если файл и ссылка в одной файловой системе.

```bash
ln файл  жёсткая_ссылка
```

Ссылки видно в `ls -l` по букве `l` в начале строки прав.

### Шаблоны (globbing)

Звёздочка и другие шаблоны разворачиваются оболочкой до списка файлов:

```bash
ls *.txt        # все .txt в текущем каталоге
rm log.?        # один любой символ вместо ?
cp *.log /tmp   # все .log
echo *.md       # оболочка превратит маску в имена файлов
```

## 7. Просмотр файлов cat, less, head, tail, wc

### cat — склеить и вывести всё

```bash
cat file.txt             # вывести содержимое на экран
cat a.txt b.txt          # вывести несколько файлов подряд
```

`cat` удобна и для создания файлов прямо в терминале:

```bash
cat > new_file.txt       # напишите текст, затем Ctrl+D
cat >> existing.txt      # добавить в конец существующего
```

После `cat > file` терминал перейдёт в режим ожидания ввода: печатайте строки и завершите **Ctrl+D**. Для коротких файлов `cat` отлично подходит.

### less — постраничный просмотр

`less` показывает большие файлы по частям:

```bash
less большая_логи.txt
```

Клавиши внутри `less`: `Пробел` — вниз на страницу, `b` — вверх, `g` — в начало, `G` — в конец, `/текст` — поиск, `n` — следующее совпадение, `q` — выход. Пользоваться `less` для чтения любых больших выводов — хорошая привычка: `ls -R | less`.

### head, tail — начало и конец файла

```bash
head file.txt            # первые 10 строк
head -n 20 file.txt      # первые 20 строк
head -c 100 file.txt     # первые 100 байт

tail file.txt            # последние 10 строк
tail -n 5 file.txt       # последние 5 строк
tail -f /var/log/syslog  # следить за файлом в реальном времени
```

`tail -f` — важнейший инструмент при работе с логами: он показывает новые строки по мере появления (выход — **Ctrl+C**).

### wc — подсчёт

```bash
wc file.txt            # строки, слова, байты
wc -l file.txt         # только строки
wc -w file.txt         # только слова
wc -c file.txt         # только байты
```

Частый приём: `grep -c` или `ls | wc -l` для подсчёта количества строк в выводе.

### Ещё немного

```bash
nl file.txt            # показать файл с номерами строк
tac file.txt           # показать строки в обратном порядке
rev file.txt           # перевернуть каждую строку задом наперёд
less file.txt          # всегда надёжнее cat для больших файлов
```

## 8. Поиск файлов find, locate

### find — полноценный поиск по критериям

Это самый мощный инструмент поиска. Синтаксис:

```bash
find <каталог поиска> <критерии> <действия>
```

```bash
find . -name "report.txt"      # по точному имени в текущем каталоге
find . -iname "report*"        # без учёта регистра, с маской
find /home -name "*.png"       # все картинки в /home
find / -name "clock.c" 2>/dev/null   # искать по всей системе, скрыв ошибки доступа
```

Критерий `-name` проверяет только имя файла (маленький регистр). Для поиска без учёта регистра есть `-iname`.

### Поиск по типу (-type)

| Символ | Тип |
| --- | --- |
| `f` | обычные файлы |
| `d` | каталоги |
| `l` | символические ссылки |
| `b`, `c` | блочные / символьные устройства |
| `p`, `s` | именованные каналы, сокеты |

```bash
find . -type d                    # только каталоги
find . -type f -name "*.conf"     # только файлы .conf
```

### Поиск по размеру (-size)

Знаки: `+` — больше, `-` — меньше, без знака — равно. Единицы: `c` — байт, `k` — килобайт, `M` — мегабайт, `G` — гигабайт.

```bash
find . -size +1G                 # всё больше 1 ГБ
find . -size -10k                # всё меньше 10 КБ
find . -empty                    # пустые файлы и каталоги
```

### Поиск по времени

```bash
find . -mtime +180               # не менялись последние 180 дней
find . -cmin -60                 # изменены за последний час
find . -atime +30                # не открывались 30+ дней
```

### Поиск по владельцу и правам

```bash
find /home -user petr 2>/dev/null     # все файлы пользователя petr
find / -perm 777 2>/dev/null          # файлы с правами 777
```

### Операторы: -and -or -not

```bash
find /home -user petr -and -size +1G 2>/dev/null
find /home \( -user petr -or -user mariya \) -and -size +1G 2>/dev/null
```

Скобки в команде экранируются обратным слэшем, чтобы оболочка не посчитала их своими.

### Действия с результатами

| Действие | Что делает |
| --- | --- |
| `-print` | печать путей (по умолчанию) |
| `-ls` | подробный вывод с размерами и inode |
| `-delete` | удалить найденные файлы |
| `-exec` | выполнить команду для каждого найденного файла |

```bash
find . -empty -delete                          # удалить все пустые
find . -name "*.jpg" -exec cp {} /backups \;   # скопировать картинки
find . -name "*.log" -mtime +30 -exec gzip {} \;  # сжать старые логи
```

`{}` — подстановка найденного файла; `\;` — окончание `-exec` (слэш нужен, чтобы `;` не съела оболочка). Сначала всегда запускайте поиск с `-print` и только потом применяйте удаление или перемещение.

### locate — быстрый поиск по базе

`locate` использует заранее построенный индекс и находит файлы мгновенно:

```bash
sudo updatedb        # обновить индекс (не всегда нужно — часто ставится в cron)
locate bashrc
locate -i report     # без учёта регистра
```

Минус: база не всегда свежая, только что созданные файлы могут не находиться.

### Вспомогательные

```bash
which nano       # путь к программе
whereis nano     # путь + man-страница
type ls          # тип команды
history | grep apt    # поиск в истории своих команд
```

## 9. Текст grep, sed, awk и регулярные выражения

Три утилиты-«рабочих лошадки» обработки текста решают разные задачи:

| Утилита | Назначение | Лучше всего подходит для |
| --- | --- | --- |
| `grep` | поиск строк по шаблону | фильтрация строк, поиск в логах |
| `sed` | потоковый редактор | замена и удаление текста |
| `awk` | обработка столбцов | анализ данных, разбор вывода команд |

Командой, обрабатывающей текст, можно управлять прямо в терминале — например: `grep "error" log.txt` (ищем строки с ошибками), `awk '{print $1, $3}'` (берём нужные столбцы), `sed 's/:/-/'` (заменяем символ).

### grep — поиск по шаблону

Синтаксис:

```bash
grep [опции] <шаблон> [файл|каталог]
```

Часто используемые ключи:

| Ключ | Действие |
| --- | --- |
| `-i` | игнорировать регистр |
| `-n` | показать номера строк |
| `-c` | только количество совпадений |
| `-v` | вывести строки БЕЗ совпадений (инверсия) |
| `-r` / `-R` | рекурсивно по каталогу (второй — идёт в симлинки) |
| `-l` / `-L` | только имена файлов с совпадениями / без |
| `-o` | вывести только совпавшую часть строки |
| `-w` | искать только целые слова |
| `-E` | расширенные регулярные выражения (как `egrep`) |
| `-F` | фиксированные строки, без регулярки (как `fgrep`, быстрее) |
| `-P` | Perl-совместимые регулярные выражения |
| `-A n`, `-B n`, `-C n` | контекст: после, до, до-и-после совпадения |
| `--color=auto` | подсветка совпадений |

Примеры:

```bash
grep -i "error" /var/log/syslog           # ошибки (без учёта регистра)
grep -n "^Linux" /etc/os-release          # строки, начинающиеся с Linux
grep -c "404" access.log                  # сколько таких строк
grep -v "INFO" application.log            # всё, кроме INFO
grep -r "password" /etc/                  # рекурсивно по каталогу
grep -l "TODO" *.py                       # файлы, где есть TODO
grep -o "[0-9a-f]\{40\}" file             # только hex-строки длиной 40
grep --color=auto "error" log.txt         # подсветка
grep -C 3 "panic" kernel.log              # ошибка и 3 строки контекста
dmesg | grep -i warn                      # поиск по выводу другой команды
history | grep apt                        # что я делал с apt
```

`grep` оперирует **строками**, `find` — **файлами и каталогами**. Для сложных задач их часто комбинируют:

```bash
find /var -type f -name "*.log" -print0 | xargs -0 grep -i "error"
```

Если `grep` кажется медленным на больших проектах — есть современная альтернатива `ripgrep` (`rg`): рекурсивна по умолчанию, игнорирует `.gitignore`, работает на порядок быстрее. Именно `rg` стоит движком поиска в VS Code.

### sed — потоковый редактор

Умеет менять, удалять и вставлять строки:

```bash
sed 's/apple/orange/' file.txt        # заменить первое вхождение в каждой строке
sed 's/error/ERROR/g' file.txt        # заменить все вхождения (g — global)
sed '/DEBUG/d' file.txt               # удалить строки, где есть DEBUG
sed -i 's/foo/bar/g' file.txt         # -i: редактировать файл на месте
sed -n '5,10p' file.txt               # вывести строки с 5-й по 10-ю
sed 's/^///' file.txt                 # добавить в начало каждой строки
```

Регулярные выражения в `sed` — «как в grep». Обратите внимание: без `-i` sed просто печатает результат в терминал, исходный файл не трогается. Чтобы переписать файл, нужен `-i`.

### awk — обработка по столбцам

`awk` разбивает каждую строку на поля (по умолчанию по пробелам) и позволяет выполнять вычисления:

```bash
awk '{print $1, $3}' file.txt          # 1-й и 3-й столбцы
awk -F ":" '{print $1}' /etc/passwd    # разделитель - двоеточие (имена пользователей)
awk '$3 > 50 {print $1, $3}' file.txt  # строки, где 3-й столбец больше 50
awk '{sum+=$3} END {print "Сумма:", sum}' file.txt
awk 'NR % 10 == 0' file.txt            # каждая десятая строка
ps aux | awk '{print $2, $11}' | head  # PID и команда каждого процесса
df / | awk 'NR==2 {print $5}' | sed 's/%//'   # процент занятого диска
```

Поля: `$1`, `$2`, … `$NF` — последнее, `NR` — номер текущей строки, блок `END { ... }` выполняется после чтения всего файла.

### Регулярные выражения: систематизация

Регулярное выражение («регулярка», regex) — это шаблон для описания набора строк. Понимание regex — основа работы и `grep`, и `sed`, и `awk`.

#### Основные элементы (базовый синтаксис POSIX BRE)

| Элемент | Значение | Пример |
| --- | --- | --- |
| `^` | начало строки | `^root` — строки, начинающиеся с root |
| `$` | конец строки | `root$` — строки, оканчивающиеся на root |
| `.` | любой один символ | `a.c` — abc, axc, a1c |
| `*` | 0 или более повторений предыдущего | `a*` — пусто, a, aa, aaa… |
| `[]` | любой символ из набора | `[aeiou]` — одна гласная |
| `[^]` | любой символ КРОМЕ набора | `[^0-9]` — любая нецифра |
| `\( \)` | группировка (и захват в BRE) | `\(ab\)*` |
| `\|` | или (в ERE/с -E) | `foo\|bar` |
| `?`, `+`, `{n,m}` | повторения | в расширенных (см. ниже) |

`grep` по умолчанию понимает базовые (BRE): `?`, `+`, `{n,m}`, `|` там работают как литералы. С `-E` (или `egrep`) включаются расширенные ERE:

| Элемент (ERE) | Значение |
| --- | --- |
| `?` | 0 или 1 повторение (`colou?r` — color, colour) |
| `+` | 1 или более (`go+` — go, goo, gooo) |
| `{n,m}` | от n до m повторений (`{11,13}`) |
| `{k}` | ровно k повторений |
| `|` | или (`fail(ed)?|error`) |
| `(…)` | группа и захват |

#### Спецклассы и другие метасимволы (совместимы с `grep -P` / PCRE)

| Символ | Значение |
| --- | --- |
| `\w` | буквенно-цифровой символ (a-z, A-Z, 0-9, `_`) |
| `\W` | всё, кроме `\w` |
| `\d` | цифра 0–9 |
| `\D` | не цифра |
| `\s` | пробельный символ (пробел, таб, перевод строки) |
| `\S` | не пробельный |
| `\b` | граница слова |
| `\B` | НЕ граница слова |
| `\n` | ссылка на n-ю скобочную группу (обратная ссылка) |

#### Примеры

```bash
grep "^Linux" file.txt                # начинается с Linux
grep "root\$" file.txt                # заканчивается на root
grep -E "err(or)?" file.txt           # error или err
grep -E "fail(ed)?|error" /var/log/syslog
grep -P "\b\w+@\w+\.\w+\b" file.txt  # простой шаблон e-mail (PCRE)
sed -E 's/[[:space:]]+/,/g' file.txt  # пробелы → запятые
awk '/^[0-9]+:/ {print}' file.txt     # строки, начинающиеся с цифр и двоеточия
```

Мнемоника на память: `\w` — **w**ord (слово), `\W` — всё что **W**ide-вне слова, `\d` — **d**igit (цифра), `\D` — **D**enies digit (нецифра), `\s` — **s**pace, `\S` — не пространство.

## 10. Права доступа и владельцы chmod, chown, umask, su, sudo

### Пользователи, группы, root

Linux — многопользовательская система. Каждый пользователь имеет:

- **UID** — цифровой идентификатор (обычно 1000 и выше для обычных пользователей);
- основную группу (**GID**) и дополнительные группы;
- домашний каталог (`/home/ivan`).

Группа объединяет пользователей и позволяет давать права сразу всем: создал группу `dev`, добавил в неё разработчиков и выдал права группе на каталог проекта.

Самое главное — пользователь **root** (UID 0): он может всё, включая уничтожающие команды. Поэтому в обычной работе вы находитесь под обычным пользователем, а права root получаете временно через `sudo`.

```
┌──────────────────────────────┐
│            root              │  UID 0, может всё
└──────────────┬───────────────┘
               │ sudo (временное повышение прав)
               ▼
┌──────────────────────────────┐
│      обычный пользователь    │  UID 1000
└──────────────┬───────────────┘
               │ членство в группах: users, sudo, dev, …
               ▼
┌──────────────────────────────┐
│   права на файлы rwx         │  владелец / группа / остальные
└──────────────────────────────┘
```

### Из чего состоят права

Каждый файл и каталог имеет три группы прав: для **владельца**, для **группы**, для **остальных**. Каждая группа — из трёх битов: `r` (read, чтение), `w` (write, запись), `x` (execute, исполнение / вход для каталога).

Примеры записи:

```
rwxr-xr--  755   владелец: чтение+запись+исполнение; группа и прочие: чтение+исполнение
rw-------  600   только владелец
rw-r--r--  644   владелец пишет, все читают (стандарт для файлов)
drwxr-xr-x 755   каталог: все могут заходить, менять — только владелец
```

### chmod — изменение прав

Числовой способ (цифры складываются из битов: 4=чтение, 2=запись, 1=исполнение):

```bash
chmod 755 script.sh      # владелец rwx, группа r-x, остальные r-x
chmod 644 file.txt       # владелец rw-, группа r--, остальные r--
chmod 700 private_dir    # только владелец
```

Символьный способ:

```bash
chmod u+x script.sh      # добавить исполнение владельцу
chmod g-w file.txt       # убрать запись у группы
chmod o+r file.txt       # дать чтение всем остальным
chmod a+r file.txt       # дать чтение всем (user+group+others)
chmod -R 755 каталог/    # рекурсивно по всем файлам и подкаталогам
```

Для каталога `x` означает «можно заходить и перечислять содержимое». Если нужно выдать только просмотр каталога — `chmod o+r каталог/`.

### chown, chgrp — смена владельца и группы

```bash
sudo chown ivan file.txt          # владелец → ivan
sudo chown ivan:dev file.txt      # владелец ivan, группа dev
sudo chown -R ivan:dev каталог/   # рекурсивно
sudo chgrp dev file.txt           # только группу
```

### umask — права по умолчанию для новых файлов

`umask` задаёт маску, которая «вычитается» из максимальных прав (666 для файлов, 777 для каталогов) при создании:

```bash
umask                  # показывает текущее значение (обычно 0022)
umask 022              # новые файлы 644, каталоги 755
umask 077              # новые файлы 600 — приватно (для скрытой папки с данными)
```

Маску уместно прописать в `~/.bashrc`, если всем новым файлам нужно давать минимум прав.

### su — переключение пользователя

```bash
su                  # стать root (введёте пароль root; без изменения каталога)
su -                # стать root, как при полноценном входе (учитывает окружение)
su - ivan           # стать пользователем ivan
exit                # вернуться к своему пользователю
```

### sudo — выполнить одну команду с правами root

```bash
sudo apt update                     # обновить списки пакетов
sudo systemctl restart nginx        # перезапустить службу
sudo -i                             # интерактивная сессия root
sudo -u ivan ls /home/ivan/         # выполнить от имени другого пользователя
sudo -k                             # забыть кэшированный запрос пароля
```

Кто может использовать `sudo`, определяется в файле `/etc/sudoers`. Редактируют его **только** командой `visudo` (она проверяет синтаксис):

```bash
sudo visudo
```

Права на sudo обычно выдаются добавлением пользователя в группу `sudo` (в Debian/Ubuntu) или `wheel` (в других дистрибутивах):

```bash
sudo usermod -aG sudo ivan
```

### Пользователи: добавление, удаление, пароль

```bash
sudo useradd -m ivan            # создать пользователя с домашним каталогом
sudo adduser ivan               # «дружелюбная» версия: спросит пароль и детали
sudo passwd ivan                # задать/сменить пароль пользователю
passwd                          # сменить пароль себе
sudo usermod -aG dev ivan       # добавить ivan в группу dev (-a = добавить, не затирать старые)
sudo gpasswd -d ivan dev        # убрать пользователя из группы
sudo deluser ivan               # удалить пользователя (дом без - без удаления)
sudo deluser --remove-home ivan # удалить пользователя вместе с домашним каталогом
id ivan                         # UID, GID и все группы пользователя
groups                          # группы текущего пользователя
sudo groupadd dev               # создать группу
```

Где хранится информация:

- `/etc/passwd` — список пользователей и их UID/GID;
- `/etc/shadow` — зашифрованные пароли (доступен только root);
- `/etc/group` — группы и их участники.

## 11. Процессы ps, top, kill, jobs, bg, fg, nohup

### Что такое процесс

**Программа** — это файл на диске (рецепт). **Процесс** — запущенная программа, которая живёт в памяти (приготовление по рецепту). Каждый процесс имеет уникальный **PID** (идентификатор) и **PPID** (PID родителя, который его запустил). Одну программу можно запустить несколько раз — получится несколько процессов.

```
           PID 1 (systemd / init)
              │
       ┌──────┼───────┐
       ▼      ▼       ▼
     shells  dbus   службы
       │
┌──────┼──────┐
▼      ▼      ▼
ls    grep   менее важные…
```

Посмотреть родственные связи можно командой `pstree`, а дерево процессов с PID — `ps -e -o pid,args --forest`.

### ps — снимок процессов

```bash
ps                       # процессы текущего терминала
ps aux                   # все процессы со всеми пользователями
ps -e -o pid,args --forest   # дерево процессов
ps -eafw                 # полная информация, однократно
ps aux | grep firefox    # найти процессы браузера
ps aux --sort=-%mem      # отсортировать по памяти
```

`ps aux` покажет: имя пользователя, PID, %CPU, %MEM, время старта/запуска, команду.

### top и htop — живые мониторы

```bash
top
htop            # улучшенная версия: стрелками по списку, F9 — убить
```

Полезные клавиши в `top`: `q` — выход, `P` — сортировка по CPU, `M` — по памяти, `k` — убить процесс (спросит PID), `r` — изменить приоритет. В `htop` можно ходить стрелками и нажимать `F9`.

### Сигналы и kill

Процессам можно отправлять **сигналы**. Основные:

| Сигнал | Номер | Что делает |
| --- | --- | --- |
| `TERM` | 15 | вежливо попросить завершиться (по умолчанию) |
| `KILL` | 9 | убить немедленно, без шанса сохранить данные |
| `HUP` | 1 | перечитать конфигурацию (или закрыть терминал) |
| `INT` | 2 | прерывание (это делает Ctrl+C) |

```bash
kill 1234                  # SIGTERM процессу с PID 1234
kill -9 1234               # принудительно
kill -1 1234               # перечитать конфиг (HUP)
killall firefox            # всем процессам с именем firefox
killall -9 sshd
pkill -f "python my_script"   # по шаблону в командной строке
```

Всегда начинайте с обычного `TERM` — у процесса есть шанс корректно завершиться. `-9` — последний аргумент.

### Приоритеты: nice, renice

Приоритет задаётся от -20 (максимальный) до +19 (минимальный). Чем меньше значение — тем выше приоритет.

```bash
nice -n 10 длинная_задача    # запустить с пониженным приоритетом
sudo renice -n 5 -p <PID>    # изменить приоритет запущенного процесса
```

Долгой и тяжёлой компиляции или рендеру можно дать низкий приоритет, чтобы не мешать работе.

### Дополнительные просмотры

```bash
pstree                  # дерево процессов
free -m                 # использование памяти и swap
lsof -p <PID>           # какие файлы открыты процессом
lsof /home/user        # кто сейчас использует файлы из каталога
strace -c ls >/dev/null # системные вызовы (диагностика)
dmesg                   # буфер сообщений ядра
```

Команда `lsof` и другие админ-инструменты часто требуют прав root.

## 12. Потоки и перенаправление, конвейер и tee

### Три стандартных потока

Каждая команда имеет три потока данных:

| Поток | Номер | Назначение |
| --- | --- | --- |
| **stdin** | 0 | ввод (обычно клавиатура) |
| **stdout** | 1 | вывод (обычно экран) |
| **stderr** | 2 | сообщения об ошибках (тоже на экран, но иначе) |

`stderr` существует отдельно, чтобы ошибки можно было отправить в другой файл или спрятать, не испортив основной вывод.

```
  клавиатура ──► stdin(0) ──► [команда] ──► stdout(1) ──► экран
                                            │
                                ошибки stderr(2) ──► 2> error.log

  экран ◄── stdout ── [команда2] ◄── stdin ──| pipe ── stdout [команда1]
```

### Перенаправление

| Символ | Значение |
| --- | --- |
| `>` | записать stdout в файл (перезаписать) |
| `>>` | добавить stdout в конец файла |
| `2>` | записать stderr в файл |
| `2>>` | добавить stderr в конец файла |
| `2>&1` | направить stderr туда же, куда stdout |
| `&>` | оба потока в файл (bash) |
| `<` | читать ввод из файла |
| `<<` | heredoc: многострочный ввод прямо из терминала |

Примеры:

```bash
ls > list.txt                 # список каталога в файл (перезаписать)
ls >> list.txt                # дозаписать в конец
grep error log.txt 2> err.log # ошибки (например, permission denied) в err.log
command > out.log 2>&1        # всякий вывод в один файл
command &>> app.log           # и stdout, и stderr дозаписать
find / -name "*.conf" 2>/dev/null   # спрятать ошибки доступа (не писать ничего)
ls > /dev/null                # вывод в «чёрную дыру»
cat < file.txt                # подать содержимое файла в stdin
cat file > /dev/null
```

`/dev/null` — специальный файл-«мусорка»: всё, что туда попало, исчезает. Наоборот, `/dev/null` часто используют для проверки, что команда отработала.

Диск занят / перенаправление куда попало — вот классическая ошибка cron: `>` без абсолютного пути (см. раздел про cron).

### Конвейер (пайп) `|`

Пайп передаёт **stdout одной команды в stdin другой**:

```bash
ls -la | less                  # пролистать длинный список
ps aux | grep -i ssh           # найти процессы ssh
dmesg | grep -i "error"        # ошибки из журнала ядра
cat /var/log/syslog | grep -i "warn" | tail -n 20
ls -la | wc -l                 # сколько записей в каталоге
df -h | grep -v tmpfs          # занятость дисков, без tmpfs
history | grep apt
```

Конвейер можно строить длинным: результат каждой следующей команды становится входом следующей.

### tee — и показать, и сохранить

`tee` делит поток: пишет в файл(ы) и одновременно передаёт дальше/на экран:

```bash
ls -la | tee /tmp/list.txt         # вывод на экран и в файл
command 2>&1 | tee -a log.txt      # логирование с добавлением, а не перезаписью
```

### xargs — превратить строки во входные аргументы

Иногда нужно передать вывод одной команды как *аргументы* другой (не как stdin):

```bash
find . -name "*.log" | xargs rm            # удалить все найденные
ps aux | grep python | awk '{print $2}' | xargs kill -9
git branch | fzf | xargs git checkout      # выбрать ветку интерактивно
```

### heredoc — многострочный ввод

```bash
cat > script.txt << EOF
Первая строка
Вторая строка
EOF
```

Всё между `<< EOF` и строкой `EOF` станет входными данными.

## 13. Переменные и окружение

### Переменные оболочки

Переменная — это имя с сохранённым значением. Создать и прочитать:

```bash
name="Иван"          # присвоить (без пробелов вокруг «равно»!)
echo "$name"         # вывести значение
echo $HOME           # без кавычек тоже работает, но с кавычками безопаснее
```

Правила:

- Присваивание без пробелов: `name="Иван"`, а не `name = "Иван"`;
- Читается через `$имя`, при сложных именах — `${имя}`;
- В двойных кавычках переменные подставляются, в одинарных — нет:

```bash
echo "Hello, $name"    # подставит значение
echo 'Hello, $name'    # выведет буквально $name
```

### Переменные окружения (environment)

Это переменные, доступные всем процессам, запущенным из оболочки. Экспорт в окружение:

```bash
export LANG=ru_RU.UTF-8
export PATH="$PATH:$HOME/bin"
```

Важнейшая переменная — **PATH**: список каталогов, где bash ищет исполняемые команды.

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/games
```

Посмотреть окружение целиком и искать по нему:

```bash
env                # все переменные окружения
printenv PATH      # одну переменную
env | grep -i lang
echo $SHELL $HOME $USER $LANG
```

Проверка/удаление:

```bash
set               # переменные оболочки
unset MY_VAR      # удалить переменную
readonly K=1      # константа
```

### Специальные переменные bash

| Переменная | Значение |
| --- | --- |
| `$HOME` | домашний каталог |
| `$USER` | имя текущего пользователя |
| `$HOSTNAME` | имя машины |
| `$SHELL` | путь к текущей оболочке |
| `$PATH` | список каталогов поиска программ |
| `$PWD` | текущий каталог |
| `$OLDPWD` | предыдущий каталог |
| `$0` | имя скрипта/команды |
| `$1 … $9` | аргументы позиционные |
| `$#` | количество аргументов |
| `$@` | все аргументы |
| `$?` | exit-код последней команды |
| `$$` | PID текущей оболочки |
| `$RANDOM` | случайное число (0–32767) |
| `$LINENO` | текущая строка скрипта |

### Подстановка команд `$( ... )`

Результат команды можно поместить в переменную или аргумент:

```bash
now=$(date)                 # текущая дата в переменную
echo "Сегодня: $(date +%F)"
files=$(ls | wc -l)
backup_dir="$(echo $HOME)/backup"
```

### Диалоговый ввод: read

```bash
read -p "Как вас зовут? " name
echo "Привет, $name!"
read -s -p "Пароль: " pass   # -s: не отображать вводимое
```

### Перенос настроек навсегда

Постоянные переменные и алиасы кладут в конфигурационный файл оболочки — `~/.bashrc` (для bash). Изменения вступают в силу после `source ~/.bashrc` или перезапуска терминала.

```bash
echo 'export MY_VAR="value"' >> ~/.bashrc
source ~/.bashrc
```

## 14. Условные операторы и циклы if, for, while, case

Bash умеет ветвления и циклы — как настоящий язык программирования. Это основа любых скриптов.

### if / elif / else

```bash
if условие; then
    команды…
elif условие2; then
    другие команды…
else
    остальное…
fi
```

Условием служит либо `test`-выражение в квадратных скобках, либо код завершения команды:

```bash
if [ -f /etc/os-release ]; then
    echo "Файл существует"
fi

if [ "$USER" = "root" ]; then
    echo "Мы root!"
else
    echo "Обычный пользователь: $USER"
fi
```

### Проверки `[ ... ]` (команда test)

Числовые: `-eq` равно, `-ne` не равно, `-gt` больше, `-ge` больше-или-равно, `-lt` меньше, `-le` меньше-или-равно.

Строковые: `=`, `!=`, `-z` пустая строка, `-n` непустая.

Файловые: `-f` обычный файл, `-d` каталог, `-e` существует, `-L` симлинк, `-r/-w/-x` читается/пишется/исполняется, `-s` непустой, `-nt` / `-ot` новее/старше.

Логика: `-a` (и), `-o` (или), `!` (не). Например:

```bash
if [ -f file.txt ] && [ -s file.txt ]; then
    echo "Файл существует и непустой"
fi

[ -d "$HOME/.ssh" ] || mkdir "$HOME/.ssh"
```

### Короткая логика: && и ||

```bash
mkdir каталог && cd каталог        # cd только если создалось
[ -f flag ] && ./script.sh && rm flag
grep -q ERROR log || echo "Ошибок нет"
```

### case — выбор варианта

```bash
case "$1" in
    start)  systemctl start служба ;;
    stop)   systemctl stop служба ;;
    restart) systemctl restart служба ;;
    *)      echo "Неизвестный вариант: $1" ; exit 1 ;;
esac
```

`*)` — вариант по умолчанию. Каждая ветка заканчивается `;;`.

### for — цикл по списку

```bash
for i in 1 2 3 4 5; do
    echo "Шаг $i"
done

for file in *.txt; do
    echo "Обрабатываю $file"
done

for n in $(seq 1 10); do echo $n; done

for arg in "$@"; do
    echo "Аргумент: $arg"
done
```

### while — цикл по условию

```bash
n=1
while [ $n -le 10 ]; do
    echo "Строка $n"
    n=$((n + 1))
done
```

### until, break, continue

```bash
until [ -f ready.txt ]; do   # повторять, пока НЕ наступит условие
    sleep 1
done

for i in {1..100}; do
    [ $((i % 2)) -eq 0 ] && continue   # пропустить чётные
    echo "$i"
done

for i in {1..100}; do
    [ $i -ge 10 ] && break             # прервать цикл
    echo "$i"
done
```

### Арифметика

```bash
echo $((5 + 3))          # 8
n=5; n=$((n * 2)); echo $n   # 10
echo $((2**10))          # 1024
```

Целая арифметика записывается в `$(( ... ))`.

## 15. Функции

Функция — именованный блок команд, который можно вызывать многократно:

```bash
greet() {
    echo "Привет, $1!"
}

greet Мир          # Привет, Мир!
greet Bash         # Привет, Bash!
```

### Объявление и вызов

```bash
function my_func {        # или без слова function
    echo "тело функции"
}
my_func
```

### Аргументы и возврат

Внутри функции доступны `$1…$n`, `$#`, `$@` — но это аргументы функции, а не скрипта. `return N` задаёт код возврата:

```bash
is_dir() {
    [ -d "$1" ]
}

if is_dir "$HOME"; then
    echo "Домашний каталог есть"
fi
```

### Локальные переменные

Переменные, объявленные без `local`, видны и снаружи функции. `local` ограничивает область видимости:

```bash
calc_sum() {
    local a=$1 b=$2            # локальные
    echo $((a + b))
}
```

### Функции полезнее алиасов

Алиас умеет только подставлять текст команды, а функция — полноценный код: ветвления, циклы, аргументы. Поэтому для сложной логики выбирают функцию.

Пример функции из реальных конфигов:

```bash
mkcd() {
    mkdir -p "$1" && cd "$1"
}

extract() {          # универсальный разархиватор
    case "$1" in
        *.tar.gz) tar -xzf "$1" ;;
        *.zip)    unzip "$1" ;;
        *.7z)     7z x "$1" ;;
        *) echo "Формат не поддерживается: $1" ;;
    esac
}
```

Функции прописывают в `~/.bashrc`, чтобы они были доступны в каждой новой сессии.

## 16. Скрипты shebang, аргументы, exit-коды

Скрипт — это файл с последовательностью команд. Скрипт можно писать на любом языке; для bash это просто набор строк с командами (и/или конструкциями из разделов 14–15).

### Минимальный скрипт

```bash
#!/usr/bin/env bash
# Первый скрипт

echo "Скрипт запущен"
date
echo "Домашний каталог: $HOME"
```

Разбор строк:

- `#!/usr/bin/env bash` — **shebang**: говорит системе, какой интерпретатор использовать. Писать нужно именно первой строкой файла;
- остальные строки — команды, которые выполняются по порядку.

### Как запустить

```bash
bash script.sh          # явный запуск через bash (права на исполнение не нужны)
./script.sh             # обычный запуск: требуется право на исполнение
chmod u+x script.sh     # дать себе право на исполнение
```

Скрипт можно поместить в `~/.local/bin` (и добавить этот каталог в PATH), тогда запуск — просто `script.sh`.

### Смена прав на исполнение

```bash
chmod +x script.sh
ls -l script.sh
# -rwxr-xr-x 1 user group  54 июл  7 10:23 script.sh
```

### Аргументы скрипта

Внутри скрипта доступны позиционные параметры:

| Переменная | Содержимое |
| --- | --- |
| `$0` | имя самого скрипта |
| `$1`, `$2`, … | первый, второй аргументы |
| `$#` | количество аргументов |
| `$@` | все аргументы по отдельности |
| `$*` | все аргументы одной строкой |
| `shift` | сдвинуть аргументы на один влево |

Пример:

```bash
#!/usr/bin/env bash
# backup.sh — простейший бэкап по аргументам

if [ $# -ne 2 ]; then
    echo "Использование: $0 <что_копируем> <куда>"
    exit 1
fi

cp -r "$1" "$2"
echo "Готово: $1 скопирован в $2"
```

Проверка количества аргументов — обязательная защита от «молчаливых» ошибок.

### Изменяемый путь к скрипту

```bash
DIR=$(cd "$(dirname "$0")" && pwd)   # абсолютный путь к папке скрипта
echo "Скрипт лежит в $DIR"
```

Это удобно, когда скрипт должен найти данные рядом с собой.

### Коды возврата и $?

Каждая команда возвращает число — код возврата (exit status). **0 — успех, любое другое — ошибка.**

```bash
ls /nonexistent
echo $?      # 2 (ошибка)
ls /tmp
echo $?      # 0 (успех)
```

Использование кода в скрипте:

```bash
grep -q "error" log.txt
if [ $? -eq 0 ]; then
    echo "Ошибки найдены!"
else
    echo "Всё чисто"
fi
```

### exit — явный выход из скрипта

```bash
exit 0    # успех
exit 1    # ошибка
exit 5    # свой код ошибки (обычно документируют в начале скрипта)
```

Код `exit` скрипта виден той программе, которая его запустила (например, cron заметит ненулевой код).

### Полный пример: скрипт мониторинга диска

```bash
#!/usr/bin/env bash
# disk-check.sh — предупредит, если диск занят более чем на 90%

THRESHOLD=90
LOG_FILE="$HOME/.disk_usage.log"

USAGE=$(df / | awk 'NR==2 {print $5}' | sed 's/%//')

if [ "$USAGE" -ge "$THRESHOLD" ]; then
    echo "⚠ Диск занят на $USAGE%!" | tee -a "$LOG_FILE"
else
    echo "Диск в норме: $USAGE%"
fi
```

Такие скрипты удобно вешать в cron (раздел 17).

### Разница: алиас → функция → скрипт

| Инструмент | Когда использовать |
| --- | --- |
| алиас | короткая замена одной команды (`ll`, `..`) |
| функция | логика из нескольких команд внутри сессии |
| скрипт | полноценная программа, которую можно запускать где угодно, в т.ч. из cron |

## 17. Планировщик задач cron

**cron** — классический планировщик Unix-подобных систем. Демон `crond` «просыпается» каждую минуту и проверяет таблицы заданий (`crontab`), запуская то, что подошло по времени.

### Формат задания

```
минута  час  день_месяца  месяц  день_недели   команда
0       2    *            *      *             /path/script.sh
```

| Поле | Допустимые значения |
| --- | --- |
| минута | 0–59 |
| час | 0–23 |
| день месяца | 1–31 |
| месяц | 1–12 |
| день недели | 0–7 (0 и 7 = воскресенье) или SUN, MON… |

`*` — «любое значение».

### Расшифровка типовых записей

| Задание | Что делает |
| --- | --- |
| `* * * * * cmd` | каждую минуту |
| `*/5 * * * * cmd` | каждые 5 минут |
| `0 * * * * cmd` | каждый час в начале часа |
| `0 0 * * * cmd` | каждый день в полночь |
| `0 3 * * * cmd` | каждый день в 03:00 |
| `30 * * * * cmd` | каждый час в 30 минут |
| `0 * * * 0 cmd` | каждое воскресенье в полночь |
| `0 0 * * 1-5 cmd` | пн–пт в полночь |
| `15 16 1 * * cmd` | 16:15 первого числа каждого месяца |
| `0 0 1 */3 * cmd` | каждый квартал |
| `0 0 1 1 * cmd` | раз в год |

Элементы можно комбинировать:

- **Диапазоны**: `0 0 1-7 * *` — первые 7 дней месяца;
- **Списки**: `0 0 1,15 * *` — 1-го и 15-го числа;
- **Комбинации**: `0 8-18/2 * * 1-5` — каждые 2 часа с 8:00 до 18:00 по будням.

### Специальные строки

| Строка | Равнозначна |
| --- | --- |
| `@reboot` | при старте системы |
| `@yearly` / `@annually` | `0 0 1 1 *` |
| `@monthly` | `0 0 1 * *` |
| `@weekly` | `0 0 * * 0` |
| `@daily` / `@midnight` | `0 0 * * *` |
| `@hourly` | `0 * * * *` |

### Управление заданиями

```bash
crontab -l              # показать задания текущего пользователя
crontab -e              # редактировать (откроет редактор)
crontab -r              # удалить ВСЕ задания
crontab -u ivan -e      # задания другого пользователя (root)
man 5 crontab           # формат файла
```

У каждого системного пользователя собственная таблица. Пользовательские crontab живут обычно в `/var/spool/cron/crontabs/`. Есть и системные файлы: `/etc/crontab`, `/etc/cron.d/`.

### Примеры реальных заданий

Записать дату на рабочий стол каждое 16-е число в 09:00:

```
00 09 16 * * echo "$(date)" > /home/user/Desktop/date.txt
```

Воспроизводить трек каждый день в 08:00:

```
00 08 * * * /usr/bin/mpg123 /home/user/Music/alarm.mp3
```

Проверить, что плеер установлен, до этого: `which mpg123`.

### Переменные окружения в cron

Cron работает в **минимальном окружении**: PATH часто ограничивается `/usr/bin:/bin`, пользовательские переменные и `.bashrc` не читаются. Поэтому:

1. **Всегда указывайте полные пути** к командам и файлам;
2. При необходимости задавайте переменные прямо в crontab:

```bash
PATH=/usr/local/bin:/usr/bin:/bin
SHELL=/bin/bash
MAILTO=admin@example.com
```

`MAILTO` — куда отправлять результаты работы задания (можно несколько адресов через запятую; `MAILTO=syslog` — в системный журнал).

Пример «опасной» и правильной записи:

```
* * * * * myscript.sh                 # может не найти скрипт и команды
* * * * * /home/user/scripts/myscript.sh
* * * * * /usr/local/bin/python3 /home/user/scripts/app.py
```

Полные пути легко найти: `which python3`, `whereis mpg123`.

### Логирование и тихие ошибки

Не отправляйте вывод «в никуда», иначе не узнаете об ошибках:

```bash
0 0 * * * /path/script.sh >> /var/log/script.log 2>&1
```

Раздельные потоки:

```bash
0 0 * * * /path/script.sh >> /var/log/script.log 2>> /var/log/script.err
```

Логи с ротацией по дате (в crontab `%` нужно экранировать как `\%`):

```bash
0 0 * * * /path/script.sh >> "/var/log/script_$(date +\%Y\%m\%d).log" 2>&1
```

### Наложение задач — пик нагрузки

Если задача выполняется дольше, чем интервал запуска, копятся параллельные копии. Решения:

Ограничение времени:

```bash
* * * * * timeout 300 /path/long_task.sh      # принудительно остановить через 5 минут
```

Блокировка от повторного запуска через `flock` (файл-флаг блокировки):

```bash
* * * * * /usr/bin/flock -n /tmp/task.lock /path/task.sh   # -n: не ждать
* * * * * /usr/bin/flock -w 10 /tmp/task.lock /path/task.sh # ждать до 10 с
```

Пропуск, если процесс уже бежит:

```
*/5 * * * * [ $(pgrep -c -f "script.sh") -eq 0 ] && /path/script.sh
```

Запуск только при низкой загрузке CPU:

```bash
0 22 * * * [ $(awk '{print 100-$NF}' /proc/loadavg | cut -d. -f1) -lt 30 ] && /path/backup.sh
```

Каскад задач с флагом успеха:

```bash
0 2 * * * /path/first.sh  && touch /tmp/first_ok
15 2 * * * [ -f /tmp/first_ok ] && /path/second.sh && rm /tmp/first_ok
```

### Когда cron, а когда systemd.timer

| Возможность | systemd.timer | cron |
| --- | --- | --- |
| Зависимости между задачами | да | нет |
| Запуск пропущенных задач | да (`Persistent=true`) | нет |
| Логирование | `journalctl` | файлы, `MAILTO` |
| Точность времени | до секунд | до минут |

Простое периодическое действие — cron. Нужны зависимости, точность по секундам, надёжные логи — systemd.timer (раздел 18).

Полезный помощник для тренировки синтаксиса — сайт <https://crontab.guru/>: вводите запись, и он объясняет, что она значит.

## 18. Основы systemd и systemctl

**systemd** — менеджер системы и служб современного Linux. Он запускает всё при старте, отвечает за службы (юниты) и заменяет собой старые механизмы init-скриптов.

### Управление системой

```bash
systemctl reboot            # перезагрузка
systemctl poweroff          # выключение
systemctl suspend           # сон
systemctl hibernate         # гибернация
systemctl rescue            # режим обслуживания (консоль root)
systemctl emergency         # аварийный режим
```

### Управление службой

```bash
systemctl start  nginx      # запустить
systemctl stop   nginx      # остановить
systemctl restart nginx     # перезапустить
systemctl reload nginx      # перечитать конфигурацию без остановки
systemctl enable nginx      # в автозагрузку
systemctl disable nginx     # убрать из автозагрузки
systemctl status nginx      # состояние + последние логи
systemctl is-active nginx   # активна ли
systemctl --failed          # какие службы упали
```

### Просмотр состояния

```bash
systemctl list-units                      # загруженные юниты
systemctl list-units --type=service       # только службы
systemctl list-units --type=service --state=running
systemctl list-unit-files                 # все установленные юниты
systemctl list-timers                     # таймеры (аналог cron)
systemctl list-dependencies nginx         # от чего зависит служба
systemctl cat nginx                       # показать содержимое юнит-файла
```

### Логи: journalctl

```bash
journalctl -u nginx                 # логи службы nginx
journalctl -u nginx -f              # в реальном времени
journalctl -b                       # логи текущей загрузки
journalctl -b -1                    # логи прошлой загрузки
journalctl -k                       # только логи ядра
journalctl -p err..alert            # только ошибки и выше
journalctl --since "1 hour ago"     # за последний час
journalctl -e                       # показать с конца
```

### Как устроен юнит

Юнит-файлы лежат в `/usr/lib/systemd/system/` (поставляются дистрибутивом) и `/etc/systemd/system/` (локальные свои). Типов юнитов несколько: `.service` (служба), `.socket`, `.timer` (таймер), `.target` (цель-группа), `.mount`.

Минимальный service-юнит:

```ini
[Unit]
Description=Мой сервис
After=network.target          # запускать после сети

[Service]
Type=simple                   # simple, forking, oneshot…
ExecStart=/usr/bin/myapp --flag
Restart=on-failure            # перезапуск при сбое
RestartSec=5s
User=appuser                  # от какого пользователя
Environment="APP_ENV=prod"

[Install]
WantedBy=multi-user.target    # когда включать
```

Часто используемые директивы секции `[Service]`: `WorkingDirectory`, `EnvironmentFile`, `ExecStartPre`/`ExecStartPost`, `ExecStop`, `LimitNOFILE`, `MemoryMax`, `ProtectSystem=strict`, `PrivateTmp=yes`.

Типы `Type`:

| Тип | Когда |
| --- | --- |
| `simple` | процесс не демонизируется (значение по умолчанию) |
| `forking` | процесс порождает потомка и завершается (nginx, apache); нужен `PIDFile` |
| `oneshot` | выполнился один раз и завершился (инициализация) |
| `notify` | служба сама сообщает о готовности |
| `dbus` | готова, когда зарегистрировала имя в D-Bus |

### Создание своей службы

```bash
sudo systemctl edit --force --full myservice          # создать/редактировать юнит
systemctl daemon-reload                               # после правок юнитов
systemctl enable myservice
systemctl start myservice
systemctl status myservice
```

Проверка включённости в скрипте:

```bash
if ! systemctl is-enabled --quiet nginx; then
    systemctl enable nginx
fi
```

См. также: `mask`/`unmask` (полный запрет запуска), `systemd-analyze blame` (что дольше всего грузилось), `systemc-analyze critical-chain` (почему затянулся запуск), `systemd-analyze` для времени загрузки.

## 19. История команд и автодополнение

### История команд

Bash запоминает всё, что вы вводили. Клавиши:

- `↑` / `↓` — шагать по истории;
- `Ctrl + R` — обратный **поиск** по истории (начните печатать фрагмент);
- `Ctrl + C` ещё раз в режиме поиска — отмена.

Организация истории:

```bash
history                  # весь список с номерами
history | grep apt       # искать команды с apt
history | tail -n 20     # последние 20 команд
!42                      # снова выполнить команду под номером 42
!!                       # повторить последнюю команду
sudo !!                  # повторить последнюю команду от root!
!$                       # последний аргумент предыдущей команды
history -c               # очистить историю текущей сессии
```

Переменные истории: `HISTSIZE` — сколько команд помнить, `HISTFILE` — файл (обычно `~/.bash_history`).

### Автодополнение (Tab)

- `Tab` — дополнить имя команды, файла, каталога;
- `Tab` + `Tab` — показать все варианты, если неоднозначно;
- `Alt + .` — вставить последнее слово предыдущей команды (удобно для имён файлов);
- Дополняются также имена хостов, варианты для git/apt и т.д.

### fzf — «прокачанный» поиск

`fzf` — интерактивный нечёткий фильтр: начинаете набирать и мгновенно получаете релевантные варианты. После установки он подменяет `Ctrl+R` красивым списком, а также добавляет:

- `Ctrl+T` — искать файлы в текущем каталоге;
- `Alt+C` — быстро перейти в выбранный каталог.

Примеры пайплайнов с fzf:

```bash
git branch | fzf | xargs git checkout        # выбрать ветку
ps -ef | fzf | awk '{print $2}' | xargs kill -9   # выбрать процесс
cd "$(find . -type d | fzf)"                 # перейти в каталог
```

### Установка

```bash
# Debian/Ubuntu
sudo apt install fzf
# Arch
sudo pacman -S fzf
```

## 20. Псевдонимы alias

Алиас — короткое имя для команды (или цепочки). Определение:

```bash
alias ll='ls -l'
alias la='ls -la'
alias ..='cd ..'
```

Использование:

```bash
alias                # показать все алиасы
alias ll             # показать один
unalias ll           # удалить
```

### Где хранить

Постоянные алиасы кладут в `~/.bashrc`. После изменения — `source ~/.bashrc` или новая сессия.

```bash
# ---------------------------------------------------------------
# Безопасное удаление и навигация
# ---------------------------------------------------------------
alias rm='rm -i'
alias ..='cd ..'
alias 2..='cd ../..'
alias 3..='cd ../../..'

# ---------------------------------------------------------------
# ls и удобный вывод
# ---------------------------------------------------------------
alias ls='ls --color=auto'
alias ll='ls -l'
alias la='ls -la'
alias lt='ls -lt'
alias grep='grep --color=auto'

# ---------------------------------------------------------------
# Быстрые команды
# ---------------------------------------------------------------
alias c='clear'
alias h='history | tail -n 30'
alias e='exit'
alias net='ip a'
alias df='df -h'
alias free='free -m'

# ---------------------------------------------------------------
# Git
# ---------------------------------------------------------------
alias gs='git status'
alias ga='git add'
alias gc='git commit -m'
alias gl='git log --oneline --graph'
alias gd='git diff'
```

Любые другие, полезные именно вам:

```bash
alias update='sudo apt update && sudo apt upgrade'
alias serve='python3 -m http.server'
alias myip='curl ifconfig.me'
```

Помните: алиас работает только на подстановку текста. Если нужна логика — функция (раздел 15), если полноценная программа с запуском отовсюду — скрипт (раздел 16).

## 21. Фоновые задачи и tmux

### Простые фоновые задачи

```bash
длинная_команда &        # запустить сразу в фоне, терминал свободен
Ctrl + Z                 # приостановить текущую команду (заморозить)
jobs                     # список фоновых/приостановленных задач
bg                       # продолжить приостановленную в фоне
fg                       # вернуть фоновую в «передний план»
```

Пример сценария:

```bash
sleep 30 &               # фоновый sleep
firefox &                # запустить браузер, не блокируя терминал
jobs                     # [1]- Запущ. sleep 30 ...
fg %1                    # вернуть первую задачу на передний план
```

Номера задач видно в `jobs` — ссылайтесь через `%N`.

### nohup и disown — пережить закрытие терминала

Обычно когда терминал закрывается, его фоновые процессы получают `HUP` (hangup) и умирают. `nohup` защищает от этого:

```bash
nohup длинная_команда > out.log 2>&1 &
```

`disown` — «отвязать» уже запущенную фоновую задачу от терминала:

```bash
длинная_команда &
disown
```

Для по-настоящему долгих задач удобнее `tmux` или `systemd`.

### tmux — менеджер сессий терминала

`tmux` создаёт слой между вами и процессами: отключился от сессии (detach) — процессы продолжают жить, вернулся — всё на месте.

```bash
tmux new -s work        # создать сессию с именем work
tmux ls                 # список сессий
tmux attach -t work     # вернуться в сессию work
tmux detach             # отсоединиться (внутри: Ctrl+B, затем d)
tmux kill-session -t work   # убить сессию
```

Создание сессии с фоновой задачей:

```bash
tmux new-session -d -s background-task 'watch date'
tmux attach -t background-task
```

Внутри сессии нужно помнить **префикс** — по умолчанию `Ctrl+B`. Сначала нажимаете префикс, затем клавишу действия:

| Комбинация | Действие |
| --- | --- |
| `Ctrl+B` `?` | показать все горячие клавиши |
| `Ctrl+B` `c` | новое окно (как вкладка) |
| `Ctrl+B` `n` / `p` | следующее / предыдущее окно |
| `Ctrl+B` `0…9` | окно с номером |
| `Ctrl+B` `%` | разделить окно по вертикали |
| `Ctrl+B` `"` | разделить окно по горизонтали |
| `Ctrl+B` стрелки | переход между разделениями |
| `Ctrl+B` `,` | переименовать окно |
| `Ctrl+B` `$` | переименовать сессию |
| `Ctrl+B` `d` | detach (отсоединиться) |
| `Ctrl+B` `x` | закрыть панель |

Типовой сценарий: подключились по SSH на сервер, подняли `tmux new -s build`, запустили долгую сборку, отключились (`Ctrl+B` `d`), сервер продолжает работать; позже `tmux attach`.

Если вы работаете в связке с GUI и часто держите открытыми несколько вкладок терминалов, tmux заменяет их одной сессией с несколькими окнами и панелями.

## 22. Работа с сетью ping, curl, wget, ip, ss

### ping — проверка доступности

```bash
ping 8.8.8.8                          # пинговать непрерывно (выход Ctrl+C)
ping -c 4 ya.ru                       # четыре пакета
ping -c 4 google.com
```

Ответ — RTT (время кругового пути). Таймауты и потери пакетов = сеть нестабильна.

### ip — адреса и интерфейсы

```bash
ip a                # все адреса, интерфейсы (в т.ч. IP)
ip addr show eth0   # конкретный интерфейс
ip route            # таблица маршрутизации (куда «ушёл» трафик по умолчанию)
hostname -I         # просто список своих IP
```

Утилита `ip` заменяет старые `ifconfig` и `route`.

### ss — порты и соединения

`ss` — наследник `netstat`, но быстрее и подробнее:

```bash
ss -tlnp            # слушающие TCP-порты + процессы
ss -tunp            # TCP и UDP соединения
ss -s               # сводка по сокетам
ss -tunap | column -t
```

Флаги: `-t` TCP, `-u` UDP, `-l` только слушающие, `-n` без имён (цифровые порты), `-p` показывать процессы.

### curl — HTTP-запросы из командной строки

```bash
curl https://example.com              # скачать тело ответа в stdout
curl -I https://example.com           # только заголовки ответа
curl -o file.html https://example.com # сохранить в файл
curl -O https://example.com/file.zip  # сохранить под именем из URL
curl -L https://short.url            # следовать за редиректами
curl -k https://self-signed.example   # не проверять TLS-сертификат
curl -u user:pass https://api.example/x   # базовая аутентификация
curl -H "Content-Type: application/json" -d '{"a":1}' https://api.example/post
curl https://api.github.com/users/octocat   # пример JSON
curl ifconfig.me                   # ваш внешний IP
curl ipinfo.io                     # информация о внешнем IP
```

Как проходит запрос:

```
 вы                   локальная машина                    сервер
 │                         │                               │
 │ 1. DNS-резолвинг:       │   как найти example.com       │
 │    curl спрашивает DNS  │ ─────────────────────────────►│   отвечает IP
 │                         │ ◄─────────────────────────────│
 │ 2. TCP-соединение:      │                               │
 │    handshake (SYN/ACK)  │ ─────────────────────────────►│
 │ 3. TLS (для https):     │                               │
 │    обмен ключами        │ ─────────────────────────────►│
 │    + проверка сертификата (если -k, пропускается)       │
 │ 4. Отправка запроса:    │                               │
 │    GET / HTTP/1.1       │ ─────────────────────────────►│
 │    Host: example.com    │                               │
 │ 5. Ответ:               │ ◄─────────────────────────────│  HTTP 200 OK
 │    статус + заголовки   │           тело ответа         │  + HTML
 │    + тело               │                               │
 │                         ▼                               │
 │            curl пишет ответ в stdout (и вы его видите)
 ```

Проверяйте код ответа: `curl -s -o /dev/null -w "%{http_code}\n" https://example.com`.

### wget — качалка с проверкой продолжения

```bash
wget https://example.com/file.zip
wget -c https://example.com/file.zip     # продолжить докачку после обрыва
wget -q -O out.txt https://example.com   # тихо, в файл с заданным именем
wget -r -l 2 https://example.com/        # рекурсивно, до глубины 2
```

### Диагностика маршрута и прочего

```bash
traceroute ya.ru        # поочерёдно: какие узлы проходит пакет
mtr ya.ru               # ping + traceroute в реальном времени
dig example.com         # DNS-запрос подробно
nslookup example.com    # простой DNS-запрос
which curl wget
```

### Файрвол: базовые iptables

Старый добрый сетевой фильтр (правила лучше хранить в файле):

```bash
sudo iptables -L                     # список правил
sudo iptables -L -nv --line-numbers  # с номерами строк и счётчиками
sudo iptables -F INPUT               # очистить цепочку INPUT
sudo iptables -A INPUT -s 192.168.0.104 -j DROP    # блокировать IP
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT # открыть порт 22
sudo iptables -P INPUT DROP          # политика по умолчанию DROP
sudo iptables-save > ~/iptables_config      # сохранить правила
sudo iptables-restore < ~/iptables_config   # загрузить из файла
```

### Задание 4. Отличие > и >>

Командой `>` запишите в файл одно слово, затем командой `>>` добавьте второе. Объясните разницу, проверив содержимое через `cat`.

<details>
<summary>Подсказка</summary>

```bash

cat combined.txt
```
`>` перезаписывает файл, `>>` дописывает.

### Задание 8. Права

Создайте файл `secret.txt` с правами rw-----, затем дайте всем право на чтение, потом снова верните исходные права. Какими будут числовые коды в каждой точке?

<details>
<summary>Подсказка</summary>

### Задание 11. Ветвление в скрипте

Напишите скрипт `check.sh`, который для переданного аргумента-пути сообщает: каталог, обычный файл или «нет такого». При отсутствии аргумента пусть выдаёт сообщение и код возврата 1.

<details>
<summary>Подсказка</summary>

```bash
cat > check.sh << 'EOF'
#!/usr/bin/env bash
if [ $# -eq 0 ]; then
    echo "Укажите путь"
    exit 1
fi
if [ -d "$1" ]; then
    echo "Каталог: $1"
elif [ -f "$1" ]; then
    echo "Файл: $1"
else
    echo "Нет такого: $1"
fi
EOF
chmod +x check.sh
./check.sh /etc
./check.sh /etc/hostname
./check.sh /no_such
```
</details>

### Финал: соберите всё вместе

Напишите скрипт `report.sh`, который:

1. берёт каталог из первого аргумента (по умолчанию текущий);
2. проверяет, что каталог существует;
3. выводит количество файлов и каталогов в нём;
4. топ-5 самых больших файлов;
5. завершает работу с кодом 0 при успехе и 1 при ошибке.

<details>
<summary>Подсказка</summary>

```bash
cat > report.sh << 'EOF'
#!/usr/bin/env bash
DIR="${1:-.}"

if [ ! -d "$DIR" ]; then
    echo "Каталог не существует: $DIR" >&2
    exit 1
fi

echo "Файлов:      $(find "$DIR" -maxdepth 1 -type f | wc -l)"
echo "Каталогов:   $(find "$DIR" -maxdepth 1 -type d | wc -l)"
echo "Топ-5 по размеру:"
du -ah "$DIR" 2>/dev/null | sort -rh | head -n 6 | tail -n 5

exit 0
EOF
chmod +x report.sh
./report.sh /usr/share/doc
```
</details>
