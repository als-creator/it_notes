# Интерактивный учебник-практикум: Bash-скриптинг для автоматизации

**Bash** (Bourne Again SHell) — командная оболочка и язык скриптов, стандартный интерпретатор в большинстве Linux-систем. Bash позволяет автоматизировать рутинные задачи: обработку файлов, управление серверами, развертывание сервисов и любые повторяющиеся операции. В отличие от одноразовых команд в терминале, Bash-скрипты — это программы, которые можно запускать многократно, передавать им параметры и переиспользовать.

> Не путайте с справочником по командам bash: здесь другой фокус — **автоматизация**. Пишутся не команды «на один раз», а переиспользуемые скрипты, которые делают работу за человека. Рассчитано на **Bash 5.x** (Linux). Выполняйте разделы по порядку: теория → схема → «Попробуй сам» → «Задание» → «Самопроверка» (ответы в разделе «Самопроверка»).

## Введение: зачем автоматизировать

Мы против ручной работы. Если вы выполняете в терминале одну и ту же последовательность команд чаще пары раз — лучше оформить её в скрипт. Скрипт — это файл с командами, который выполняет bash интерпретатор. Преимущества:

- **повторяемость** — результат одинаковый от запуска к запуску;
- **параметризация** — одним скриптом можно обрабатывать разные файлы, папки, серверы;
- **надёжность** — скрипт не забывает шаги и не отвлекается;
- **документирование** — скрипт сам описывает, как устроен процесс.

Автоматизация — это мышление: «как описать процесс так, чтобы машина сделала его за меня и не ошибалась».

### Схема: уровень абстракции

```
  РУКАМИ                          СКРИПТОМ
+----------------+              +----------------+
| cd ~/proj      |              | backup.sh      |
| mkdir logs     |              | 1. собрать список файлов
| cp *.log logs/ | — много раз—>| 2. создать архив
| ...            |              | 3. проверить размер
+----------------+              | 4. вывести отчёт
                                 +----------------+
                                        |
                                   cron (по расписанию)
                                        v
                                  автоматически
```

### Попробуй сам

Выполните в терминале простейший скрипт из одной строки:

```bash
bash -c 'echo "первый скрипт: $(date +%F)"'
```

## Сценарии использования

Bash-скриптинг закрывает широкий круг задач системного администратора и разработчика.

| Сценарий | Что автоматизирует |
|---|---|
| Бэкапы | копирование и архивация папок, баз данных, по расписанию |
| Мониторинг | сбор метрик (CPU, RAM, диск), проверка портов, отправка предупреждений |
| Развёртывание | деплой кода на сервер, миграции, настройка окружения |

| Отчёты | выборка из логов с awk/sed, формирование сводных таблиц |
| CI/CD | скрипты в GitLab CI / GitHub Actions как шаги пайплайна |
| Вводные сценарии | загрузка данных, парсинг CSV/JSON (совместно с jq) |

## Как bash исполняет скрипт

Bash читает скрипт **не одной строкой**, а построчно, в порядке следования. Важнейшее отличие от PHP: bash — интерпретатор, который выполняет команды по мере чтения, и **ошибка в строке 10 не помешает выполнить строки 1–9**. Если нужно «всё или ничего» — включают жёсткие режимы (`set -e`), об этом позже.

### Схема исполнения скрипта

```
        +-----------------------------------------------+
        |  bash script.sh                                |
        |                                               |
        |  1. читает строку  -> выполняет команду       |
        |  2. читает строку  -> выполняет команду       |
        |  3. читает строку  -> выполняет команду       |
        |  ...                                          |
        |  N. натыкается на ошибку -> если set -e НЕТ   |
        |     просто переходит к следующей строке       |
        +-----------------------------------------------+
```

Каждая команда по завершении возвращает код состояния `$?`: `0` — успех, любое другое число — ошибка. Скрипты на этом и строят логику: «если команда упала — сделай то-то».

### Попробуй сам

```bash
bash -c 'echo ok; nonexistent-command; echo "дожили до этой строки! $?"'
```

### Задание

Объясните вывод предыдущей команды: почему напечаталось «дожили до этой строки! 127»?

### Самопроверка

**Ответ:**

`nonexistent-command` не найдена, bash вернул код 127 (команда не существует). Но без `set -e` скрипт продолжился, и следующая строка выполнилась, подставив в текст `$?` = 127.

## Первый исполняемый скрипт

Скрипт становится «исполняемым» в два шага: файл получает бит исполнения, а первая строка указывает интерпретатор.

```bash
mkdir -p ~/scripts
nano ~/scripts/hello.sh
```

```bash
#!/usr/bin/env bash
echo "Привет из скрипта!"
```

Теперь делаем файл исполняемым и запускаем:

```bash
chmod +x ~/scripts/hello.sh
~/scripts/hello.sh
```

Либо запускаем без права исполнения — вызовом интерпретатора:

```bash
bash ~/scripts/hello.sh
```

### Схема запуска

```
+----------+  1. chmod +x  +------------------+
| файл     | ------------->| бит исполнения x  |
| hello.sh |               +------------------+
+----------+                       |
                                   v
+----------+  2. ./hello.sh   +-------------------+
|  ядро ОС | ----------------->| шебанг #!/usr/bin/env bash
|          |алгоритм: читает  | читает путь интерпретатора
+----------+ первую строку    | ОС запускает bash
                                  |
                                  v
                            +-------------------+
                            | bash выполняет    |
                            | строки скрипта    |
                            +-------------------+
```

### Попробуй сам

Выполните весь цикл из примера у себя. Убедитесь, что `./hello.sh` (со слешем) работает, а `hello.sh` без `./` — нет: переменная окружения `PATH` не содержит текущую папку.

## Шебанг и поиск интерпретатора

Первая строка скрипта `#!` (произн. «шебанг») сообщает ядру, какой интерпретатор запускать. Два популярных варианта:

```bash
#!/bin/bash      # жёстко: именно /bin/bash
#!/usr/bin/env bash  # поиск bash в PATH (вдруг он не в /bin)
```

Скрипты, написанные «по-портовому», начинаются с `#!/usr/bin/env bash`.

### Схема: почему env?

```
#!/bin/bash            # путь жёстко зашит. На macOS bash живёт в
                       # /opt/homebrew/bin — вариант сломан!
#!/usr/bin/env bash    # env найдёт bash через PATH и запустит его
```

Важно: если файл запускают как `bash script.sh`, шебанг **игнорируется** — интерпретатор уже задан командой.

### Попробуй сам

```bash
type -a bash        # где живёт bash?
file "~ (чужой скрипт)" | head -1
```

### Задание

Скачайте (или создайте) скрипт без шебанга и запустите его двумя способами: `./script` (упадёт с «Permission denied» или «command not found») и `bash script` (выполнится). Объясните разницу.

### Самопроверка

**Ответ:**

Без шебанга ядро не знает, чем исполнять файл, и даже с `chmod +x` попытка `./script` безуспешна. Вызов `bash script` явно указывает интерпретатор, поэтому скрипт выполняется независимо от шебанга.

## Переменные и подстановки

Переменная в bash — имя со значением-строкой. Присваивание **без пробелов** вокруг `=`.

```bash
NAME="Моя записная"
count=5
echo "$NAME: $count файлов"
```

### Схема подстановки

```
    NAME="Моя записная"
          |
          v
  "$NAME: $count файлов"
        |        |
        |        +--> счётчик уже раскрыт в строку "5"
        +--> подстановка значения переменной

  $VAR      -> значение переменной VAR
  $(cmd)    -> вывод команды cmd
  ${VAR:-default} -> значение или замена, если пусто
```

### Подстановки с умолчанием (стандарт автоматизации)

```bash
MODE=${MODE:-prod}        # если не задано — "prod"
FILE=${1:?укажите файл}   # нет аргумента — скрипт умрёт с сообщением
EXT=${PATH//'/home'/~}    # замена подстроками
LEN=${#NAME}              # длина строки
```

Имена переменных пишут в верхнем регистре — так отличают их от слов. Кавычки вокруг `"$VAR"` защищают от разбиения по пробелам (всегда кавычьте!).

### Попробуй сам

```bash
bash -c 'MSG="мир"; echo "Привет, $MSG"; echo "это команда: $(date +%Y)"'
```

### Задание

## Позиционные параметры и флаги getopts

Скрипт может принимать аргументы командной строки — «позиционные параметры».

```bash
#!/usr/bin/env bash
echo "Имя скрипта:    $0"
echo "Первый аргумент: $1"
echo "Второй аргумент: $2"
echo "Все аргументы:  $*"
echo "Сколько их:     $#"
```

Для флагов (`-v`, `-o file`) есть встроенный `getopts`.

### Схема getopts

```
  ./deploy.sh -v -e prod --help
        |   |
        |   +--> флаги перебираются в цикле
        |
  getopts "veh" option
      v = нет аргумента
      e = требует аргумент (двоеточие в строке: "ve:h")
      h = помощь
```

### Пример

```bash
#!/usr/bin/env bash
usage() {
    echo "Использование: $0 -e <env> [-v]"
    echo "  -e  окружение (dev|prod)"
    echo "  -v  подробный вывод"
}

env="dev"
verbose=0
while getopts "e:vh" opt; do
    case "$opt" in
        e) env="$OPTARG" ;;
        v) verbose=1 ;;
        h) usage; exit 0 ;;
        *) usage; exit 1 ;;
    esac
done

echo "Окружение: $env, verbose=$verbose"
```

### Попробуй сам

Скопируйте пример в файл `deploy.sh`, запустите: `./deploy.sh -e prod -v`, затем `./deploy.sh -h`.

### Задание

## Условные операторы

Условия в bash — команда `[ ]` (test) или продвинутая `[[ ]]` (только bash, не POSIX). Основное правило: **условие — это команда**, а команда «успешна» или «нет».

```bash
#!/usr/bin/env bash
file="settings.sh"

if [[ -f "$file" ]]; then
    echo "Файл $file существует"
elif [[ -d "$file" ]]; then
    echo "$file — каталог"
else
    echo "$file не найден"
fi

# проверка числа строк
lines=$(wc -l < "$file")
if (( lines > 50 )); then
    echo "Большой файл"
fi
```

### Полезные проверки

```bash
[[ -f path ]]   # обычный файл
[[ -d path ]]   # каталог
[[ -z "$v" ]]   # переменная пустая
[[ -n "$v" ]]   # непустая
[[ -e path ]]   # существует (что угодно)
[[ "$a" == "x" ]]  # равенство строк (в [[ ]] не нужны кавычки — безопасно)
[[ "$n" -gt 10 ]]  # числовое сравнение: -eq -ne -gt -ge -lt -le
[[ "$s" =~ ^[0-9]+$ ]]  # регулярное выражение!
[[ -r path ]] && echo "можно читать"   # сокращённая запись
```

### Попробуй сам

```bash
bash -c 'name="мир"; if [[ "$name" == "мир" ]]; then echo "Здравствуй, мир"; fi'
bash -c 'n=12; if (( n % 2 == 0 )); then echo "чётное"; fi'
```

## Циклы

Три цикла: `for` по списку, `while` по условию, `until` по отрицанию условия.

```bash
#!/usr/bin/env bash
# for по явному списку
for fruit in яблоко груша слива; do
    echo "Фрукт: $fruit"
done

# for по результату команды (замена слов)
for file in *.log; do
    echo "Обрабатываю $file"
done

# for с диапазоном
for i in {1..5}; do
    echo "Шаг $i"
done

# C-стиль
for ((i = 0; i < 3; i++)); do
    echo "i=$i"
done

# while — читаем файл построчно
while IFS= read -r line; do
    echo ">> $line"
done < data.txt

# until — пока НЕ выполнится
n=0
until (( n >= 3 )); do
    echo "n=$n"
    ((n++))
done
```

### Схема: for по списку

```
        +-----------+-----------+-----------+
список: | яблоко    | груша     | слива     |
        +-----------+-----------+-----------+
            |            |            |
            v            v            v
        "Фрукт: яблоко"  ...       "Фрукт: слива"
```

Бонус: `break` прерывает цикл, `continue` переходит к следующей итерации.

### Попробуй сам

```bash
bash -c 'for f in a b c; do echo "x$f"; done'
bash -c 'for i in {1..3}; do printf "%s " "$i"; done; echo'
```

### Задание

Напишите цикл, который выводит квадраты чисел от 1 до 10: `1 4 9 ... 100`. Используйте C-стиль `for ((...))`.

**Ответ:**

```bash

```

## Функции

Функции группируют логику и принимают свои собственные параметры (`$1`, `$2`, ...).

```bash
#!/usr/bin/env bash
# функция возвращает код 0/1 и "отдаёт" результат через echo
is_even() {
    local n=$1
    if (( n % 2 == 0 )); then
        return 0
    else
        return 1
    fi
}

# функция-«модуль»: вывод в stdout
greet() {
    local name=$1
    echo "Привет, $name!"
}

# вызовы
for num in 2 3 4; do
    if is_even "$num"; then
        echo "$num — чётное"
    else
        echo "$num — нечётное"
    fi
done

who_string=$(greet "Мария")   # захват вывода функции
echo "Внутри: $who_string"
```

Ключевое: `local` объявляет локальную переменную; возврат значения — через `echo`, а статус — через `return` (код 0–255).

### Схема: как функция «возвращает» результат

```
  x=$(прочитай_файл путь)
      |
```

## Арифметика в bash

Bash оперирует целыми числами. Арифметика — двойные круглые скобки.

```bash
#!/usr/bin/env bash
a=10
b=3

sum=$((a + b))        # 13
diff=$((a - b))       # 7
mult=$((a * b))       # 30
div=$((a / b))        # 3 (целочисленное деление!)
mod=$((a % b))        # 1 (остаток)
pow=$((a ** 2))       # 100 (нет в POSIX, есть в bash)

((++a)); echo "$a"    # 11

# сравнение в (( ))
if (( sum >= 10 )); then
    echo "Больше десяти"
fi

# с плавающей точкой — нужен отвнеший инструмент
bc -l <<< 'scale=4; 10/3'   # 3.3333
```

### Схема: где нужен bc

```
целые:      $(( ... ))    $((7/2)) -> 3
дробные:    bc            echo "scale=2; 7/2" | bc -> 3.50
```

```bash
bash -c 'x=7; y=2; echo "x/y=$((x/y)), остаток=$((x%y))"'
```

## Потоки stdin stdout stderr и конвейеры

У каждой команды три канала: stdin (вход), stdout (вывод), stderr (диагностика/ошибки).

### Схема потоков

```
                 stdin (0)     выводимый результат  ошибки диагностика
команда ----------->+-------+============>+-------+ stderr (2) ---> экран
                     |       |  stdout (1) |       |
                     +-------+             +-------+
                        |                       |
                 файл, клавиатура,         файл, >&2, /
                 `echo "x" | cmd`          redirect 2>
```

### Перенаправления

```bash
ls -la > out.txt          # stdout в файл (перезаписать)
ls -la >> out.txt         # в файл (дозаписать)
ls no-such 2> err.txt     # stderr в файл
ls > all.txt 2>&1         # оба потока в один файл
./script.sh < data.txt    # stdin из файла (здесь квот!)

# и временно заглушить ошибки
rm file 2>/dev/null
```

### Конвейер

```bash
# pipe: stdout первой команды -> stdin второй
cat app.log | grep ERROR | wc -l

# имя файла без расширения
echo "report.tar.gz" | cut -d. -f1

# интеграция с скриптом: ошибки из конвейера
cmd 2>&1 | tee -a build.log     # выводить и писать в файл
```

## Обработка ошибок set -e trap exit-коды

Автоматизация без обработки ошибок — бомба замедленного действия. Три кита: `set -e`, `trap`, явные `exit`.

### set -e, set -u, set -o pipefail

```bash
#!/usr/bin/env bash
set -e          # прекратить при первой ошибке
set -u          # обращаться к необъявленной переменной - ошибка
set -o pipefail # ошибка любой команды в конвейере = ошибка конвейера

# часто пишут одной строкой:
# set -euo pipefail
```

### exit-коды

```bash
#!/usr/bin/env bash
check_failure() {
    if ! command -v rsync >/dev/null 2>&1; then
        echo "rsync не установлен" >&2
        exit 3     # свой код для «нет зависимости»
    fi
}
```

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | общая ошибка |
| 2 | синтаксическая (bash -n) |
| 126 | нет прав на запуск |
| 127 | команда не найдена |
| 130 | прервано Ctrl+C |

### trap — действия при сигнале или выходе

```bash
#!/usr/bin/env bash
cleanup() {
    echo "Чистим временные файлы..."
    rm -rf /tmp/backup_tmp
}
trap cleanup EXIT          # выполнится при любом выходе
trap 'echo "Прервано!"; exit 130' INT   # при Ctrl+C
```

### Попробуй сам

```bash
bash -c 'set -e; false; echo "не выполнится"'
bash -c 'false; echo "выполнится, т.к. без set -e"'
```

## Проверка и отладка bash -n bash -x

### Проверка синтаксиса без запуска

```bash
bash -n script.sh
```

Код `0` (без вывода) — синтаксис в порядке. Код `2` — синтаксическая ошибка, bash печатает строку.

### Отладка по шагам

```bash
bash -x script.sh        # показывает каждую команду с его аргументами (+)
# или внутри скрипта:

set +x                   # выключить
```

### Схема bash -x

```
$ bash -x test.sh
+ echo 'Привет'
+ x=10
+ echo 'x=10'
```

Знак `+` — «эта команда будет исполнена», после подстановки переменных видны реальные значения — золото при отладке.

### Попробуй сам


## Скрипт-шаблон для своих задач

Один раз написанный скелет экономит полчаса на каждой новой задаче. Скопируйте и наполняйте.

```bash
#!/usr/bin/env bash
# --------------------------------------------------------------------
# Описание: что делает скрипт
# Использование: ./skript.sh -e prod -v
# --------------------------------------------------------------------

set -euo pipefail

LOG_BASE="/tmp"
LOG_FILE="$LOG_BASE/skript-$(date +%F).log"

log() {
    printf "[%s] %s\n" "$(date +%H:%M:%S)" "$*" | tee -a "$LOG_FILE"
}

die() {
    log "ОШИБКА: $*"
    exit 1
}

usage() {
    sed -n '2,4p' "$0"
    exit 0
}

env_name="dev"
verbose=0

while getopts "e:vh" opt; do
    case "$opt" in
        e) env_name="$OPTARG" ;;
        v) verbose=1 ;;
        h) usage ;;
        *) usage; exit 1 ;;
    esac
done
shift $((OPTIND - 1))

log "Старт: env=$env_name verbose=$verbose"

if (( verbose )); then
    log "Подробный режим включён"
fi

cd "$(dirname "$0")"          # скрипт исполняется из своей папки

for f in "$@"; do
    [[ -e "$f" ]] || die "Файл не найден: $f"
    log "Обрабатываю: $f"
done

trap 'log "Завершение"' EXIT
log "Скрипт отработал успешно"
```

### Схема структуры

```
шебанг
описание
set -euo pipefail
функции: log / die / usage
getopts-параметры
логика (шаги 1, 2, 3…)
trap EXIT
```

## Проект бекап-скрипт

Финальный проект №1. Требования:

1. Принимает список каталогов (аргументы или конфиг-файл).
2. Проверяет, что каталоги существуют (`-d`).
3. Архив в `~/backups/backup-ГГГГММДД-ЧЧММ.tgz` через `tar czf`.
4. Хранит последние 14 архивов (старые удаляет).
5. Логирует в `~/backups/backup.log`.
6. При успешном бэкапе выводит размер архива.

### Эталон

```bash
#!/usr/bin/env bash
set -euo pipefail

BACKUP_DIR="$HOME/backups"
LOG_FILE="$BACKUP_DIR/backup.log"
KEEP=14
mkdir -p "$BACKUP_DIR"

log() { printf '%s %s\n' "$(date +%F\ %T)" "$*" >> "$LOG_FILE"; }

[ $# -gt 0 ] || { echo "укажите каталоги для бэкапа" >&2; exit 1; }

for dir in "$@"; do
    [[ -d "$dir" ]] || { log "ОШИБКА: нет каталога $dir"; continue; }

    stamp=$(date +%F_%H%M)
    stamp_name=$(basename "$dir")
    archive="$BACKUP_DIR/backup-${stamp_name}-${stamp}.tgz"

    if tar czf "$archive" -C "$(dirname "$dir")" "$(basename "$dir")"; then
        size=$(du -h "$archive" | cut -f1)
        log "OK: $dir -> $archive ($size)"
        echo "OK: $dir ($size)"
    else
        log "ОШИБКА: сбой при архивации $dir"
    fi

    rm -f "$archive"
done

# ротация: оставляем только последние K архива
cd "$BACKUP_DIR"
ls -1t backup-*.tgz 2>/dev/null | tail -n +$((KEEP + 1)) | while read -r old; do
    rm -f "$BACKUP_DIR/$old"
    log "Удалён старый архив $old"
done

log "Бэкап завершён"
```

### Схема работы

```
каталоги -> существуют? -> tar cjf в ~/backups/ -> лог-запись
                              |
                          размер -> вывод
ротация: 14 новых, старые удаляются
```

Выполните: `chmod +x backup.sh && ./backup.sh ~/notes ~/scripts`. Проверьте `~/backups` и лог.

**Ориентир решения:**

## Проект мониторинг системы

Финальный проект №2. Скрипт, который можно поставить в cron каждые 5 минут:

1. Собирает: load average, использование диска `/`, RAM, число процессов, `df`, uptime.
2. Если диск занят > 90% — отправляет предупреждение (пока просто лог + красное сообщение).
3. Пишет отчёт в `~/monitor/report.log` (журнал с меткой времени).
4. Не засоряет вывод — вся диагностика в stderr/лог.
5. Выходной код `0`, если всё ок; `1` — если порог превышен (удобно в cron: cron увидит «failure»).

### Эталон

```bash
#!/usr/bin/env bash
set -euo pipefail

MONITOR_DIR="$HOME/monitor"
LOG_FILE="$MONITOR_DIR/report.log"
DISK_LIMIT=90
mkdir -p "$MONITOR_DIR"

log() { printf '%s %s\n' "$(date +%F\ %T)" "$*" >> "$LOG_FILE"; }

load=$(uptime | awk -F'load average:' '{print $2}')
disk_used=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
ram=$(free -h | awk '/Mem/ {printf "%s/%s", $3, $2}')
procs=$(ps -e | wc -l)

log "load=$load | диск=$disk_used%% | RAM=$ram | процессы=$procs"

echo "Load: $load"
echo "Диск /: $disk_used%"
echo "RAM: $ram"
echo "Процессов: $procs"

if (( disk_used >= DISK_LIMIT )); then
    log "ВНИМАНИЕ: диск занят на $disk_used%"
    echo "!! Диск заполнен на $disk_used% — требуется очистка" >&2
    exit 1
fi

echo "Всё в порядке"
exit 0
```

### Схема работы

```
данные: load / disk / RAM / procs
        |
        v
 отчёт -> report.log (по cron каждые 5 мин)
        |
        v
 диск >= 90% ? -> предупреждение + exit 1
        |
        v
      exit 0
```

### Попробуй сам

Запустите: `./monitor.sh`. Принудительно проверьте ветку тревоги: временно `DISK_LIMIT=1 ./monitor.sh` — дойдёте до `exit 1`.

**Ориентир решения:**

Строка cron:


Дублирование тревог — добавить в этой ветке `>> ~/monitor/alerts.log` в самой ветке предупреждения. Абсолютные пути устраняют проблемы с `PATH`/`HOME` внутри cron.
