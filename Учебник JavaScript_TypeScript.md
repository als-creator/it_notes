## 1. Где работает JavaScript и что такое TypeScript

**JavaScript (JS)** — язык программирования, «родной» для веба. Он способен динамически менять содержимое страницы, реагировать на действия пользователя и обмениваться данными с серверами. Изначально он жил только в браузере, но вошёл и в **Node.js** — серверное окружение, поэтому сегодня JS — это и язык фронтенда, и язык бэкенда.

Две главные среды:

- **Браузер** — здесь JS доступны DOM, события, `fetch`, `localStorage`. Главное окружение — объект `window`, а работа с документом — через `document`.
- **Node.js** — здесь JS доступны файлы (`fs`), сеть, потоки; на нём пишут серверы и утилиты. Запуск: `node script.js`. Глобальных объектов браузера синтаксиса нет (`window`, `document`, `fetch` — нет; зато есть `process`, `require`, `module`).

**TypeScript (TS)** — это **надмножество (суперсет) JavaScript**: любой корректный JS-код — одновременно корректный TS. Он добавляет *статическую типизацию* — возможность описать, какого типа данные ожидают переменные, параметры и функции. В момент компиляции `tsc` проверяет типы и **транспилирует TS в чистый JS**, который и исполняет браузер/Node.

```text
   Ваш код на TypeScript           компилятор tsc             JS для браузера/Node
   ┌───────────────────┐    ┌────────────────────┐    ┌───────────────────┐
   │ let x: number = 1;│    │ проверка типов     │    │ let x = 1;        │
   │ greet("Маша")     │───►│ + удаление типов   │───►│ greet("Маша")     │
   └───────────────────┘    └────────────────────┘    └───────────────────┘
   типы видны тебе и IDE, но           │              браузер/Node видят только JS
   во время выполнения их нет          └─ ошибка типов ~ компилируется НЕ будет
```

Ключевая идея: типы — «проектная» информация, которую TypeScript проверяет **до** запуска (но в рантайме их уже нет — они стираются). Поэтому TS не «медленнее» JS: итоговый код — тот же JS, только уверенный в данных.

### Попробуй сам

1. Откройте любой сайт, `Ctrl+Shift+I` → вкладка **Console**, введите `document.title` — покажет заголовок страницы.
2. Установите Node.js (если нет): `node --version`. Затем файл `hello.js` с `console.log("Привет из Node!");` и запустите `node hello.js`.
3. Установите TypeScript глобально: `npm i -g typescript`. Затем `hello.ts` с `let x: number = 1;` и `npx tsc hello.ts` — появится `hello.js` без типов.

Напишите в браузерной консоли: `console.log(2 + 2 === 4)`, затем `typeof 42`, затем создайте Node-файл и выведите `process.version`. Разберитесь, где выполняется каждый из этих примеров и почему `typeof 42` вернёт `"number"`.

### Самопроверка

**Развернуть ответы:**

1. **Где выполняется JS?** — В браузере (интерфейсы) и в Node.js (сервер, утилиты). Обе среды реализуют один стандарт — ECMAScript.
2. **Является ли TypeScript отдельным языком?** — Нет, это надмножество JS: весь JS валидный TS. TS добавляет типы, а затем «стирает» их, выдавая обычный JS.
3. **Что делает `tsc`?** — Проверяет типы и транспилирует `.ts` → `.js` (и `.d.ts` — описания типов).
4. **Почему в браузерной консоли нет `process.version`?** — `process` — объект среды Node.js; у браузера своё глобальное окружение (`window`).

## 2. Подключение JavaScript к странице

Самый простой способ — тег `<script>` прямо в HTML:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Пример</title>
</head>
<body>
  <h1>Привет</h1>
  <script>
    console.log("Я выполнился при загрузке этой страницы");
    document.querySelector("h1").style.color = "tomato";
  </script>
</body>
</html>
```

Внешний файл: `<script src="script.js"></script>`.

**Ключевой момент** — браузер парсит HTML построчно, и, встретив `<script>`, **останавливает парсинг**, загружает/выполняет скрипт и только потом продолжает. Если скрипт стоит в `<head>` и пытается обратиться к `h1`, который ещё не распарсен, — получите ошибку («h1 is null»). Отсюда три решения:

- ставить `<script>` **в конец `<body>`** — самый надёжный для новичков;
- использовать **`defer`**: `<script defer src="script.js"></script>` — файл догрузится параллельно, а выполнится *после* полного парсинга HTML (все `defer`-скрипты — по порядку);
- использовать **`async`**: `<script async src="script.js"></script>` — выполняется, как только загрузится (порядок не гарантируется; подходит независимым скриптам).

```text
порядок парсинга HTML                       момент выполнения скрипта
─────────────────────────────────────────────────────────────►

<script src="a.js"> (в head, без атрибутов)  ▲ стоп здесь ▲
   ── HTML Parser ──> ЗАГРУЗИ и ВЫПОЛНИ ----► парсинг продолжается

<script src="b.js" defer>                    обычная загрузка параллельно,
                                             выполнение последним по порядку
<script src="c.js" async>                    выполняется сразу после загрузки
```

### Попробуй сам

1. В `index.html` с `<h1 id="title">` выведите в консоль `document.querySelector("#title").textContent`.
2. Переместите скрипт в `<head>` и снова откройте страницу — увидите ошибку. Затем добавьте `defer` — ошибка исчезнет. Сравните порядок с `<script>` без атрибутов.

### Задание

Создайте страницу с двумя файлами: `utilities.js` (определяет глобальную функцию) и `app.js` (её вызывает). Подключите оба через `defer` и убедитесь, что порядок выполнения соответствует порядку подключения. Затем поменяйте на `async` и понаблюдайте разницу в Timeout-логах (Console).

### Самопроверка

**Развернуть ответы:**

1. **Почему `<script>` в `<head>` без defer не найдет `h1`?** — Парсер HTML останавливается на скрипте раньше, чем распарсил `<h1>`.
2. **Разница между `defer` и `async`?** — `defer`: догрузка фоново, выполнение после полного парсинга в порядке подключения. `async`: выполнение сразу по готовности файла, порядок не гарантирован.
3. **Где новичку безопаснее писать скрипты?** — В конце `<body>` (или в `<head>` с `defer`).

## 3. Переменные и типы

Переменные объявляются тремя способами:

```js
var name = "Вася";    // устаревшее: область видимости - функция и глобальная
let age = 30;         // можно переприсвоить значение
const pi = 3.14;      // нельзя переприсвоить (но объект/массив можно менять)
```

| | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Можно переприсвоить | да | да | нет |
| Область видимости | функция/глобальная | блок `{ }` | блок `{ }` |
| «Поднятие» до инициализации | да (undefined) | ошибка (TDZ) | ошибка |
| Рекомендация | не использовать | где нужна переустановка | **по умолчанию** |

Сегодня всё пишут на `const`, а `let` — только когда значение реально переприсваивается (счётчик в цикле). `var` не используют.

Типы данных (примитивы):

```js
typeof 42;                   // "number"
typeof "строка";             // "string"
typeof true;                 // "boolean"
typeof undefined;            // "undefined"  (не назначено значение)
typeof null;                 // "object"     (исторически "null" ошибочно)
typeof {a: 1};               // "object"
typeof [1, 2];               // "object"     (массив — разновидность объекта)
typeof Symbol();             // "symbol"
typeof 10n;                  // "bigint"
typeof function () {};       // "function"   (!)
```

Строгий режим `"use strict"` (в начале модуля/скрипта) включает современный стиль поведения и делает «тихие» ошибки громкими (присвоение несуществующей глобальной переменной, дублирование параметров и т.д.). В ES-модулях (с `type="module"`) строгий режим включён **по умолчанию**.

### Попробуй сам

В консоли выполните: `typeof null`, `typeof [],  typeof [1,2]`, `typeof function(){}`. Затем объявите `let x = 1;` и `const y = 2;`, попробуйте `x = 3;` (ок) и `y = 4;` (ошибка TypeError). Объявите `const obj = {}; obj.name = "Вася"` — это работает, потому что меняется содержимое, а не сама переменная.

### Задание

1. Определите свои `const user = { name: "Инна" }` и попробуйте перезаписать `user = ...` (ошибка) и `user.age = 27` (работает). Объясните, почему второе разрешено.
2. Проверьте `typeof` на 5 разных значениях и запишите результаты.

### Самопроверка

**Развернуть ответы:**

1. **Почему пишут `const` по умолчанию?** — Меньше шансов случайно перезаписать переменную; по смыслу сигнализирует, что ссылка не меняется. `let` — только для реально изменяемых.
2. **Что выведет `typeof null`?** — `"object"` (устаревшее поведение, исправлять нельзя — «сломаются» существующие сайты).
3. **Что такое временная мёртвая зона (TDZ)?** — Интервал до объявления `let`/`const`, где обращение к переменной выбросит ошибку (в отличие от `var`, дающего `undefined`).
4. **Можно ли изменить элементы массива, объявленного `const`?** — Да. `const` фиксирует *ссылку* на массив, а его содержимое менять можно: `arr.push(3)` ок, `arr = [...]` — ошибка.

## 4. Операторы

```js
// арифметика
console.log(7 % 3);        // 1  (остаток от деления)
console.log(2 ** 3);       // 8  (возведение в степень)

// сравнение (строгое ===  и  ==)
console.log(1 === "1");    // false  (разные типы)
console.log(1 == "1");     // true   (с приведением — избегайте)
console.log(3 >= 2);       // true

// логика
console.log(true && false);  // false  (И)
console.log(true || false);  // true   (ИЛИ)
console.log(!true);          // false  (НЕ)

// операторы нулевого слияния ?? и присваивания ??=
const name = null ?? "Гость";   // "Гость": ?? — левый operand, если не null/undefined
let theme = null;
theme ??= "light";               // theme === "light"

// тернарный оператор
const price = 100;
const result = price > 50 ? "дорого" : "дёшево";
```

**Строгое сравнение `===`/`!==`** проверяет и значение, и тип. Всегда используйте его вместо `==`/`!=`, которые неявно приводят типы и порождают неожиданности (`0 == ""` → true!).

Операторы сокращения: `+=`, `-=`, `*=`, `/=`, `++`, `--`.

### Попробуй сам

В консоли выполните `console.log(0 == false)` (→ true: приведение!) и `console.log(0 === false)` (→ false). Затем `console.log(5 % 2)` и `2 ** 3`. Присвойте `a ??= 10` при `a = null` и проверьте.

### Задание

1. Посчитайте: `10 % 3`, `2 ** 0.5`, `"5" - 2`, `"5" + 2`. Объясните разницу `"5" - 2` (число) и `"5" + 2` (строка `"52"` — склейка).
2. Напишите выражение, возвращающее `"чётное"`/`"нечётное"` по числу через тернарный оператор.

### Самопроверка

**Развернуть ответы:**

1. `10 % 3` = 1; `2 ** 0.5` = 1.414...; `"5" - 2` = 3 (вычитание приводит к числу); `"5" + 2` = `"52"` (плюс склеивает строки).
2. **Почему использовать `===`?** — Он не приводит типы, поэтому предсказуем: `0 === false` — false, `"" === 0` — false.
3. **Что делает `??`?** — Берёт левый операнд, если он не `null`/`undefined`; иначе правый (`name ?? "Гость"`). Отличается от `||` тем, что не трогает `0`, `""`, `false`.

## 5. Строки и шаблонные строки

```js
const name = "Мир";

// конкатенация
console.log("Привет, " + name + "!");

// шаблонные строки (бэктики) — подстановка и многострочность
console.log(`Привет, ${name}!`);
console.log(`Можно
переносить
строки.`);

// методы строк
console.log("hello".toUpperCase());      // "HELLO"
console.log("  текст  ".trim());         // "текст"
console.log("abc".startsWith("a"));      // true
console.log("abc".includes("b"));        // true
console.log("abc".slice(1, 3));          // "bc"
console.log("1,2,3".split(","));         // ["1", "2", "3"]
console.log("hello".length);             // 5
console.log("ab".repeat(3));             // "ababab"
console.log("какой-то текст".replace("текст", "айсбэг")); // "какой-то айсбэг"
console.log("42".padStart(4, "0"));      // "0042"
```

Строки в JS иммутабельны: методы `toUpperCase`, `trim`, `slice` возвращают **новые** строки, не меняя исходную.

### Самопроверка

**Развернуть ответы:**

## 6. Массивы и их методы

```js
const fruits = ["яблоко", "груша", "слива"];
console.log(fruits[0]);         // "яблоко"
console.log(fruits.length);     // 3
fruits.push("вишня");           // добавить в конец
fruits.pop();                   // убрать с конца
fruits.unshift("банан");        // в начало
fruits.shift();                 // с начала
```

Методы **перебора/трансформации** — главные инструменты:

```js
const numbers = [1, 2, 3, 4, 5];

// forEach — выполнить действие на каждом элементе (без возврата нового массива)
numbers.forEach((n) => console.log(n));

// map — преобразовать каждый элемент → новый массив той же длины
const doubled = numbers.map((n) => n * 2);     // [2, 4, 6, 8, 10]

// filter — оставить только удовлетворяющие условию
const evens = numbers.filter((n) => n % 2 === 0); // [2, 4]

// reduce — свернуть весь массив в одно значение
const sum = numbers.reduce((acc, n) => acc + n, 0); // 15

// find/some/every — поиск и проверки
const firstBig = numbers.find((n) => n > 3);   // 4 (первый подходящий)
const hasBig = numbers.some((n) => n > 100);   // false
const allPositive = numbers.every((n) => n > 0);// true

// полезное для массивов
console.log([1, 2].concat([3, 4]));   // [1,2,3,4] (копия, не меняет исходники)
console.log([3, 1, 2].sort((a, b) => a - b)); // [1,2,3] (числовая сортировка!)
console.log([1, 2, 3].includes(2));   // true
console.log([1, 2, 3].join(" - "));   // "1 - 2 - 3"
console.log(["a", "b"].at(-1));       // "b" (отрицательный индекс — с конца)
```

Важно: `map`, `filter`, `reduce` **не меняют исходный массив**, а возвращают новый. `forEach` ничего не возвращает — только выполняет побочные действия.

Сравнение: `[1, 2, 3] == [1, 2, 3]` — `false`! Массивы сравниваются по ссылке, а не по содержимому. Для сравнения нужен цикл или `JSON.stringify(a) === JSON.stringify(b)`.

**Развернуть ответы:**

1. `map` — новый массив преобразованных элементов; `filter` — новый массив только с прошедшими условие; `reduce` — свёртка массива в одно значение (сумма, объект-счётчик и т.д.).
2. **Почему `map` не меняет исходный массив?** — Он возвращает новый; исходные данные остаются нетронутыми (импмутабельный стиль).
3. **Как правильно сортировать числа?** — `arr.sort((a, b) => a - b)`. Без компаратора `sort()` превращает элементы в строки и сортирует лексикографически: `[10, 2]` даст `[10, 2]` (`"10" < "2"`), что для чисел — сюрприз.

## 7. Объекты и деструктуризация

Объекты хранят пары «ключ: значение»:

```js
const user = {
  name: "Мария",
  age: 29,
  address: { city: "Москва", street: "Ленина" },
  skills: ["JS", "CSS"],
  greet() { return `Привет, я ${this.name}`; }   // метод
};

console.log(user.name);          // "Мария"
console.log(user["age"]);        // 29  (то же самое, но через строку-ключ)
const key = "name";
console.log(user[key]);          // динамический доступ
```

Доступ к вложенным полям без страха ошибок — **опциональная цепочка** `?.`:

```js
console.log(user.address.street);    // "Ленина"
console.log(user.phone?.number);     // undefined (не упадёт!), а не TypeError
```

**Деструктуризация** — «разобрать» объект/массив на отдельные переменные:

```js
const { name, age } = user;          // name="Мария", age=29
const { city } = user.address;       // вложенность
const { name: displayName } = user;  // переименование: переменная displayName
const { role = "user" } = user;      // значение по умолчанию

// массивы аналогично — по позициям
const [first, second, ...rest] = [1, 2, 3, 4];
// first=1, second=2, rest=[3,4]
```

Деструктуризация в параметрах функции — очень частый паттерн:

```js
function greet({ name, age }) {
  return `Привет, ${name}! (${age})`;
}
greet({ name: "Олег", age: 24 });   // "Привет, Олег! (24)"
```

## 8. Функции

```js
// объявление функции (поднимается в область видимости — можно вызвать ДО объявления)
function add(a, b) {
  return a + b;
}
console.log(add(2, 3));   // 5

// стрелочная функция (arrow) — короткий синтаксис
const multiply = (a, b) => a * b;  // одно выражение, неявный return

// параметры по умолчанию
const greet = (name = "Гость") => `Привет, ${name}!`;

// rest-параметр (собирает все аргументы в массив)
const sum = (...numbers) => numbers.reduce((a, b) => a + b, 0);
sum(1, 2, 3);  // 6

// передача функции как аргумента
const numbers = [1, 2, 3];
const doubled = numbers.map((n) => n * 2);
```

**Проблема `this`**: у обычных функций контекст (`this`) определяется *в момент вызова*. Стрелочные функции создают `this` *при определении* (перенимают `this` внешней области). Поэтому в методах объектов **классов**.arrow-функции работают, но в «обычных» методах — нет:

```js
const counter = {
  count: 0,
  increment() {
    this.count++;
  },
  delay() {
    // arrow внутри метода перенимает this из increment:
    setTimeout(() => {
      this.count++;
      console.log(this.count);
    }, 1000);
  },
};
```

## 9. Условия и switch

```js
// if / else if / else
const age = 18;
if (age >= 18) {
  console.log("Добро пожаловать");
} else {
  console.log("Вы несовершеннолетний");
}

// тернарный оператор (короткий if)
const status = age >= 18 ? "взрослый" : "ребёнок";

// switch
const day = "вторник";
switch (day) {
  case "понедельник":
  case "вторник":
    console.log("Рабочий день");
    break;
  case "суббота":
  case "воскресенье":
    console.log("Выходной");
    break;
  default:
    console.log("Нет данных");
}
```

**Важно:** всегда используйте строгое сравнение `===`. `if (0)` — ложь, `if (1)` — истина, `if ("0")` — истина (!), `if ("")` — ложь. Однако никогда не полагайтесь на неявное приведение — это читается с трудом.

```js
// шаблон:ifer-цепочка (без switch)
const handle = (value) => {
  if (value === null || value === undefined) return "пусто";
  if (typeof value === "string") return `строка: ${value}`;
  if (typeof value === "number") return value;
  return String(value);
};
```

## 10. Циклы

```js
// for
for (let i = 0; i < 5; i++) {
  console.log(i);
}

// while (условие до начала каждой итерации)
let i = 0;
while (i < 5) {
  console.log(i);
  i++;
}

// do...while (тело выполняется минимум один раз)
let j = 0;
do {
  console.log(j);
  j++;
} while (j < 5);

// for...of — перебор iterable (массивы, строки, Set, Map)
for (const fruit of ["яблоко", "груша", "слива"]) {
  console.log(fruit);
}

// for...in — перебор свойств объекта (реже используется; не для массивов!)
for (const key in { a: 1, b: 2 }) {
  console.log(key);
}

// break — выход из цикла; continue — перейти к следующей итерации
for (let n = 0; n < 100; n++) {
  if (n > 3) break;   // выйдем на 4
  console.log(n);      // 0, 1, 2, 3
}
```

**`for...of` vs `for...in`** — частая ошибка новичков:
- `for...of` — перебирает **значения** коллекции (массива, строки).
- `for...in` — перебирает **имена свойств (ключи)** объекта. На массиве `for (const i in arr)` вернёт индексы как строки и заодно системные свойства прототипа — не используйте его для массивов.

## 11. Обработка ошибок

```js
try {
  const result = JSON.parse("{ bad json }"); // бросает SyntaxError
  console.log(result);
} catch (error) {
  console.error("Ошибка:", error.message);  // "Unexpected token..."
  // error.name — тип ошибки
} finally {
  console.log("Выполнится всегда");  // даже при ошибке
}

// выброс собственной ошибки
function divide(a, b) {
  if (b === 0) throw new Error("Деление на ноль");
  return a / b;
}

// новый в ES2022: error cause — причина ошибки
throw new Error("Оригинальная ошибка", { cause: new RangeError(" причинная") });
```

Популярные ошибки:

- `ReferenceError: x is not defined` — переменная не объявлена.
- `TypeError: Cannot read property ... of undefined` — попытка обратиться к свойству `undefined`.
- `SyntaxError` — синтаксическая ошибка (лишняя запятая, незакрытая скобка).
- `RangeError` — числовое значение за пределами (например, `[]` без размера).

Рекомендация: **обрабатывайте ошибки там, где можете их осмысленно исправить**; на верхних уровнях — не ловите всё подряд, давайте приложению «упасть» с информативным сообщением.

## 12. DOM и работа со страницей

**DOM (Document Object Model)** — объектная модель документа, которую браузер строит из HTML (раздел 1 учебника по HTML/CSS). JavaScript получает эти объекты-элементы и управляет ими: читает текст, меняет стили, навешивает обработчики событий, добавляет/удаляет узлы.

**Поиск элементов:**

```js
document.querySelector(".card");        // первый элемент по CSS-селектору
document.querySelector("#main");        // по id
document.querySelectorAll(".card");     // все элементы (NodeList, можно for...of)
document.getElementById("main");        // самый быстрый поиск по id
```

**Чтение и изменение содержимого:**

```js
const h1 = document.querySelector("h1");
console.log(h1.textContent);            // читаем текст
h1.textContent = "Новый заголовок";     // безопасная замена текста
h1.style.color = "tomato";              // инлайн-стиль (эквивалент style="color:...")
h1.classList.add("active");             // добавить класс (лучше, чем style)
h1.classList.remove("active");
h1.classList.toggle("visible");         // переключить класс
```

**События: `addEventListener`**

```js
const button = document.querySelector(".btn");
button.addEventListener("click", (event) => {
  console.log("Нажата кнопка:", event.target);
});
```

`event` — объект события: `event.target` — элемент, на котором сработало; `event.preventDefault()` — отменить действие по умолчанию (отправку формы, переход по ссылке). Событийную модель называют «всплытие и погружение»: событие проходит от `<html>` вниз до цели (capturing), а затем поднимается обратно (bubbling). У `addEventListener` третий параметр описывает фазу и прочее. Делегирование событий (just for mention): обработчик на контейнере ловит события детей — не добавляем обработчики тысяче кнопок.

**Создание и удаление элементов:**

```js
const li = document.createElement("li");   // создали элемент
li.textContent = "Новый пункт";
list.append(li);                           // добавить в конец <ul>

li.remove();                               // удалили узел из документа
```

**Как работает событийный цикл браузера (Event Loop):**

```text
Синхронный код выполняется в единственном потоке — в Call Stack.
Когда встречается асинхронное действие (setTimeout, fetch, обработчик
события), его выполнение передаётся Web API, и стек освобождается.

        ┌─────────────────────────────┐
        │        Call Stack           │  ← выполняется код последовательно
        │  (одна команда за раз)      │
        └──────────────┬──────────────┘
                       │ когда стек пуст —
                       │ берём следующую задачу
        ┌──────────────▼──────────────┐
        │  Macro-очередь              │    Очередь задач (task queue):
        │  setTimeout(f, 1000)        │    события, таймеры, I/O
        │  click-обработчик           │
        ├─────────────────────────────┤
        │  Micro-очередь             │
        │  .then() / await-продолжение│    микро-задачи имеют ПРИОРИТЕТ:
        │  queueMicrotask()           │    обрабатываются перед макро-очередью
        └─────────────────────────────┘

Правило: микро-задачи разгребаются до старта следующей макро-задачи.
Поэтому:
  setTimeout(() => console.log("макро"), 0);
  Promise.resolve().then(() => console.log("микро"));
  // порядок в консоли: "микро", потом "макро"
```

**Что это даёт на практике:** браузер не «зависает» при загрузке данных — пока данные идут через `fetch`, основной код продолжает работать; когда данные готовы, выполняются callback/`.then`/`await-продолжение` (микро-задачи), но только когда стек освободится.

## 13. Асинхронность: callbacks Promise async/await

### Callbacks (обёртки-полковники)

```js
setTimeout(() => {
  console.log("Через 1 секунду");
}, 1000);
```

Callback-стиль быстро превращается в «ад вложенных колбэков» — поэтому в ES6 появились Promises.

### Promise

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

wait(1000)
  .then(() => console.log("прошла 1 секунда"))
  .catch((err) => console.error(err));
```

Промис — «обещание» результата: состояние pending → fulfilled (resolve) или rejected (reject). Цепочка `.then()` — последовательность обработки; `.catch()` — единственная точка перехвата; `.finally()` — как в try/finally.

```js
Promise.allSettled(promises)   // ждать, узнав результат каждого
Promise.all(promises)          // ждать все; упадёт, если хоть один — rejected
Promise.any(promises)          // вернуть первый выполненный
```

### async/await — читать синхронно

```js
async function load() {
  try {
    await wait(1000);                 // ждём 1 сек, не блокируя поток
    const data = await fetchData();   // вторая после первой
    return data;
  } catch (error) {
    console.error("Что-то пошло не так:", error);
    throw error;
  }
}
load().then((data) => console.log(data));
```

`await` работает только внутри `async`. Ошибки обрабатываются обычным `try/catch` (на уровне синтаксиса они поднимаются вверх). Схема:

```text
           ИСПОЛНЕНИЕ                                Web API (вне JS-потока)
   ┌──────────────────────────┐           ┌──────────────────────────┐
   │  Call Stack              │           │  fetch("...")            │
   │  async load() {          │ routine ───► запрос ушёл в Сеть       │
   │   await fetchData()  │   │  (запуск)    (не блокирует стек)      │
   │  }  → suspend (пауза)   │           │  ответ пришёл             │
   └──────────────────────────┘           └───────────┬──────────────┘
           ▲                                          │
           │  возобновляем async-функцию              ▼
           └──────────────────────  Micro-очередь
            (стек освободился)     (.then / await-continuation)
```

### Попробуй сам

В консоли вставьте и выполните:

```js
console.log("1");
Promise.resolve().then(() => console.log("2"));
setTimeout(() => console.log("3"), 0);
console.log("4");
```

Порядок: 1, 4, 2, 3 — потому что микро-задача (2) уходит раньше макро-очереди (3), а синхронный код (1, 4) — прямо в стеке.

### Задание

2. Обработайте отказы: `Promise.reject("боюсь")` с `.catch`, затем с `async/await` + try/catch. Сравните.
3. Скачайте (мысленно) «новостную ленту»: два параллельных `wait`, но с `Promise.allSettled`.

### Самопроверка

**Развернуть ответы:**

1. **В чём разница `.then` и `await`?** — Это два синтаксиса одного и того же механизма; `await` — синтаксический сахар поверх `.then`, читается как линейный синхронный код.
2. **Что возвращает `async function`?** — Promise, который выполняется с `return`, либо `reject` по исключению.
3. **Зачем нужен `.catch`?** — Единственная точка перехвата ошибки любой стадии цепочки `.then`. Без неё отклонённый промис «проглотится» (Unhandled rejection).
4. **`Promise.all` встретит первый `reject` — что с остальными?** — Он «отклонится» немедленно, но остальные промисы продолжат выполняться (просто результат не вернётся).

## 14. fetch и работа с API (JSON)

**JSON** (JavaScript Object Notation) — текстовый формат данных: `{ "ключ": "значение" }`. JS и браузеры понимают его «нативно»: `JSON.stringify(obj)` — в строку, `JSON.parse(str)` — из строки в объект.

`fetch(url, options)` — современный встроенный API для HTTP-запросов:

```js
// GET — получить данные
const response = await fetch("https://api.open-meteo.com/v1/forecast?latitude=55.75&longitude=37.61&current_weather=true");
if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}
const data = await response.json();
console.log(data.current_weather.temperature);

// POST — отправить данные (например, на свой сервер)
await fetch("/api/orders", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ product: "Клавиатура", qty: 1 }),
});
```

`response.ok` — true при 2xx, иначе false; `response.status` — код (200, 404, 500…). Проверять надо всегда — сам по себе `fetch` не бросает исключение на 404.

Практические советы для API-запросов:

- всегда `await` JSON после fetch;
- оборачивайте `fetch` в try/catch и показывайте осмысленную ошибку;
- отделите «функцию API» от UI: `fetchWeather(city)` возвращает данные, а форма рисует результат;
- **CORS**: браузер блокирует запросы на другой домен без разрешительных заголовков сервера. Бесплатные демо-API (Open-Meteo и прочие) их отправляют — работают из браузера.

**Схема работы с внешним API:**

```text
   ваша страница                 open-meteo.com
   ─────────────────────────────────────────────────
   fetch("...?latitude=55.75&longitude=37.61...")
        │  GET-запрос
        └──────────────────────────────────────────►
                                                    │ формирует JSON
        │  HTTP 200 + {"current_weather":{"temperature":17,...}}
        ◄──────────────────────────────────────────┘
   response.ok? → if (!response.ok) throw
   data = response.json()
   рисуем data.current_weather.temperature на странице
```

### Попробуй сам

В браузерной консоли выполните (модулем `await` на верхнем уровне консоль разрешает):

```js

```

Если консоль не поддерживает top-level await — оберните в `async () => {...}()`.

## 15. Классы и прототипы

JS — язык с **прототипным наследованием**: у каждого объекта есть невидимая ссылка на **прототип**, от которого он «берёт» методы, пока не объявит собственные.

```text
Чтение свойства obj.method:

  obj ──► прототип obj (Object.prototype-цепочка)
          │
          ├─ есть свой собственный method?  → используем
          ├─ нет → ищем в proto (прототипе)
          ├─ ещё выше ... вплоть до Object.prototype
          └─ не нашли → undefined

Пример цепочки для массива:
   [1,2,3] ──► Array.prototype ──► Object.prototype ──► null
      push/map    ▲                  constructor и пр.
                   наследуют
class — «синтаксический сахар» над прототипами:
```

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() { return `${this.name} говорит`; }
  static kingdom() { return "Животные"; }   // статический метод (на классе)
}

class Dog extends Animal {                // наследование
  constructor(name, breed) {
    super(name);                          // вызвать конструктор родителя
    this.breed = breed;
  }
  speak() { return `${super.speak()} — гав!`; }  // переопределение
}

const dog = new Dog("Бобик", "Такса");
console.log(dog.speak());                 // "Бобик говорит — гав!"
console.log(Dog.kingdom());               // "Животные"
console.log(dog instanceof Dog);          // true
console.log(dog instanceof Animal);       // true (через цепочку прототипов)
```

Поля класса (ES2022+): `rate = 5` — объявленные напрямую; приватные поля `#x` — видимы только внутри класса. Статические методы вызываются на классе (не на экземпляре).

### Попробуй сам

### Самопроверка

**Развернуть ответы:**

1. **Что такое прототип?** — Скрытая ссылка объекта на «родителя», члены которого заимствуются при чтении. Цепочка обрывается на `Object.prototype` → `null`.
2. **Чем класс отличается от прототипа «по-старинке»?** — Прототипами оперируют напрямую (`Object.create`, `Func.prototype`); `class` — понятный уровень выше: `constructor`, `extends`, `super`, `static`.
3. **Что делает `super()`?** — Вызывает конструктор родительского класса (обязателен, если у родителя есть `constructor`).
4. **Приватное поле `#x` — видно ли снаружи?** — Нет, и это настоящая приватность (в отличие от `_x` — просто соглашения).

## 16. Модули import/export

С модулями код делится на файлы, а `import/export` связывают их. **Это стандарт ES6+ на нативной поддержке браузера и Node 20+.**

`math.js`:

```js
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export default function subtract(a, b) { return a - b; } // единственный default-export
```

`app.js`:

```js
import subtract, { PI, add as sum } from "./math.js";
//         ↑ default-export  ↑ именованные   (переименование через as)

console.log(add(2, 3), PI, subtract(10, 3));
```

Правила:

- по одному `default`-экспорту на файл; импорт без фигурных скобок — это default;
- именованные — в фигурных скобках (можно переименовать `as`);
- в браузере подключение: `<script type="module" src="app.js"></script>`;
- модули загружаются асинхронно и **выполняются в строгом режиме**;
- top-level `await` доступен только в модулях.

Гарантия переиспользования: каждый модуль **выполняется один раз**, импорты разделяют один экземпляр. Динамический импорт `import("./lazy.js")` даёт Promise — для «ленивой» загрузки.

### Попробуй сам

Создайте файлы `math.js` и `app.js` в одной папке, подключите `app.js` с `type="module"` (не забудьте запустить без сервера: браузер откроет страницу по `file://` — модули требуют HTTP-сервера; проще всего `npx serve` или просто запустить локальный сервер через Python: `python3 -m http.server`).

2. Сделайте одним `default`-экспортом и переименуйте при импорте через `as`.

### Самопроверка

**Развернуть ответы:**

1. **Зачем модули?** — Изоляция кода, переиспользование, порядок загрузки стабилен (декларативные зависимости).
2. **Можно ли несколько `default`-экспортов?** — Нет, только один на файл. Именованных — сколько угодно.
3. **Что происходит при `import "./x.js"`?** — Модуль выполняется один раз; если его уже импортировали — вернётся кэшированный результат, повторного выполнения не будет.

## 17. Введение в TypeScript

TypeScript — надмножество JS (схема в разделе 1). Установка и первый прогон:

```bash
# глобально
npm install -g typescript
tsc --version                 # 5.x

# в проекте
npm init -y
npm install -D typescript
npx tsc hello.ts              # скомпилировать один файл
```

Базовые аннотации типов:

```ts
let count: number = 0;
let userName: string = "Аня";
let isReady: boolean = true;
let anything: any = "можно всё";       // any — отключить проверку (избегайте)
let value: unknown = "неизвестный";    // unknown — безопаснее any (нужно сужение)

// массивы
const scores: number[] = [10, 20, 30];
const labels: Array<string> = ["a", "b"];

// кортеж (tuple)
const pair: [number, string] = [1, "один"];

// функции
function add(a: number, b: number): number {
  return a + b;
}
const dot = (a: number): number => a * a;

// optional параметры, default, union
function greet(nickname?: string, emotion: "hi" | "hey" = "hi"): string {
  return `${nickname ?? "Гость"} (${emotion})`;
}
```

**Интерфейсы** — описание «формы» объекта:

```ts
interface User {
  id: number;
  name: string;
  email?: string;          // необязательное поле
  readonly createdAt: Date; // только для чтения
}
const u: User = { id: 1, name: "Олег", createdAt: new Date() };
```

Типы (`type`) — более широкий инструмент: можно делать объединения (union), пересечения и примитивные псевдонимы. Интерфейс удобен для декларации объекта и расширяется `extends`:

```ts
type Status = "active" | "banned" | "pending";
type Id = number | string;

interface BaseUser { id: Id; }
interface Admin extends BaseUser { permissions: string[]; }
```

**Generics** — типы «по параметру», чтобы описать поведение, не привязываясь к конкретному типу:

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
const n = first([3, 7]);        // T  = number → n: number
const s = first(["а", "б"]);    // T  = string  → s: string

type Box<T> = { value: T };
const numBox: Box<number> = { value: 42 };
```

`as const` и `satisfies` (TS 4.9+):

```ts
const directions = ["up", "down"] as const;          // readonly ["up","down"]
const config = { theme: "dark" } satisfies { theme: "dark" | "light" };
```

**tsconfig.json** — настройки компиляции (создаётся `npx tsc --init`). Ключевые опции:

```jsonc
{
  "compilerOptions": {
    "target": "ES2022",           // версия выходного JS
    "module": "ESNext",           // формат модулей
    "strict": true,               // ОБЯЗАТЕЛЬНО включать: строгие проверяемые типы
    "outDir": "dist",             // куда класть скомпилированный JS
    "noEmitOnError": true,        // не писать JS, если есть ошибки типов
    "lib": ["ES2022", "DOM"],     // доступные библиотеки (браузерные API)
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

Идея строгого режима: `strict: true` включает `noImplicitAny` (запрет необъявленных типов), `strictNullChecks` (проверка null/undefined) и др. — это тот уровень, на котором TS действительно защищает от ошибок.

3. Вывод результата в `output`; обрабатывайте деление на ноль (`.catch` ошибки).
4. Красивые стили: flex/grid из учебника HTML, hover-анимации.
5. (Необязательно) разложить по модулям: `operators.js` + `main.js`.

### Проект 4. Погодное приложение через Open-Meteo

**Цель:** async/await, fetch, JSON, ошибки.

План (бесплатный API — open-meteo.com):
1. UI: поле ввода города (или координат), кнопка «Показать погоду», блок результатов.
2. Обращение: `fetch(`https://api.open-meteo.com/v1/forecast?latitude=${lat}&longitude=${lon}&current_weather=true`)`.
3. Проверка `response.ok`, `.catch` — вывод «Погода не загрузилась».
4. Рендер: температура, скорость ветра, иконка «день/ночь» (`is_day`).
5. Пересохранение последнего города в `localStorage` и авто-запрос при старте.
