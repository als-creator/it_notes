## Установка и запуск

### Теория

Go — **компилируемый язык**. Это значит, что специальная программа-компилятор превращает
исходный код (человекопонятный текст) в **машинный код**, который компьютер выполняет
напрямую. Результат — один исполняемый бинарный файл, который можно запустить даже без
установленного Go на целевой машине.

В отличие от интерпретируемых языков (например Python), компиляция происходит **до** запуска.
Если в коде есть синтаксическая ошибка, вы узнаете о ней ещё на этапе сборки, а не в середине
работы программы.

### ASCII-схема: компиляция vs интерпретация

```
КОМПИЛИРУЕМЫЙ ЯЗЫК (Go)
+------------------+      +---------------------+      +------------------+
|  main.go         | ---> |  КОМПИЛЯТОР (go build)| ---> |  myapp (бинарник)|
|  (исходный код)  |      |  один проход        |      |  машинный код    |
+------------------+      +---------------------+      +------------------+
                                                    |
                                                    v
                                              компьютер выполняет
                                              напрямую, ОЧЕНЬ быстро

ИНТЕРПРЕТИРУЕМЫЙ ЯЗЫК (Python, для сравнения)
+------------------+      +------------------------------------------+
|  main.py         | ---> |  ИНТЕРПРЕТАТОР читает и выполняет        |
|  (исходный код)  |      |  код построчно в момент запуска           |
+------------------+      +------------------------------------------+
```

Ключевые команды Go:

```text
go mod init <путь-модуля>   # создать новый модуль (создаёт go.mod)
go run .                    # скомпилировать и сразу запустить
go build .                  # скомпилировать в бинарный файл
go test ./...               # запустить тесты
go vet ./...                # статический анализ кода
```

Как установить Go:

- Скачайте последнюю версию с https://go.dev/dl/ и следуйте инструкциям по установке.
- На Linux (Debian/Ubuntu): `sudo apt install golang-go`
- Проверьте установку: `go version` — выведет что-то вроде `go version go1.24.0 linux/amd64`

### Попробуй сам

Создайте папку проекта, инициализируйте модуль и напишите свою первую программу:

```bash
mkdir hello
cd hello
go mod init hello
```

Создайте файл `main.go`:

```go
// main.go — первая программа на Go
package main        // main — исполняемая программа

import "fmt"        // пакет для вывода на консоль

// main — точка входа программы
func main() {
    // Вывод строки на экран
    fmt.Println("Привет, мир!")
}
```

Запустите:

```bash
go run .
```

Вы увидите: `Привет, мир!`

### Задание

1. Измените строку приветствия на своё имя и запустите программу снова.
2. Добавьте вторую строку вывода: `fmt.Println("Я учу Go!")`.
3. Соберите бинарный файл командой `go build .` и запустите его напрямую
   (на Linux: `./hello`).
4. Что выведет программа, если заменить `Println` на `Print`? Сравните результат.
5. Осознайте разницу: `go run .` компилирует во временную папку и сразу запускает,
   а `go build .` сохраняет бинарник в текущей папке.

### Самопроверка

**Ответы:**

1. Замените строку внутри `fmt.Println(...)` на своё имя — например
   `fmt.Println("Привет, Анна!")`.
2. Либо добавьте строку под первой, либо замените её. Просто:
   `fmt.Println("Я учу Go!")`.
3. `go build .` создаст в папке бинарник `hello`. Запустите его:
   `./hello`. Программа работает без установленного Go, потому что уже
   скомпилирована в машинный код.
4. `Print` не добавляет перевод строки в конце. Поэтому два вызова `Print`
   напечатают текст слитно: `Привет, мир!Я учу Go!`.
5. `go run .` удобен при разработке: компилирует и запускает одной командой.
   `go build .` нужен, когда вы хотите получить готовый файл для запуска
   или распространения.

## Переменные и типы

### Теория

Переменная — это именованное место в памяти для хранения данных. Go — **статически
типизированный язык**: тип переменной определяется один раз и не может измениться.
Компилятор следит, чтобы вы не записали число туда, где ожидается строка.

Основные встроенные типы:

- `int`, `int64`, `int32`, `uint` — целые числа
- `float64`, `float32` — числа с плавающей запятой
- `string` — строка (текст)
- `bool` — истина/ложь (`true`/`false`)
- `byte` — то же, что `uint8` (байт), `rune` — символ в кодировке Unicode

Есть два основных способа объявить переменную: явно с типом и через оператор `:=`
(короткое объявление), когда тип выводится автоматически.

### ASCII-схема: типы данных

```
ПЕРЕМЕННАЯ = (имя, тип, значение)
+--------+------------+----------------------+
|  name  |   тип      |  значение            |
+--------+------------+----------------------+
|  age   |   int      |  25                  |
|  pi    |  float64   |  3.14159             |
|  msg   |  string    |  "привет"            |
|  ok    |  bool      |  true                |
+--------+------------+----------------------+

В памяти компьютера всё это — последовательности нулей и единиц.
Тип говорит компилятору, КАК эти биты интерпретировать и сколько места занимают.
```

### Попробуй сам

```go
package main

import "fmt"

func main() {
    // 1. Явное объявление: var имя тип = значение
    var age int = 25

    // 2. Короткое объявление: тип выводится автоматически
    name := "Анна"
    pi := 3.14159
    isHappy := true

    // 3. Объявление без значения — присваится нулевое значение
    var total int   // total == 0
    var label string // label == "" (пустая строка)

    // Вывод всех переменных
    fmt.Println(name, age, pi, isHappy)
    fmt.Println("total =", total)
    fmt.Println("label =", label)
}
```

### Задание

1. Объявите переменную `height := 1.75` и выведите её.
2. Объявите `var city string = "Москва"` и выведите.
3. Создайте переменную и выведите её тип с помощью `%T`.
4. Что произойдёт, если присвоить `age` строку? Попробуйте и объясните.
5. Объявите переменную без начального значения и проверьте, какое "нулевое"
   значение у `bool` и `float64`.

### Самопроверка

**Ответы:**

1. `fmt.Println(height)` — выведет `1.75`.
2. `city := "Москва"` работает, но по заданию нужно явно:
   `var city string = "Москва"`, вывод: `fmt.Println(city)`.
3. Используйте спецификатор `%T`:
   `fmt.Printf("Тип: %T\n", height)` — выведет `float64`.
4. Компилятор выдаст ошибку: `cannot use "..." (untyped string constant)
   as int value`. Go жёстко следит за типами на этапе компиляции.
   Чтобы конвертировать, нужно явное преобразование: `int("...")` — но для
   строки это не сработает. Это защита от ошибок.
5. `var b bool` → `false`; `var f float64` → `0`. Go автоматически даёт
   переменным "нулевые значения", поэтому нет неожиданных мусорных данных.

## Управление потоками (if, for, switch)

### Теория

Программы редко выполняют все строки подряд. Чтобы ветвить логику и повторять действия,
Go даёт три основные конструкции:

- `if` / `else` — условное ветвление
- `for` — единственный цикл (универсальный: `for` с условием, `for` со счётчиком, `for range`)
- `switch` — упрощённое множественное ветвление

В Go нет ключевого слова `while` — для этого используется `for` с одним условием.
Здесь нет и `do-while`: любое повторение делается через `for`.

### ASCII-схема: архитектура ветвления

```
        [ вход ]
            |
            v
     [ условие if? ]
     /            \
   да/            \нет
    v              v
[ветка then]   [ветка else]
    \              /
     \            v
      \______ [ выход ]
```

### Попробуй сам

```go
package main

import "fmt"

func main() {
    temperature := 30

    // if / else
    if temperature > 25 {
        fmt.Println("Жарко!")
    } else if temperature > 15 {
        fmt.Println("Тепло")
    } else {
        fmt.Println("Холодно")
    }

    // for со счётчиком: от 0 до 4
    for i := 0; i < 5; i++ {
        fmt.Println("Итерация", i)
    }

    // for как while: пока верно условие
    count := 3
    for count > 0 {
        fmt.Println("Осталось:", count)
        count--
    }

    // switch — множественное ветвление
    day := "пятница"
    switch day {
    case "суббота", "воскресенье":
        fmt.Println("Выходной!")
    case "пятница":
        fmt.Println("Почти выходной")
    default:
        fmt.Println("Рабочий день")
    }
}
```

### Задание

1. Напишите `if`, который проверяет, является ли число чётным (оператор `%` — остаток).
2. Выведите числа от 10 до 1 (в обратном порядке) через `for`.
3. Напишите цикл, который суммирует числа от 1 до 100 (итог 5050).
4. Напишите `switch`, который по оценке (2..5) выводит её словесную характеристику.
5. Что выведет `switch` с fallthrough? Разберитесь, что делает `fallthrough`.

### Самопроверка

**Ответы:**

1. `if num%2 == 0 { fmt.Println("чётное") } else { fmt.Println("нечётное") }`.
   Остаток от деления на 2 равен 0 у чётных чисел.
2. `for i := 10; i >= 1; i-- { fmt.Println(i) }` — счётчик с шагом `--`.
3. `sum := 0; for i := 1; i <= 100; i++ { sum += i }; fmt.Println(sum)`.
   Ответ: 5050.
4. Например: `switch grade { case 5: "отлично"; case 4: "хорошо";
   case 3: "удовлетворительно"; default: "неуд" }`.
5. `fallthrough` принудительно переходит к следующему `case`, даже если он
   не подходит. В Go после сработавшего `case` выполнение автоматически
   останавливается (в отличие от C), `fallthrough` «ломает» это правило.

## Функции, возврат нескольких значений, ошибки (error)

### Теория

Функция — именованный блок кода, который можно вызывать многократно. В Go:

- Параметры и возвращаемый тип указываются явно.
- Функция может возвращать **несколько** значений одновременно — это идиоматично.
- Очень часто функция возвращает `(результат, error)`, где `error` сообщает об ошибке,
  а `nil` означает «ошибки нет».

Возврат нескольких значений — ключевая «фишка» Go. Стандартный паттерн обработки ошибок:

```go
value, err := doSomething()
if err != nil {
    // обрабатываем ошибку
    return
}
// используем value
```

### ASCII-схема: функция

```
+----------------+   вызов с аргументами   +-----------------------+
|  вызывающий код | ---------------------> |   функция add(a, b)   |
|  main()         |                        |   return a + b        |
+----------------+ <--------------------- +-----------------------+
                  результат (может быть несколько)
```

### Попробуй сам

```go
package main

import (
    "errors"
    "fmt"
)

// Функция, возвращающая одно значение
func square(x int) int {
    return x * x
}

// Функция, возвращающая ДВА значения
func divide(a, b int) (int, error) {
    if b == 0 {
        // errors.New создаёт объект ошибки
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil // nil = ошибка отсутствует
}

func main() {
    // Вызов функции с одним значением
    fmt.Println("9 в квадрате:", square(9))

    // Вызов функции с двумя возвращаемыми значениями
    result, err := divide(10, 2)
    if err != nil {
        fmt.Println("Ошибка:", err)
    } else {
        fmt.Println("Результат:", result)
    }

    // Попробуем деление на ноль
    _, err2 := divide(10, 0) // _ игнорирует первое значение
    fmt.Println("err2:", err2)
}
```

### Задание

1. Напишите функцию `max(a, b int) int`, которая возвращает большее число.
2. Напишите функцию `swap(a, b string) (string, string)`, возвращающую аргументы наоборот.
3. Напишите функцию `divMod(a, b int) (div, mod int)`, возвращающую частное и остаток.
4. Перепишите `divide`, чтобы она на ноль возвращала ошибку (уже сделано) — объясните
   роль `nil`.
5. Зачем в коде используется `_`? Напишите свой пример, где `_` полезен.

### Самопроверка

**Ответы:**

1. `func max(a, b int) int { if a > b { return a }; return b }`.
2. `func swap(a, b string) (string, string) { return b, a }`.
3. `func divMod(a, b int) (int, int) { return a / b, a % b }` — используется
   именованная пара `(div, mod)`, но в простейшем виде достаточно позиционных.
4. `nil` в Go — это «нулевое значение» указателя/интерфейса/карты и т.д.
   В контексте `error` `nil` означает «всё хорошо, ошибки нет». Принято проверять
   `if err != nil` сразу после вызова.
5. `_` — пустой идентификатор. Он позволяет проигнорировать неиспользуемое
   значение. Go не разрешает иметь неиспользуемые переменные, поэтому если какое-то
   из возвращаемых значений не нужно, «сбрасывают» его в `_`.

## Структуры и методы

### Теория

Структура (`struct`) — это пользовательский тип, объединяющий несколько полей разных типов.
Например, человек имеет имя (строка), возраст (число) и рост (число). Структура — аналог
«записи» в других языках, в Python похоже на класс без методов поведения.

Метод — это функция, привязанная к типу. Объявляется как обычная функция, но перед именем
указывается «приёмник» (receiver):

```go
func (p Person) describe() string { ... }
```

Здесь `p Person` — приёмник. Метод вызывается через точку: `person.describe()`.

### ASCII-схема: структура в памяти

```
Person
+-------------+------+--------+
| name string | age  | height |
+-------------+------+--------+
   "Анна"       30     1.72

Метод:  person.describe() -> "Анна, 30 лет"
```

### Попробуй сам

```go
package main

import "fmt"

// Объявление структуры с полями
type Person struct {
    Name   string
    Age    int
    Height float64
}

// Метод с приёмником-значением (p — копия)
func (p Person) describe() string {
    return fmt.Sprintf("%s, %d лет", p.Name, p.Age)
}

// Метод с приёмником-указателем (*Person) — может менять поля
func (p *Person) haveBirthday() {
    p.Age++
}

func main() {
    // Создание структуры
    alice := Person{Name: "Анна", Age: 30, Height: 1.72}

    // Вызов метода
    fmt.Println(alice.describe())

    // Вызов метода-указателя — возраст увеличится
    alice.haveBirthday()
    fmt.Println("После дня рождения:", alice.describe())
}
```

### Задание

1. Создайте структуру `Book` с полями `Title`, `Author`, `Pages`.
2. Создайте несколько книг и выведите их.
3. Добавьте к `Book` метод `summary()`, возвращающий `"Автор: <автор> — <название>"`.
4. Добавьте метод `readMore(pages int)`, увеличивающий количество прочитанных страниц
   (добавьте поле `ReadPages int`).
5. Объясните разницу приёмника-значения и приёмника-указателя.

### Самопроверка

**Ответы:**

1. `type Book struct { Title, Author string; Pages int }`.
2. `b := Book{Title: "Война и мир", Author: "Толстой", Pages: 1400}` затем `fmt.Println(b)`.
3. По образцу: `func (b Book) summary() string { return fmt.Sprintf("Автор: %s — %s", b.Author, b.Title) }`.
4. Добавьте поле `ReadPages int`, затем
   `func (b *Book) readMore(p int) { b.ReadPages += p }`.
   Указатель нужен, потому что мы изменяем поле структуры.
5. Приёмник-значение `(b Book)` работает с **копией** и не может изменять
   оригинал. Приёмник-указатель `(b *Book)` работает с оригиналом и может
   менять его поля. По соглашению, если метод изменяет структуру, используют
   указатель.

## Указатели

### Теория

Указатель хранит **адрес** переменной в памяти, а не её копию. Это позволяет:

- Изменять значение переменной через функцию.
- Экономить память (не копировать большие структуры).
- Реализовывать общий доступ к данным.

Операторы:

- `&x` — взять адрес переменной `x` (получить указатель).
- `*p` — разыменовать указатель (получить/записать значение по адресу).

Пустой указатель называется `nil`. Разобраться с указателями помогает схема.

### ASCII-схема: указатели

```
ПЕРЕМЕННАЯ                      УКАЗАТЕЛЬ
+------+--------+              +------+----------------+
|  x   |   42   |  <--- адрес  |  p   |  &x (адрес x) |
+------+--------+              +------+----------------+
   возьми &x                             |
        ^                                |
        +--- &x даёт адрес, по которому  |
        |    лежит значение 42           |
        +------------------->  *p == 42
```

### Попробуй сам

```go
package main

import "fmt"

// Функция, принимающая указатель: может изменять оригинал
func addToValue(p *int, delta int) {
    *p = *p + delta // *p разыменовывает указатель: меняем значение по адресу
}

func main() {
    x := 10
    fmt.Println("Начальное x:", x)

    // &x — адрес переменной x
    p := &x
    fmt.Println("p хранит адрес:", p)
    fmt.Println("По адресу p лежит значение:", *p)

    // Передаём указатель в функцию — x изменится!
    addToValue(&x, 5)
    fmt.Println("После вызова x:", x)
}
```

5. Объясните, чем отличается `p *int` от `p int` в параметрах функции.

### Самопроверка

**Ответы:**

   (точное число зависит от системы и запуска).
2. `*p = 200` — теперь `n == 200`.
3. `func zero(p *int) { *p = 0 }`, вызов: `zero(&n)`.
4. `&n` печатает адрес в памяти. Адреса меняются между запусками, потому что
   операционная система выделяет программам разные участки памяти каждый раз.
5. `p int` — это значение (копия). `p *int` — это адрес. При передаче `p int`
   функция не может повлиять на оригинал; `p *int` — может.

## Массивы, срезы (slices), map

### Теория

- **Массив** — фиксированный набор элементов одного типа. Размер задаётся при объявлении
  и не меняется: `[5]int`.
- **Срез (slice)** — динамический «кусок» массива. В реальном коде работают почти всегда
  со срезами, а не массивами. Объявляется без размера: `[]int`. Это ссылка на часть массива
  с длиной и ёмкостью.
- **Map** — словарь «ключ → значение», как dict в Python. Объявление: `map[K]V`.

Срез — гибкая структура: его можно наращивать функцией `append`. Map — это хеш-таблица,
позволяющая быстро находить значение по ключу.

### ASCII-схема: массив vs срез

```
МАССИВ [3]int  — фиксированный размер
+-----+-----+-----+
|  1  |  2  |  3  |   длина всегда 3
+-----+-----+-----+

СРЕЗ []int  — динамический, ссылается на массив
  +------+---------+---------+
   длина   указатель  ёмкость
   3         ...        5
   (можно добавить ещё 2 элемента)
```

```
MAP: ключ -> значение  (быстрая хеш-таблица)
+---------+-------+
|  "apple"| 3     |
|  "banana"| 5    |
+---------+-------+
запрос: m["apple"] -> 3
```

### Попробуй сам

```go
package main

import "fmt"

func main() {
    // МАССИВ — фиксированный размер
    var arr [3]int = [3]int{1, 2, 3}
    fmt.Println("Массив:", arr, "длина:", len(arr))

    // СРЕЗ — динамический
    nums := []int{10, 20, 30}
    nums = append(nums, 40) // добавление элемента
    fmt.Println("Срез:", nums, "длина:", len(nums))

    // Срез из массива (часть)
    part := arr[1:] // от индекса 1 до конца
    fmt.Println("Часть массива:", part)

    // MAP — словарь
    ages := map[string]int{
        "Анна": 30,
        "Пётр": 35,
    }
    ages["Иван"] = 28 // добавить
    fmt.Println("Возраст Анны:", ages["Анна"])

    // Проверка существования ключа
    v, ok := ages["Иван"]
    fmt.Println("Иван есть?", ok, "возраст", v)

    // Перебор map
    for name, age := range ages {
        fmt.Printf("%s: %d лет\n", name, age)
    }
}
```

### Самопроверка

**Ответы:**

   элемент это индекс 2 (индексация с нуля).
2. `nums := []int{}; for i := 1; i <= 10; i++ { nums = append(nums, i) }`.
3. `func sum(nums []int) int { s := 0; for _, v := range nums { s += v }; return s }`.
4. `prices := map[string]float64{"хлеб": 40, "молоко": 70}; fmt.Println(prices["хлеб"])`.

   но следует использовать второе возвращаемое значение `ok`, чтобы не принять
   «нет данных» за реальный ноль.

## Интерфейсы (кратко)

### Теория

Интерфейс — это набор сигнатур методов. Тип «удовлетворяет» интерфейсу автоматически,
если реализует все его методы. Не нужно явно писать «я реализую интерфейс X» — Go проверяет
это сам, по структуре.

Это ключевая идея Go: **структурная типизация**. Любой тип, у которого есть нужные методы,
считается реализацией интерфейса. Это позволяет писать обобщённый код: функция принимает
интерфейс, а вызвать её можно с любым типом, у которого есть нужные методы.

Базовый интерфейс `error` встроен: всё, у чего есть метод `Error() string`, — ошибка.

### ASCII-схема: интерфейс

```
ИНТЕРФЕЙС:  Shape
   методы: Area() float64
        ^
        | (автоматически удовлетворяют типы, у которых есть Area())
   +----+----+
   |    |    |
 Circle  Rect
Area()   Area()
```

### Попробуй сам

```go
package main

import "fmt"

// Определяем интерфейс
type Shape interface {
    Area() float64
}

// Тип Circle с методом Area
type Circle struct {
    Radius float64
}

func (c Circle) Area() float64 {
    return 3.14 * c.Radius * c.Radius
}

// Тип Rect с методом Area
type Rect struct {
    Width, Height float64
}

func (r Rect) Area() float64 {
    return r.Width * r.Height
}

// Функция принимает интерфейс — работает с любым типом Shape
func printArea(s Shape) {
    fmt.Printf("Площадь: %.2f\n", s.Area())
}

func main() {
    c := Circle{Radius: 5}
    r := Rect{Width: 4, Height: 6}

    printArea(c) // работает, т.к. Circle имеет Area()
    printArea(r) // работает, т.к. Rect имеет Area()
}
```

3. `func (c Circle) String() string { return fmt.Sprintf("Круг r=%.1f", c.Radius) }`.
4. Go проверяет **структуру** (набор методов) на этапе компиляции. Если у типа есть
   все методы интерфейса — он автоматически его реализует, без явного объявления.

   (можно подменить объект заглушкой).

## Горутины и каналы (базово)

### Теория

Горутина — это лёгкий поток выполнения, запускаемый ключевым словом `go`.
В отличие от тяжёлых потоков ОС, горутины очень дёшевы: их можно создавать тысячами.

Канал (`chan`) — это «труба», по которой горутины обмениваются данными. Канал:
- буферизированный (`make(chan int, 5)`) — с вместимостью,
- небуферизированный (`make(chan int)`) — синхронная передача: отправитель ждёт получателя.

Классическая фраза Go: *«Do not communicate by sharing memory; instead, share memory by
communicating»* — «Не общайтесь через общую память, а делитесь памятью через общение».
Каналы и есть этот способ общения.

Если главная функция `main` завершится, все горутины остановятся. Поэтому обычно используют
`sync.WaitGroup` для ожидания завершения горутин или каналы для передачи результата.

### ASCII-схема: как работает горутина с каналом

```
go worker(ch)  --->  запускается в отдельной горутине
                        |
                        v
   [ главная ]          [worker]
      |   make(chan int)  |
      |        |          |
      |        v          |
      |   +---------+     |
      |   |  канал  |     |
      |   |  ch     |<----+ worker пишет: ch <- 42
      |   +---------+     |
      |        |          |
      |   ch <- result    |
      |   result := <-ch  |
      |        |          |
      v        v          v

Ключевые операции с каналом c:
    ch <- v     // отправить v в канал (запись)
    v := <-ch   // получить значение из канала (чтение)
    close(ch)   // закрыть канал (больше не будет данных)
```

### Попробуй сам

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

func main() {
    // Создаём небуферизированный канал для строк
    messages := make(chan string)

    // Горутина, которая шлёт сообщение
    go func() {
        time.Sleep(100 * time.Millisecond) // имитация работы
        messages <- "Привет из горутины!"  // запись в канал
    }()

    // Читаем значение из канала (ждём, пока горутина его отправит)
    msg := <-messages
    fmt.Println(msg)

    // Более продвинутый вариант: запуск нескольких горутин
    // и ожидание всех через WaitGroup
    var wg sync.WaitGroup
    for i := 1; i <= 3; i++ {
        wg.Add(1) // добавляем в счётчик ожидаемых горутин
        go func(id int) {
            defer wg.Done() // уменьшаем счётчик, когда горутина закончит
            fmt.Println("Горутина", id, "работает")
        }(i)
    }
    wg.Wait() // ждём, пока все горутины вызовут Done
    fmt.Println("Все горутины завершились")
}
```

### Задание

1. Объясните, почему без чтения `<-messages` выполнение зависнет/не завершится корректно.
2. Создайте буферизированный канал `make(chan int, 3)` и отправьте в него 3 числа
   до чтения.
3. Напишите программу с двумя горутинами: одна пишет в канал, вторая читает из него.

5. Что произойдёт, если отправить в закрытый канал?

### Самопроверка

**Ответы:**

1. Операция `<-messages` блокирует выполнение, пока не придёт значение. Без неё
   горутина успела бы отправить значение в никуда, а `main` завершился бы до вывода.
   Небуферизированный канал ждёт, пока получатель будет готов.
2. `ch := make(chan int, 3); ch <- 1; ch <- 2; ch <- 3` — буфер вмещает 3,
   поэтому запись не блокируется.
3. Отправка и приём в разных горутинах. Например, отправка в одной горутине,
   а `<-ch` в `main`.
4. `WaitGroup` — счётчик ожидания. `wg.Add(1)` перед стартом горутины, `wg.Done()`
   внутри неё (обычно через `defer`), `wg.Wait()` в главной — блокируется, пока счётчик
   не станет нулевым.
5. Отправка в закрытый канал вызывает **панику** (panic). Чтение из закрытого
   канала возвращает нулевое значение. Поэтому закрывают канал, чтобы сообщить
   читателям «данных больше не будет».

## Пакеты и go.mod

### Теория

Программу удобно разбивать на **пакеты** — отдельные файлы/папки с кодом, объединённые по
назначению. Это упрощает поддержку и переиспользование.

Каждый файл начинается с объявления пакета: `package имя`.

- Имена с **заглавной** буквы экспортируются (видны другим пакетам).
- Имена с **строчной** буквы — приватные (видны только в своём пакете).

**Модуль** (go.mod) — это «карта» проекта: он определяет, как называются ваши пакеты и
отслеживает зависимости. Современный Go требует go.mod для любого проекта. Файл создаётся
командой `go mod init`.

### ASCII-схема: структура проекта

```
myproject/
├── go.mod            <- имя модуля, версия Go, зависимости
├── main.go           <- package main (точка входа), импортирует mathhelper
└── mathhelper/       <- пакет mathhelper
    └── math.go       <- package mathhelper
```

### Попробуй сам

Создайте структуру:

```bash
mkdir myproject && cd myproject
go mod init myproject

# создайте папку с пакетом
mkdir mathhelper
```

Файл `mathhelper/math.go`:

```go
// mathhelper/math.go
package mathhelper // имя пакета

// Add — экспортированная функция (с заглавной буквы)
func Add(a, b int) int {
    return a + b
}

// secret — приватная функция (со строчной буквы), видна только здесь
func secret() int {
    return 42
}
```

Файл `main.go`:

```go
package main

import (
    "fmt"
    "myproject/mathhelper" // импорт своего пакета
)

func main() {
    fmt.Println("Сумма:", mathhelper.Add(2, 3))

    // mathhelper.secret() не доступен: имя со строчной буквы
    // fmt.Println(mathhelper.secret()) // <- ошибка компиляции
}
```

Запустите: `go run .`

## Обработка ошибок и defer

### Теория

Go обрабатывает ошибки **явно**, через возвращаемое значение `error`, а не через
исключения (как в Python). Это делает поток ошибок видимым в коде.

`defer` откладывает выполнение вызова до конца текущей функции. Чаще всего `defer` используют
для закрытия ресурсов (файлов, соединений), чтобы гарантировать их освобождение даже при
ошибке. `defer` срабатывает всегда — и при нормальном выходе, и при ошибке.

### ASCII-схема: порядок выполнения с defer

```
func main()
  |  fmt.Println("1")
  |  defer fmt.Println("3")   <- откладывается
  |  fmt.Println("2")
  v
  конец функции -> выполняются отложенные вызовы (в обратном порядке)
                   -> выводится "3"
Результат: 1 2 3
defer запоминает аргументы В МОМЕНТ объявления.
```

### Попробуй сам

```go
package main

import (
    "errors"
    "fmt"
)

// Функция, имитирующая работу с ресурсом, который нужно закрыть
func doWork() error {
    fmt.Println("Открываем ресурс")

    // defer гарантирует закрытие в конце функции
    defer fmt.Println("Закрываем ресурс (defer)")

    fmt.Println("Работаем...")

    // Такой вызов в конце выполнится "3" последним среди defer-ов
    defer fmt.Println("Ещё defer")

    return nil // без ошибки
}

func risky(flag bool) error {
    if flag {
        return errors.New("произошла ошибка")
    }
    return nil
}

func main() {
    doWork()

    // Паттерн проверки ошибки
    err := risky(true)
    if err != nil {
        fmt.Println("Перехватили ошибку:", err)
    } else {
        fmt.Println("Ошибки нет")
    }
}
```

### Задание

1. Объясните порядок срабатывания двух `defer` в `doWork`.
2. Перепишите `doWork`, чтобы в середине она возвращала ошибку; убедитесь, что `defer`
   всё равно сработает.
3. Напишите функцию `openClose()` с `defer`, закрывающим «файл», даже если функция

### Самопроверка

**Ответы:**

1. defer-вызовы выполняются в **обратном** порядке (LIFO): сначала зарегистрирован
   «Закрываем ресурс», затем «Ещё defer». Значит, на выходе сначала выведется
   «Ещё defer», затем «Закрываем ресурс».
2. Добавьте `if ... { return errors.New("...") }` в середине `doWork`. `defer` всё равно
   выполнится при выходе из функции независимо от причины.
3. `defer fmt.Println("Файл закрыт")` в начале функции. Он выполнится при любом return.
4. `func calc() (result int, err error)` — именованные результаты. Можно писать
   `result = 10; return` и Go сам вернёт `10, nil`.
5. `defer` выполняется **всегда**, даже при панике, раннем `return` или ошибке.
   Ручное закрытие в конце легко пропустить при изменении кода. `defer` гарантирует
   освобождение ресурса.

## Работа с файлами

### Теория

Для работы с файлами в стандартной библиотеке Go есть несколько способов:

- `os.WriteFile(path, data, perm)` — записать файл целиком (просто).
- `os.ReadFile(path)` — прочитать файл целиком (просто).
- `os.Create` + `File.Write` / `File.Close` — пошаговая запись.
- `os.Open` + `bufio.Scanner` — построчное чтение больших файлов.
- `os.MkdirAll` — создание папок.

Все операции возвращают `error`, который нужно проверять.

### ASCII-схема: чтение и запись

```
ПРОГРАММА                     ФАЙЛ (на диске)
   |  os.WriteFile(...) ---------> [ содержимое данных ]
   |  os.ReadFile(...)  <--------- [ возвращает []byte ]
   v
Данные в памяти -> обработка
```

### Попробуй сам

```go
package main

import (
    "bufio"
    "fmt"
    "os"
)

func main() {
    filename := "notes.txt"

    // 1. Запись файла целиком ([]byte + права доступа 0o644)
    err := os.WriteFile(filename, []byte("Строка 1\nСтрока 2\n"), 0o644)
    if err != nil {
        fmt.Println("Ошибка записи:", err)
        return
    }

    // 2. Чтение файла целиком
    data, err := os.ReadFile(filename)
    if err != nil {
        fmt.Println("Ошибка чтения:", err)
        return
    }
    fmt.Println("Содержимое файла:\n", string(data))

    // 3. Построчное чтение с помощью bufio.Scanner
    f, err := os.Open(filename)
    if err != nil {
        fmt.Println("Ошибка открытия:", err)
        return
    }
    defer f.Close() // гарантированно закроем файл

    scanner := bufio.NewScanner(f)
    for scanner.Scan() {
        fmt.Println("Строка:", scanner.Text())
    }
}
```

### Задание

1. Запишите в файл список из 5 городов, по одному в строке.
2. Прочитайте этот файл и выведите только города с длиной больше 4 символов.
3. Создайте вложенную папку `data/2025` через `os.MkdirAll` и запишите туда файл.
4. Напишите функцию `countLines(path string) (int, error)`, возвращающую число строк в файле.
5. Что возвращает `os.ReadFile`, если файл не существует?

### Самопроверка

**Ответы:**

1. Соберите строку: `content := "Москва\nСПб\nКазань\nСочи\nТомск\n"` и
   `os.WriteFile("cities.txt", []byte(content), 0o644)`.
2. Прочитайте файл, разбейте на строки и фильтруйте по `len(s) > 4` (для кириллицы
   `len` считает байты — лучше использовать `utf8.RuneCountInString` из `unicode/utf8`).
3. `os.MkdirAll("data/2025", 0o755)` затем записывайте файл по полному пути.
4. `func countLines(p string) (int, error)` — открыть файл, использовать Scanner,
   счётчик строк, вернуть `count, nil`.
5. Если файла нет, `os.ReadFile` вернёт ошибку (часто `open ...: no such file
   or directory`) и `nil` для данных. Всегда проверяйте `err != nil`.

## HTTP-запросы стандартной библиотеки (net/http)

### Теория

`net/http` — стандартная библиотека Go для работы с HTTP. Она умеет и отправлять запросы,
и создавать серверы. Для новичка важны две вещи:

1. Отправка GET-запроса и чтение ответа (`http.Get`).
2. Структура `http.Response` с полями: `StatusCode`, `Body` (поток), `Header`.

`http.Client` нужен для более тонкой настройки (таймауты, повторные запросы, заголовки).

### ASCII-схема: HTTP-запрос

```
Ваш Go-код              Интернет                  Сервер
   |  http.Get(url)  -------- запрос --------->   |
   |  <-------   Ответ (Status + Body)  --------  |
   v
проверяем resp.StatusCode, читаем resp.Body
```

### Попробуй сам

```go
package main

import (
    "fmt"
    "io"
    "net/http"
    "time"
)

func main() {
    // Создаём клиент с таймаутом (чтобы программа не зависла)
    client := &http.Client{Timeout: 10 * time.Second}

    // Отправляем GET-запрос
    resp, err := client.Get("https://httpbin.org/get")
    if err != nil {
        fmt.Println("Ошибка запроса:", err)
        return
    }
    defer resp.Body.Close() // обязательно закрываем Body

    // Читаем тело ответа
    body, err := io.ReadAll(resp.Body)
    if err != nil {
        fmt.Println("Ошибка чтения:", err)
        return
    }

    // Выводим статус и первые 200 символов ответа
    fmt.Println("Статус:", resp.StatusCode)
    fmt.Println("Тело:", string(body))
}
```

### Задание

1. Отправьте GET-запрос и выведите только код статуса (`resp.StatusCode`).
2. Отправьте запрос с параметром в URL (например `https://httpbin.org/get?name=Go`)
   и выведите «параметры» из ответа.
3. Прочитайте заголовки ответа через `resp.Header`.
4. Напишите запрос через `http.NewRequest` с заголовком `User-Agent`.
5. Зачем закрывать `resp.Body` через `defer`?

### Самопроверка

**Ответы:**

1. `client.Get(url)` затем `fmt.Println(resp.StatusCode)`.
2. Добавьте `?name=Go` к URL. httpbin вернёт JSON с полем `args`, где будут параметры.
   Вы сможете увидеть `"args": {"name": "Go"}` в теле.
3. `for k, v := range resp.Header { fmt.Println(k, v) }`.
4. `req, _ := http.NewRequest("GET", url, nil);
   req.Header.Set("User-Agent", "my-go-client");
   resp, _ := client.Do(req)`.
5. `resp.Body` — это поток. Его нужно закрыть, чтобы освободить соединение для
   повторного использования в пуле клиента. `defer` гарантирует закрытие в любом случае.

## Тестирование (go test) кратко

### Теория

В Go есть встроенная система тестирования на основе команды `go test`. Тесты пишут в
файлах с окончанием `_test.go`. Каждая тестовая функция начинается с `Test` и принимает
параметр `*testing.T`.

Для проверки условий используют методы:
- `t.Errorf` / `t.Fatalf` — сообщить об ошибке теста.
- `t.Run` — подтесты.

Команда `go test ./...` запускает все тесты проекта.

### Попробуй сам

Пусть у нас есть функция в `math.go`:

```go
package mathhelper

// Add складывает два числа
func Add(a, b int) int {
    return a + b
}
```

Тест в `math_test.go`:

```go
package mathhelper

import "testing"

// TestAdd проверяет функцию Add
func TestAdd(t *testing.T) {
    got := Add(2, 3)
    want := 5
    if got != want {
        // Сообщаем об ошибке: ожидалось want, получили got
        t.Errorf("Add(2, 3) = %d; want %d", got, want)
    }
}
```

Запуск:

```bash
go test ./...
```

Успешный вывод: `ok myproject/mathhelper`. При ошибке теста вы увидите сообщение
`FAIL` и описание.

### Задание

1. Напишите тест для функции `Sub(a, b int) int`.
2. Напишите тест с несколькими наборами входных данных (табличный тест).
3. Что делает `t.Errorf` в отличие от `t.Fatalf`?
4. Напишите тест, проверяющий обработку дубликатов (например функция, удаляющая
   дубликаты из среза).
5. Зачем тестам параметр `*testing.T`?

### Самопроверка

**Ответы:**

1. `func TestSub(t *testing.T) { if Sub(5, 2) != 3 { t.Errorf("...") } }`.
2. Табличный тест: срез кейсов `struct{ a, b, want int }`, цикл по ним, сравнение.
3. `t.Errorf` помечает тест как неудачный, но продолжает выполнение остальных
   проверок. `t.Fatalf` немедленно останавливает текущий тест.
4. `removeDups` возвращает срез без повторов — тест проверяет, что `[1,2,2,3]`
   превращается в `[1,2,3]`.
5. Параметр `*testing.T` даёт доступ к методам сообщения об ошибках (`Errorf`),
   пропуска теста (`Skip`), параллельного запуска (`Parallel`) и др. Фреймворк сам
   прокидывает этот объект при запуске каждого `Test...`.

## Проекты-практикумы

Это большие упражнения, которые связывают всё изученное. Выполняйте по шагам,
в своём темпе. Каждый проект начинается с `go mod init`.

### Проект 1: Консольный калькулятор с историей

**Цель:** применить переменные, функции, обработку ошибок, циклы, работу с файлами.

Шаги:

1. `go mod init calc` — создайте модуль.
2. Напишите функции `add`, `sub`, `mul`, `div` (возвращают `float64` и `error`).
   Для `div` проверяйте деление на ноль и возвращайте ошибку.
3. В `main` организуйте `for`-цикл: ввод двух чисел и операции (`+ - * /`).
4. Используйте `fmt.Scanln` или `bufio.NewReader` для чтения ввода с консоли.
5. Храните пары «выражение = результат» в срезе строк.
6. При вводе `history` выводите всю историю; `exit` — завершает цикл.
7. Сохраняйте историю в файл `history.txt` через `os.WriteFile` при выходе.
8. Загружайте её при старте через `os.ReadFile` (если файл существует).
9. Проверьте обработку ошибок: неверная операция, деление на ноль, нечисловой ввод.

Ожидаемый результат: интерактивная программа, умеющая складывать, вычитать, умножать,
делить, показывать и сохранять историю.

### Проект 2: Список задач (Todo) в памяти

**Цель:** структуры, срезы, методы, пакеты, вывод.

Шаги:

1. `go mod init todo` — создайте модуль.
2. Определите структуру `Task` с полями `ID int`, `Title string`, `Done bool`.
3. Создайте тип `TaskList []Task` и методы:
   - `Add(title string)` — добавляет задачу.
   - `List()` — выводит все задачи с флагом [x] или [ ].
   - `Done(id int)` — отмечает выполненной.
4. В `main` организуйте командный цикл: `add <текст>`, `list`, `done <id>`, `exit`.
5. Разбейте код по пакетам: `task` (структуры и методы) и `main`.
6. Добавьте сохранение/чтение списка задач в JSON-файл (используйте `encoding/json`).
7. Добавьте команду `del <id>` для удаления задачи.

Ожидаемый результат: полноценный консольный планировщик задач с персистентным
хранением в JSON.

### Проект 3: Простой HTTP-проверщик доступности сайтов

**Цель:** работу с `net/http`, горутины, каналы, параллельность.

Шаги:

1. `go mod init checker` — создайте модуль.
2. Напишите функцию `check(url string) (string, bool)`, которая через `http.Client`
   с таймаутом делает GET-запрос и возвращает адрес + достижим ли он.
3. Список сайтов задайте в срезе строк.
4. Запустите проверку для всех сайтов `параллельно` через горутины, передавая
   результаты в канал.
5. В `main` читайте результаты из канала и выводите таблицу: адрес и статус
   (например `[OK]`/`[FAIL]`).
6. Используйте `sync.WaitGroup`, чтобы дождаться все горутины.
7. Усложнённо: сделайте функция переиспользуемой для произвольного списка адресов,
   передаваемых как аргументы командной строки (`os.Args`).

Ожидаемый результат: быстрый проверщик доступности многих сайтов, работающий параллельно.
