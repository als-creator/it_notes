# Учебник-практикум: HTML и CSS для новичков

**HTML** (HyperText Markup Language) — язык разметки, который описывает структуру веб-страницы: заголовки, абзацы, таблицы, изображения, ссылки. **CSS** (Cascading Style Sheets) — язык стилей, который задаёт внешний вид HTML-элементов: цвета, шрифты, расположение, размеры. Вместе HTML и CSS создают любой веб-сайт, который вы видите в браузере.

Интерактивный учебник в формате: **теория → схема → «Попробуй сам» → «Задание» → «Самопроверка»**. Всё выполняйте в реальном редакторе и браузере: создайте папку `first-site`, внутри неё файл `index.html` и `style.css`, открывайте `index.html` двойным кликом (или командой `xdg-open index.html` в Linux) и обновляйте страницу (F5 / Ctrl+R) после каждого изменения.

## 1. Как браузер получает и рендерит страницу

HTML — это **язык разметки** (HyperText Markup Language): он описывает *структуру* страницы (заголовки, абзацы, картинки, формы), а CSS (Cascading Style Sheets) — её *внешний вид* (цвета, размеры, отступы). Браузер не бывает «просто» — это сложная программа, которая выполняет целый конвейер.

Когда вы вводите адрес и нажимаете Enter, происходит следующее:

1. Браузер проверяет **кэш** (нет ли уже сохранённой копии страницы).
2. По доменному имени через **DNS** браузер узнаёт **IP-адрес** сервера.
3. Устанавливается соединение **TCP** (+ шифрование **TLS**, если адрес начинается с `https://`).
4. Браузер отправляет **HTTP-запрос** (метод `GET` — «дай мне страницу»).
5. Сервер отвечает **HTTP-ответом**: статус-код (200 OK, 404 Not Found и т.д.) и **тело ответа** — HTML-код страницы.
6. Браузер **парсит HTML** и строит **DOM** — дерево объектов документа.
7. Парсятся стили из CSS-файлов — получается **CSSOM** (объектная модель стилей).
8. DOM + CSSOM объединяются в **Render Tree** (что показывать), далее идут **Layout** (расчёт размеров и позиций), **Painting** (отрисовка пикселей) и **Compositing** (сборка слоёв, часто через GPU).
9. Страница отображается и реагирует на пользователя (события мыши, клавиатуры).

```text
URL ──► DNS: домен → IP-адрес
          │
          ▼
   TCP-соединение (+ TLS шифрование для https://)
          │
          ▼
   HTTP GET /  ──────────►  Сервер
                            │
   HTML-код + CSS/JS/картинки ◄── ответ 200 OK (или 404, 500…)
          │
          ▼
   HTML Parser ──► DOM-дерево ─┐
                               ├──► Render Tree ──► Layout ──► Paint ──► Экран
   CSS Parser ───► CSSOM ──────┘         (очертания)   (пиксели)
          │
          ▼
  JavaScript (если есть) ── исполняется, может менять DOM
```

Два полезных следствия из схемы:

- **CSS блокирует рендеринг**: пока стили не загружены и не построен CSSOM, браузер обычно не рисует страницу (иначе был бы «мигающий» неоформленный текст).
- **Скрипты `<script>` тоже останавливают парсинг HTML** в момент их встречи, поэтому их обычно подключают в конце `<body>` или с атрибутами `defer`/`async` (об этом — в учебнике по JavaScript).

Заглянуть внутрь этих процессов помогает **DevTools** (в Chrome, Firefox, Edge — клавиша `F12` или `Ctrl+Shift+I`): вкладка **Elements** показывает DOM, **Network** — запросы и статусы (200, 404…), **Console** — сообщения и ошибки JavaScript, **Performance** — время загрузки.

Откройте пустую вкладку, нажмите `Ctrl+Shift+I` → вкладка **Network**, затем в адресной строке введите любой сайт и Enter. ## 2. Структура HTML-документа

Любая HTML-страница начинается с **`<!DOCTYPE html>`** — декларации, которая говорит браузеру: «перед тобой современный HTML5, не включай режим совместимости». Дальше идёт корневой элемент `<html>` (атрибут `lang` — язык страницы, полезно для доступности и SEO), внутри — `<head>` (служебная информация, не видимая на странице) и `<body>` (видимое содержимое).

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Моя первая страница</title>
</head>
<body>
  <h1>Привет, мир!</h1>
  <p>Это мой первый сайт.</p>
</body>
</html>
```

Что кладут в `<head>`:

- `<meta charset="UTF-8">` — кодировка, чтобы кириллица отображалась корректно.
- `<meta name="viewport" ...>` — обязателен для адаптивных страниц: ширина «вьюпорта» = ширине устройства.
- `<title>` — заголовок вкладки браузера и в результатах поиска.
- `<link rel="stylesheet" href="style.css">` — подключение CSS.
- `<meta name="description" content="...">` — описание для поисковиков.

**Семантические теги** показывают *смысл* блока, а не только его вид. Скелет типичной страницы:

```text
<body>
   ┌──────────────────────────────────────────┐
   │ <header>  Шапка: логотип, название сайта  │
   ├──────────────────────────────────────────┤
   │ <nav>  Меню: Главная | Статьи | Контакты  │
   ├─────────────────────┬────────────────────┤
   │ <main>              │                    │
   │  ┌────────────────┐ │  <aside>           │
   │  │ <article>      │ │  Боковая панель:   │
   │  │  <section> …   │ │  реклама, теги,    │
   │  │ </section>     │ │  «о блоге»         │
   │  └────────────────┘ │                    │
   └─────────────────────┴────────────────────┘
   ┌──────────────────────────────────────────┐
   │ <footer>  Подвал: копирайт, контакты      │
   └──────────────────────────────────────────┘
</body>
```

- `<header>` — шапка страницы или секции.
- `<nav>` — блок навигации (меню со ссылками).
- `<main>` — основное уникальное содержимое страницы (тег один на страницу).
- `<section>` — тематический раздел (обычно со своим `<h1>`–`<h6>`).
- `<article>` — самостоятельный «законченный» фрагмент: запись блога, новость, карточка товара.
- `<aside>` — побочный контент, связанный с основным.
- `<footer>` — подвал: копирайт, контакты, карта сайта.
- Блоки без смысла, нужные только для вёрстки, оборачивают в `<div>`; для строчной группировки — `<span>`.

**Развернуть ответы:**

1. **Зачем нужен `<!DOCTYPE html>`?** — Сообщает браузеру, что документ написан по стандарту HTML5, чтобы не включить «режим совместимости» (quirks mode), ломающий вёрстку.

## 3. Основные теги HTML

Теги бывают **парными** (открывающий `<p>` и закрывающий `</p>`) и **одиночными** (`<br>`, `<img>`, `<input>`). Атрибуты пишутся в открывающем теге: `<a href="...">`.

### Текст и заголовки

```html
<h1>Заголовок самого верхнего уровня</h1>
<h2>Подзаголовок уровня 2</h2>
<h3>Уровень 3</h3>

<p>Обычный абзац. Пробелы и переносы строк внутри него
   браузер схлопывает в один пробел.</p>
<p>Разрывать строки вручную нужно тегом <br>.</p>
<p><strong>Жирный</strong> текст, <em>курсив</em>, <u>подчёркнутый</u>,
   <mark>выделенный маркером</mark>, <s>зачёркнутый</s>.</p>

<blockquote>Цитата — блок с отступом.</blockquote>
<pre>Текст ровно  как   в    коде,
   с сохранением  отступов</pre>
<code>код в строке</code> или целый `<pre><code>...</code></pre>`
```

### Списки

```html
<ul>                          <!-- маркированный список -->
  <li>Первый пункт</li>
  <li>Второй пункт</li>
</ul>

<ol>                          <!-- нумерованный список -->
  <li>Сначала чистим зубы</li>
  <li>Потом завтракаем</li>
</ol>

<dl>                          <!-- список определений -->
  <dt>HTML</dt>
  <dd>язык разметки страницы</dd>
</dl>
```

### Ссылки и картинки

```html
<!-- обычная ссылка -->
<a href="https://developer.mozilla.org/ru/">MDN на русском</a>

<!-- ссылка, открывающаяся в новой вкладке -->
<a href="https://example.com" target="_blank" rel="noopener">example.com</a>

<!-- ссылка-якорь на элемент с id на этой же странице -->
<a href="#kontakty">К контактам</a>
<h2 id="kontakty">Контакты</h2>

<!-- картинка -->
<img src="cat.jpg" alt="Рыжий кот на диване" width="400">

<!-- картинка с подписью -->
<figure>
  <img src="cat.jpg" alt="Кот">
  <figcaption>Рис. 1. Рыжий кот</figcaption>
</figure>
```

`alt` — обязательный альтернативный текст: его видно, если картинка не загрузилась, и его читают скринридеры.

### Таблицы

```html
<table>
  <caption>Прайс</caption>
  <thead>
    <tr>
      <th>Товар</th>
      <th>Цена</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Клавиатура</td>
      <td>4 990 ₽</td>
    </tr>
    <tr>
      <td>Мышь</td>
      <td>1 990 ₽</td>
    </tr>
  </tbody>
</table>
```

`<tr>` — строка, `<th>` — ячейка-заголовок, `<td>` — обычная ячейка. Ряды объединяют атрибутами `colspan` (по горизонтали) и `rowspan` (по вертикали).

### Формы

```html
<form action="/order" method="POST">
  <!-- text — одна строка текста -->
  <label for="name">Имя:</label>
  <input id="name" name="name" type="text" placeholder="Ваше имя" required>

  <!-- email — проверка формата e-mail -->
  <label for="mail">E-mail:</label>
  <input id="mail" name="mail" type="email" required>

  <!-- password — скрытые символы -->
  <label for="pass">Пароль:</label>
  <input id="pass" name="pass" type="password">

  <!-- number — только числа -->
  <label for="age">Возраст:</label>
  <input id="age" name="age" type="number" min="1" max="120">

  <!-- checkbox — галочка -->
  <input id="agree" name="agree" type="checkbox">
  <label for="agree">Согласен с условиями</label>

  <!-- radio — выбор одного из вариантов (одинаковый name) -->
  <input id="del1" name="delivery" type="radio" value="self">
  <label for="del1">Самовывоз</label>
  <input id="del2" name="delivery" type="radio" value="courier">
  <label for="del2">Курьер</label>

  <!-- select — выпадающий список -->
  <label for="city">Город:</label>
  <select id="city" name="city">
    <option value="msk">Москва</option>
    <option value="spb">Санкт-Петербург</option>
    <option value="kzn">Казань</option>
  </select>

  <!-- textarea — многострочный текст -->
  <label for="comment">Комментарий:</label>
  <textarea id="comment" name="comment" rows="4"></textarea>

  <!-- кнопки: submit отправляет форму -->
  <button type="submit">Отправить</button>
  <button type="reset">Сбросить</button>
</form>
```

`<label for="id_поля">` связывает подпись с полем: клик по подписи фокусирует поле, а для checkbox/radio — отмечает его.

## 4. Атрибуты элементов

Атрибуты — это «настройки» тега, записываемые в открывающем теге как `имя="значение"`. Каждый тег имеет свои (для `<a>` — `href`, для `<img>` — `src`/`alt`), но есть универсальные, применимые к любому элементу.

Самое главное — атрибуты-«ручки» для CSS и JavaScript:

- **`id`** — уникальный идентификатор элемента (один на странице!). Используется в CSS-селекторе `#id`, в якорных ссылках (`href="#id"`), в `label[for]` и в JS (`document.getElementById`). Придумывается один раз и больше не встречается.
- **`class`** — список классов через пробел (`class="card card--active"`). Элементов с одним классом может быть сколько угодно. Именно классы — основное «оружие» вёрстки: по ним пишут CSS-селекторы `.card`.
- **`data-*`** — любые свои данные: `data-price="1990"`, `data-id="7"`. В CSS к ним обращаются через `[data-price="1990"]`, в JS — через свойство `element.dataset.price`. Удобно хранить данные, не придумывая несуществующие атрибуты.

```html
<div id="top" class="site-header dark" data-theme="dark">
  ...
</div>
```

```css
/* селекторы для него: */
#top { ... }                       /* по id */
.site-header { ... }               /* по классу */
[data-theme="dark"] { ... }        /* по атрибуту */
```

Правило гигиены: **`id` — для уникальных элементов и якорей, `class` — для «многократного использования», `data-*` — для данных**. Не засоряйте HTML атрибутами для стилей (см. чек-лист в разделе 19).

### Попробуй сам

**Развернуть ответы:**

1. **Сколько элементов могут иметь один и тот же `id`?** — Один. Повторный `id` — ошибка: браузер и так найдёт первый, поведение JS станет непредсказуемым.
2. **Чем хорош `class` на фоне `id`?** — Классы переиспользуемы, их можно комбинировать, и у них ниже приоритет в каскаде (легче переопределять).
3. **Как в JS получить `data-price`?** — `element.dataset.price` (из `data-price`). В CSS — `[data-price]`.

## 5. Подключение CSS

Три способа подключить стили — от «заплатки» до правильного:

1. **Inline-атрибут** — стиль прямо в теге:
   ```html
   <p style="color: red;">Красный текст</p>
   ```
   Работает, но смешивает структуру и оформление, а ещё имеет чудовищный приоритет. Применяйте только для динамических правок из JavaScript.

2. **Тег `<style>` в `<head>`** — стили внутри страницы:
   ```html
   <head>
     <style>
       p { color: green; }
     </style>
   </head>
   ```
   Подходит для маленьких экспериментов; на реальных сайтах так пишут редко.

3. **Внешний файл через `<link>`** — рекомендуемый способ:
   ```html
   <head>
     <link rel="stylesheet" href="style.css">
   </head>
   ```
   Стили можно переиспользовать на всех страницах сайта, браузер кэширует файл и не скачивает его заново.

Оранжевый порядок приоритета одного и того же правила: **inline > `<style>` > `<link>`** — но это лишь вершина айсберга; правила сравниваются не по способу подключения, а по **специфичности** и **порядку** (раздел 7).

### Попробуй сам

1. В `index.html` подключите `link rel="stylesheet" href="style.css"` (порядок: тег `<link>` внутри `<head>`).
2. В `style.css` напишите `body { background: #f4f6f8; }` и откройте страницу — фон изменится.
3. Откройте DevTools → **Sources**, убедитесь, что стилевой файл загрузился. Вкладка **Network** покажет `style.css` со статусом 200.

### Задание

Создайте три «страницы-варианта» одного абзаца: в первой оставьте стили только через `<style>`, во второй — только через `<link>`, в третьей добавьте inline `style="color: red"` поверх подключённого файла. Опишите у себя в блокноте, какой цвет увидите и почему.

### Самопроверка

**Развернуть ответы:**

1. **Почему `<link>` лучше inline-стилей?** — Отдельный файл переиспользуется на всех страницах, кэшируется, а структура не засоряется оформлением. Inline-стили сложно менять (высокий приоритет) и они не переиспользуются.
2. **Может ли быть несколько `<link>`?** — Да, столько, сколько нужно; порядок их подключения влияет на каскад (последний файл «перебивает» ранние при равном приоритете).
3. **Где обычно пишут `<link>`?** — В `<head>`: так CSSOM успеет построиться раньше, чем начнёт рисоваться страница (вспомните схему из раздела 1).

## 6. Селекторы CSS

Селектор — это «адрес», по которому CSS-правило находит элементы. Чем точнее адрес, тем эффективнее правки.

```css
/* 1. По тегу (элементу) — самые общие правила */
p { font-size: 16px; }

/* 2. По классу */
.card { border: 1px solid #ccc; }

/* 3. По id */
#top-header { height: 60px; }

/* 4. По атрибутам */
input[type="email"] { border-color: teal; }
a[href^="https://"] { color: blue; }   /* href начинается с ... */
a[href$=".pdf"] { color: red; }        /* href заканчивается на ... */
[data-theme="dark"] { background: #222; }

/* 5. Комбинаторы (комбинации селекторов) */
/* пробел — потомок на любой глубине */
nav a { color: teal; }
/* > — прямой ребёнок */
section > p { margin: 0 0 12px; }
/* + — следующий сосед (сиблинг) */
h2 + p { font-style: italic; }
/* ~ — любой последующий сосед */
h2 ~ p { color: #444; }
/* :not() — «кроме» */
p:not(.less) { line-height: 1.5; }
/* :is() / :where() — группировка нескольких */
:is(h1, h2, h3) { font-family: Georgia, serif; }
```

Немного терминов: `.*` и `:where()` не добавляют вес (см. следующий раздел), `:not()` принимает простые селекторы; вложенный `nav a` сработает на любой глубине, `nav > a` — только на прямой уровень.

2. **Чем `nav a` отличается от `nav > a`?** — Первый — любой потомок на любой глубине (включая ссылки внутри подменю), второй — только прямые потомки `<nav>`.
3. **Что делает `[href^="https://"]`?** — Селектор по атрибуту с префиксом: `^=` — «начинается с», `$=` — «заканчивается на», `*=` — «содержит».

## 7. Каскад и специфичность

CSS — это **каскадные таблицы стилей**: если на элемент «падает» несколько правил, применяются не все сразу, а по такому алгоритму:

1. **Происхождение и важность**: правила `!important` идут раньше обычных.
2. **Специфичность селектора**: чем «весомее» селектор, тем он сильнее.
3. **Порядок в файле**: при равной специфичности побеждает правило, записанное позже (и inline-стиль, и подключённый позже файл).

Специфичность считается как тройка `(a, b, c)` — количество **id**, **классов/атрибутов/псевдоклассов** и **тегов/псевдоэлементов**:

```text
Вес селектора = сколько чего внутри

  селектор                         a    b    c     вес условно
  ──────────────────────────────────────────────────────────────
  *                                0    0    0     0
  p                                0    0    1     1
  .card                            0    1    0     100
  [type="text"]                    0    1    0     100
  a:hover                          0    1    1     110
  #header                          1    0    0     1000
  main .card p                     0    1    2     120
  #header .card a:hover            1    2    1     1210

  ВАЖНО: сравнение идёт по разрядам слева направо:
  1 id «тяжелее», чем любое число классов;
  1 класс «тяжелее», чем любое число тегов.
```

Проверьте на классическом примере:

```css
p      { color: green; }   /* (0,0,1) */
.red   { color: red; }     /* (0,1,0) */
#blue  { color: blue; }    /* (1,0,0) */
```

```html
<p id="blue" class="red">Какого цвета этот абзац?</p>
```

Ответ: **синий** — даже если переставить правила местами, `#blue` (1,0,0) всё равно сильнее `.red` и `p`. Вот почему злоупотреблять `id` в стилях нельзя: переопределить его почти невозможно. Вместо этого предпочитайте классы — их вес предсказуем и легко перебивается.

## 8. Наследование стилей

Некоторые CSS-свойства **наследуются**: если они заданы родителю, то распространяются на всех потомков, пока те не зададут своё. Наследуются в основном «текстовые» свойства: `color`, `font-*`, `line-height`, `letter-spacing`, `text-align`, `white-space` и другие. Не наследуются «геометрические»: `margin`, `padding`, `border`, `width`, `height`, `background`, `position` и пр.

```text
body { color: #333; font-family: Arial; }
   │
   └─── p { ... }          ← наследует цвет и шрифт
         └─── strong { }   ← наследует тоже
         └─── a { color: teal; }  ← своё значение отменяет наследование
   └─── div { border: 1px solid; }  ← border НЕ наследуется: у потомков своих границ нет
```

Ключевые слова управления наследованием:

- `inherit` — «возьми значение родителя» (например, выставить ссылкам цвет текста родителей: `a { color: inherit; }`);
- `initial` — «верни значение по умолчанию для этого свойства»;
- `unset` — «inherit, если свойство наследуемое, иначе initial»;
- `revert` — «верни к значению из стилей браузера».

### Попробуй сам

## 9. Блочная модель Box Model

Каждый элемент страницы — это **прямоугольник**, состоящий из четырёх «слоёв» изнутри наружу: **content** (содержимое) → **padding** (внутренний отступ) → **border** (граница) → **margin** (внешний отступ). По умолчанию `width`/`height` задают размер именно **content**; слой за слоем суммарная «коробка» растёт наружу.

```text
┌────────────────────────────────────────────────────────┐
│ margin — внешний отступ (прозрачная зона вокруг)        │
│  ┌───────────────────────────────────────────────────┐ │
│  │ border — граница (border-color, border-width)      │ │
│  │  ┌───────────────────────────────────────────────┐ │ │
│  │  │ padding — внутренний отступ (прозрачный)      │ │ │
│  │  │  ┌──────────────────────────────────────────┐ │ │ │
│  │  │  │ content — текст, картинка, дети          │ │ │ │
│  │  │  │ (width / height задают эту область)      │ │ │ │
│  │  │  └──────────────────────────────────────────┘ │ │ │
│  │  └───────────────────────────────────────────────┘ │ │
│  └───────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

Пример: блоку `width: 300px`, `padding: 20px`, `border: 2px`, `margin: 10px` — фактическая занимаемая ширина составит 300 + 20×2 + 2×2 + 10×2 = **364px**. Из-за этого вёрстка «не влезает». Решение — свойство `box-sizing`:

```css
* { box-sizing: border-box; }   /* стандартный сброс/глобальное правило */
```

С `border-box` **`width` задаёт итоговую ширину, включая padding и border**, а content сожмётся внутри. Так считают все современные макеты. Их фрагменты:

| Свойство | Пример | Действие |
| --- | --- | --- |
| `margin` | `margin: 0 auto;` | по вертикали 0, по горизонтали — центрирование блока |
| `margin-top/-right/-bottom/-left` | `margin-top: 20px;` | индивидуальные стороны |
| `padding` | `padding: 10px 20px 10px 20px;` | сверху / справа / снизу / слева |
| `border` | `border: 1px solid #ccc;` | ширина, стиль, цвет |
| `border-radius` | `border-radius: 12px;` | скругление углов |
| `overflow` | `overflow: hidden;` | что делать с вылезающим содержимым |

Запись `margin: 10px 20px;` = по вертикали `10px`, по горизонтали `20px`. `margin: 10px 20px 5px;` — сверху 10, справа/слева 20, снизу 5.

## 10. Единицы измерения

| Единица | Относительно чего | Пример |
| --- | --- | --- |
| `px` | фиксированный пиксель экрана | `width: 300px` |
| `%` | родительского контейнера (ширина/высота) | `width: 50%` |
| `em` | размера шрифта **родителя** | `font-size: 1.5em` |
| `rem` | размера шрифта **корня `<html>`** | `font-size: 1.25rem` |
| `vw` | 1% ширины окна (viewport width) | `font-size: 4vw` |
| `vh` | 1% высоты окна | `height: 100vh` |
| `vmin` / `vmax` | наименьший/наибольший из vw и vh | `font-size: 2vmin` |

Правила:

- `em` — относительно шрифта родителя, поэтому вложенные `em` «цепной реакцией» растут всё больше (0.8em внутри 1.5em внутри 1.5em...). Питомцы-путаники избегают `em` для размеров — для этого есть `rem`.
- `rem` — всегда от шрифта корня (`html`), у которого по умолчанию 16px. `1rem = 16px`, `2rem = 32px`.
- `%` по ширине — от ширины родителя; по высоте — работает, только если у родителя задана высота.
- `vw`/`vh` удобны для «резиновых» блоков на всю величину экрана (hero-экраны), но для текста опасны: при `4vw` на очень узком экране текст станет нечитаемым. Обычно комбинируют, например `font-size: clamp(16px, 3vw, 28px)`.

Затем `html { font-size: 24px; }` — при `1rem` текст станет 24px, при `1em` — останется 16px (родитель p не менялся). 2. **Почему `em` «цепляется» к родителю, а `rem` — к корню?** — `em` берёт размер шрифта непосредственного родителя, `rem` — всегда от `<html>`. Это защищает от каскада вложенных em.
3. **`50vw` — это что?** — 50% ширины окна браузера (viewport), меняется при изменении размера окна.
4. **Зачем `clamp()`?** — Задать «плавающий» размер с минимумом и максимумом: `clamp(16px, 3vw, 28px)` растёт от 16 до 28px и никогда не выходит за пределы.

## 11. Flexbox

Flexbox («флексбокс») — одномерная раскладка: элементы выстраиваются **по одной главной оси** (строка или колонка) и выравниваются по ней, а «вторая» ось — поперечная — используется для выравнивания. Стандартный включённый шаг: `display: flex;` у родителя (он становится **флекс-контейнером**), его прямые дети — **флекс-элементы**.

```text
       главная ось (main axis), направление = flex-direction: row
       ─────────────────────────────────────────────────────────►
       ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
       │ item 1  │   │ item 2  │   │ item 3  │   │ item 4  │
       └─────────┘   └─────────┘   └─────────┘   └─────────┘
                    justify-content: space-between
                (распределение по ГЛАВНОЙ оси от начала к концу)
                                   ▲
                                   │  поперечная ось (cross axis)
                                   │  align-items: center — выравнивает
                                   │  элементы по поперечной оси
```

Ключевые свойства контейнера:

- `flex-direction: row` (по умолчанию, ряд) / `column` (колонка) / `row-reverse` / `column-reverse`.
- `flex-wrap: nowrap` (по умолчанию, всё в одну строку — элементы сжимаются) / `wrap` (перенос на новую строку).
- `justify-content` — распределение **вдоль главной оси**: `flex-start`, `flex-end`, `center`, `space-between`, `space-around`, `space-evenly`.
- `align-items` — выравнивание **поперёк главной** (для каждой строки): `stretch`, `flex-start`, `flex-end`, `center`, `baseline`.
- `align-content` — выравнивание *нескольких строк* (работает только при `flex-wrap: wrap`).
- `gap` — общий отступ между элементами (заменяет старые костыли с margin).

Свойства элементов:

- `flex: 1` — сокращение `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`: элемент растёт, занимая всё свободное место.
- `flex-grow` — коэффициент «разрастания» (сколько займёт свободного места пропорционально соседям).
- `flex-shrink` — как быстро сжиматься при нехватке места.
- `flex-basis` — «базовая» ширина до разрастания/сжатия (`auto` — по содержимому).
- `align-self` — переопределить `align-items` для одного элемента.
- `order` — изменить визуальный порядок (редко, старайтесь не использовать: ломает восприятие скринридерами).

```css
.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 16px;
}
.item { flex: 1; }  /* три .item станут равноширокими */
```

## 12. Grid

Grid — **двумерная** раскладка: и строки, и столбцы. Флекс выстраивает «ленту», грид — «сетку». Включение: `display: grid;` + описание колонок и строк.

```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: auto;
  gap: 16px;   /* отступ и по строкам, и по столбцам */
}
```

```text
grid-template-columns: repeat(3, 1fr)  →  3 равные колонки

   1fr       1fr       1fr
 ┌─────────┬─────────┬─────────┐
 │  A      │   B     │   C     │      ← ряд 1
 ├─────────┼─────────┼─────────┤
 │  D      │   E     │   F     │      ← ряд 2
 ├─────────┼─────────┼─────────┤
 │  G      │   H     │   I     │      ← ряд 3 (дети раскладываются сами)
 └─────────┴─────────┴─────────┘
 gap: 16px — просветы между всеми ячейками
```

Единица `fr` («фракция») — часть свободного места: `grid-template-columns: 2fr 1fr` = широкая колонка + узкая в пропорции 2:1. Варианты записи:

```css
grid-template-columns: 100px 1fr;          /* фикс. + резиновая колонка */
grid-template-columns: repeat(12, 1fr);    /* классическая 12-колоночная сетка */
grid-template-rows: repeat(2, 150px);
grid-auto-flow: row;                       /* заполнение по умолчанию */
```

Позиционирование элемента по сетке (можно переиспользовать flexbox-элементы):

```css
.item {
  grid-column: 1 / 3;   /* с колонки 1 по 3 */
  grid-row: 1 / 2;      /* с ряда 1 по 2 */
}
.item:hover {
  grid-column: 1 / -1;  /* -1 = последняя линия сетки → на всю ширину */
}
```

Именованные области удобны для целого макета:

```css
.page {
  display: grid;
  grid-template-columns: 1fr 3fr 1fr;
  grid-template-areas:
    "header header header"
    "menu   main   aside"
    "footer footer footer";
  gap: 12px;
}
.page > header { grid-area: header; }
.page > nav    { grid-area: menu; }
.page > main   { grid-area: main; }
.page > aside  { grid-area: aside; }
.page > footer { grid-area: footer; }
```

## 13. Позиционирование

Свойство `position` решает, как элемент размещается в потоке документа. Значения:

- **`static`** (по умолчанию) — обычный поток: блоки идут сверху вниз, строчные — в строку. Свойства `top/right/bottom/left` и `z-index` **не работают**.
- **`relative`** — элемент остаётся в потоке, но его можно *сдвинуть* от исходного места (`top`, `left` …). Сдвиг не выталкивает соседей. Также делает элементы-потомки точками отсчёта для `absolute` (`relative`/`absolute`/`fixed` на родителе — «контейнер позиционирования»).
- **`absolute`** — элемент *выпадает из потока* (соседи его «не видят») и позиционируется относительно ближайшего предка с `position` не `static`; если такого нет — относительно viewport.
- **`fixed`** — выпадает из потока и приклеивается к **окну браузера** (не прокручивается вместе со страницей). Типичные плавающие кнопки, модальные окна, «шапки».
- **`sticky`** — гибрид: стоит в потоке, а при прокрутке «прилипает» к указанной границе (например, липкая шапка таблицы).

```text
static      в потоке, top/left не работают
relative    в потоке, но сдвинут от своего места, top/left работают
            (и служит опорой для absolute-детей)
absolute    выпал из потока; координаты — от ближайшего предка с position≠static
fixed       выпал из потока; координаты — от окна браузера; не скроллится
sticky      в потоке; прилипает при прокрутке к границе (top: 0 — липкая шапка)
```

Пример — бейдж «скидка» в углу карточки:

```css
.card        { position: relative; }
.badge       { position: absolute; top: 8px; right: 8px; }
```

Наложение элементов упорядочивает `z-index` (работает только для позиционированных элементах): больший — поверх. Без него поверх окажется тот, что позже в потоке.

### Попробуй сам

3. **Разница между `fixed` и `sticky`?** — `fixed` вообще не участвует в потоке и всегда относительно окна; `sticky` остаётся в потоке и «прилипает» только когда доезжает до своей границы.

## 14. Цвета шрифты и фон

### Цвета

```css
color: red;                      /* имя цвета */
color: #ff0000;                  /* hex: RR GG BB (+AA для прозрачности) */
color: #f00;                     /* короткая запись */
color: rgb(255 0 0);             /* современный синтаксис: rgb(r g b) */
color: rgb(255, 0, 0);           /* традиционная запись с запятыми */
color: rgba(255, 0, 0, 0.5);     /* + прозрачность 0..1 */
color: hsl(0, 100%, 50%);        /* тон (градусы), насыщенность, светлота */
color: hsl(0 100% 50% / 0.5);    /* + прозрачность через / */
```

Обычно в проекте используют hex и css-переменные (раздел 17), для прозрачности — `rgb(... / ...)` или `hsl(... / ...)`.

### Шрифты

```css
body {
  font-family: "Inter", system-ui, "Segoe UI", Arial, sans-serif;
  /* список: браузер берёт первый установленный шрифт */
  font-size: 16px;
  font-weight: 400;         /* обычный; 700 — жирный; можно "bold" */
  font-style: normal;       /* italic — курсив */
  line-height: 1.5;         /* межстрочный интервал (без единиц = множитель) */
  letter-spacing: 0.02em;   /* межбуквенный интервал */
  text-align: left;         /* left | center | right | justify */
  text-decoration: none;    /* none | underline | line-through */
  text-transform: uppercase;/* uppercase | lowercase | capitalize */
  white-space: nowrap;      /* не переносить строки */
}
```

Шрифты без засечек (`sans-serif`) читабельнее на экране. `line-height: 1.5` без единиц — «полторы строки», самый безопасный способ задать межстрочный интервал.

### Фон

```css
.box {

```

## 15. Адаптивность и media queries

Адаптивный сайт одинаково удобен на телефоне и на мониторе. Три кита:

1. **Гибкая ширина**: вместо фиксированных `width: 1200px` — `max-width: 1200px; margin: 0 auto;` и относительные размеры (`%`, `fr`, `rem`, `vw`).
2. **Meta viewport** в `<head>`: `<meta name="viewport" content="width=device-width, initial-scale=1">` (без него мобильные браузеры рисуют страницу «как на экране 980px» и зумом-хвостом в маленькое окно).
3. **Media queries** — условные стили по характеристикам устройства (`min-width`, `max-width`, `orientation`).

```css
/* база (mobile-first: сначала стили для телефона) */
body { font-size: 16px; }
.menu { flex-direction: column; }

/* планшет: ширина экрана ≥ 720px */
@media (min-width: 720px) {
  .menu { flex-direction: row; }
  body  { font-size: 17px; }
}

/* десктоп: ≥ 1100px */
@media (min-width: 1100px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}
```

Принцип **mobile-first**: пишем базовые стили для маленьких экранов, а `min-width`-условиями добавляем улучшения на бóльших. Тестировать удобно в DevTools: иконка устройства (слева вверху панели) включает режим смены разрешений.

```text
300px   ─┐ базовые стили: колонка, крупные кнопки, всё вмещается
          │
720px   ─┼ @media (min-width: 720px): меню в ряд, две колонки
          │
1100px  ─┘ @media (min-width: 1100px): три колонки, больше воздуха
```

Дополнительные инструменты адаптивности: flexbox с `flex-wrap`, grid с `auto-fit`, `minmax()` — `grid-template-columns: repeat(auto-fit, minmax(220px, 1fr))` сам кладёт карточки в ряд по мере расширения.

2. **Что означает `min-width: 720px`?** — «Примени стили, когда ширина окна **не меньше** 720px» (срабатывает и для 720, и для 2000).

4. **Что делает `minmax(220px, 1fr)` с `auto-fit`?** — Колонки не меньше 220px, а их число подстраивается под ширину контейнера: карточки сами переносятся на новые ряды.

## 16. Псевдоклассы и псевдоэлементы

**Псевдоклассы** — состояния элемента (`:hover` — под курсором, `:focus` — получил фокус, `:nth-child` — «какой по счёту ребёнок»). **Псевдоэлементы** — «виртуальные» фрагменты внутри элемента (`:before` рисует контент перед содержимым, `:after` — после), полезны для декораций и бейджей.

```css
/* псевдоклассы состояния */
a:hover       { color: #d00; }
button:focus  { outline: 3px solid #3498db; }
input:disabled { opacity: 0.5; }
input:checked + label { font-weight: bold; }

/* позиционные псевдоклассы */
li:first-child   { font-weight: bold; }
li:last-child    { margin-bottom: 0; }
li:nth-child(odd)      { background: #f4f6f8; }  /* нечётные */
li:nth-child(3n + 1)   { color: teal; }          /* каждое третье, начиная с 1-го */

/* структурные и логические */
p:not(.no-margin) { margin-block: 0 1em; }
div:empty { display: none; }      /* пустые скрыть */
a:link, a:visited { ... }         /* непросмотренные/просмотренные */

/* псевдоэлементы */
p::first-letter { font-size: 2em; }         /* первая буква */
p::first-line   { font-weight: bold; }      /* первая строка */
li::marker      { color: teal; }            /* маркер списка */
.card::after {
  content: "Новинка";
  position: absolute; top: 8px; right: 8px;
  background: #e74c3c; color: #fff; padding: 4px 8px; border-radius: 6px;
}
```

Псевдоэлементы с `content` требуют обязательно либо `content: "..."/""`, либо `content: none`. `::before`/`::after` — «дети» элемента (позиционируются относительно него, если элементу задать `position: relative`).

### Попробуй сам

Повесьте `a:hover { color: #d00; }` и `button:focus { outline: 3px solid #3498db; }`. Кликните Tab по странице — фокус переходит по элементам, и вы увидите outline. Сделайте список `<li>` и добавьте `li:nth-child(odd) { background: #f0f0f0; }` — полосатую верстку.

### Задание

1. Сделайте карточки с бейджем «-20%» через `.product::after`.
2. Окрасьте маркеры маркированного списка через `li::marker`.
3. Подсветите первый абзац каждой секции: `section > p:first-of-type { font-size: 1.1em; }`.

### Самопроверка

**Развернуть ответы:**

1. **Чем псевдокласс отличается от псевдоэлемента?** — Псевдокласс — *состояние* существующего элемента (`:hover`); псевдоэлемент — *часть* или «виртуальный» фрагмент (`::before`, `::first-letter`). В CSS имена псевдоэлементов пишут с двойным двоеточием.
2. **Что делает `li:nth-child(odd)`?** — Окрашивает нечётных детей-`li` (1-е, 3-е…). Чётные — `even`.
3. **Обязателен ли `content` у `::after`?** — Да, иначе псевдоэлемент просто не отобразится.
4. **Зачем `:focus`?** — Визуально отметить элемент, которому пользователь переключил клавиатурный фокус — критично для доступности (доступно и для мыши, но наведение `:hover` там не помощник).

## 17. Переменные CSS

Переменные (custom properties) — способ переиспользовать значения без повторного переписывания. Объявляются в любом правиле через `--имя: значение`, читаются через `var(--имя [, fallback])`.

```css
:root {
  --color-primary: #2c3e50;
  --color-accent: #e74c3c;
  --space: 16px;
  --radius: 10px;
}

.card {
  background: var(--color-primary);
  color: #fff;
  border-radius: var(--radius);
  padding: var(--space);
}
.btn {
  background: var(--color-accent, #900);   /* fallback, если --color-accent не определён */
}
```

Переменные **наследуются** и **каскадируются**: значение, заданное в предке, доступно потомкам, а более «ближний» префикс перекрывает. Поэтому темы оформления делают так:

```css
:root { --bg: #fff; --text: #222; }
[data-theme="dark"] { --bg: #222; --text: #eee; }
body { background: var(--bg); color: var(--text); }
```

Переключение темы = смена `data-theme` на `<html>` (например, из JS `document.documentElement.dataset.theme = 'dark'`). Остальной CSS не трогается.

### Попробуй сам

Опишите в `:root` переменные `--gap`, `--accent`, `--shadow`. Примените их к карточкам и кнопкам. Затем в DevTools (вкладка Styles) измените значение `--accent` прямо в правиле `:root` — вся страница мгновенно сменит акцентный цвет.

### Задание

Соберите «тему»: базовые переменные в `:root` в светлом оформлении, переопределения для `[data-theme="dark"]`, и переключатель темы — кнопку, которая (чуть-чуть JS, из следующего учебника) меняет `data-theme` на `html`. Проверьте, что контент при переключении подхватывает новые `--bg` и `--text`.

### Самопроверка

**Развернуть ответы:**

1. **Зачем нужны CSS-переменные, если есть «обычные» значения?** — Один источник правды: поменял акцент в `:root` — обновилось всё на сайте; удобно для тем и переиспользования.
2. **Что такое `var(--x, 10px)`?** — Аргумент после запятой — *значение по умолчанию*, если переменная `--x` не определена.
3. **Каскадируются ли переменные?** — Да: у потомка своё значение, если он его переопределил, иначе — от предка.

## 18. Анимации и переходы

### transition — плавное изменение при смене состояния

```css
.btn {
  background: #3498db;
  transition: background 0.3s ease, transform 0.2s ease;
}
.btn:hover {
  background: #2980b9;
  transform: translateY(-2px);   /* приподнялась на 2px */
}
```

`transition: свойство длительность функция-ускорения задержка` — для нескольких свойств через запятую или `transition: all 0.3s` (просто, но чуть менее производительно). `ease` (по умолчанию), `linear`, `ease-in`, `ease-out`, `cubic-bezier(...)`.

### animation + @keyframes — самостоятельное воспроизведение

```css
@keyframes fly-in {
  from { transform: translateY(20px); opacity: 0; }
  to   { transform: translateY(0); opacity: 1; }
}

.hero {
  animation: fly-in 0.6s ease-out both;
}
```

```css
@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.05); }
  100% { transform: scale(1); }
}
.pulse { animation: pulse 2s ease-in-out infinite; }
```

Параметры: `animation-name`, `-duration`, `-timing-function`, `-delay`, `-iteration-count` (`infinite`), `-direction` (`alternate` — туда-обратно), `-fill-mode` (`both` сохраняет состояние до старта/после конца), `-play-state` (`paused` — пауза).

Важно про производительность: плавнее и дешевле анимировать `transform` (особенно `translate`), `opacity` и, в новых браузерах, `filter` — они идут на GPU, фактически «композитируются». Свойства вроде `width`, `height`, `margin`, `top` заставляют браузер пересчитывать layout каждый кадр (вспомните схему рендеринга) — заметно на медленных устройствах.

```text
                    пересчёт
ширина/высота:      меняется layout → paint (виляет соседями)  ✗ медленно
transform:          только слой компизируется (GPU)             ✓ быстро
opacity:            только прозрачность слоя                    ✓ быстро
```

### Попробуй сам

Сделайте кнопку с плавным появлением: `@keyframes` из `opacity: 0; scale(0.9)` в полную, `animation: 0.4s ease-out both`. Затем наведите курсор — `transition: transform 0.2s; :hover { transform: scale(1.04); }`.

### Задание

1. Реализуйте мигающий маркер «Лайв» (не пропустите: `animation: blink 1s ease-in-out infinite`).
2. Добавьте появление карточек с задержкой: `animation-delay: calc(var(--i) * 0.1s)` (индекс через CSS-переменную, заданную в inline-стиле).
3. Убедитесь, что все анимации — только на `transform`/`opacity`.

### Самопроверка

**Развернуть ответы:**

1. **transition vs animation?** — transition — «от состояния А к состоянию Б» при событии (наведение, смена класса); animation — независимое воспроизведение с фазами `@keyframes` (можно «по кругу», зациклить, менять направление).
2. **Что означает `both` в `animation-fill-mode`?** — Элемент держит начальное состояние до старта (`backwards`-часть) и конечное после конца (`forwards`-часть).
3. **Почему `transform` анимировать лучше, чем `margin`?** — `transform` не трогает layout соседей и выполняется на GPU; изменение margin вызывает перерасчёт layout.
4. **Как остановить анимацию на паузе?** — `animation-play-state: paused;`.

## 19. Практические советы и чек-лист

### Советы

- Пишите **семантично**: `main`, `nav`, `article`, `footer` вместо сплошных `<div>`. Это доступность (скринридеры), SEO и понятный код.
- **Не злоупотребляйте `id` в CSS** — приоритет не перебить; для стилей по умолчанию используйте классы.
- Начинайте каждый файл со сброса привычных различий: `* { box-sizing: border-box; }` и обнуление margin у `body`.
- Размеры текста — в `rem` (переменные корня), отступы — в `rem`/пространственных переменных, ширины — `%`, `fr`, `minmax`.
- Центрируйте блоки: `max-width: 1000px; margin: 0 auto;`.
- Не задавайте жёсткие `width`/`height` тексту: пусть он «дышит» (проверяйте длинные слова и фразы без пробелов).
- Проверяйте страницу на мобильном разрешении (Device Mode) — до работы с десктопом.
- Изображения: всегда `alt`, а современный `loading="lazy"` для картинок ниже первого экрана.
- Именование классов — по-**BEM**-принципу (`block__element--modifier`) либо логичное своё: `.card`, `.card__title`, `.card--featured`.
- Обновляйте браузер (F5/Ctrl+R) после каждой правки, а ошибки ищите в DevTools → Console.

### Чек-лист страницы перед «сдачей»

```text
[ ] начинается с <!DOCTYPE html>, есть lang="ru"
[ ] <meta charset="UTF-8"> и <meta name="viewport" ...> в <head>
[ ] единственный <title>, есть <main>, семантика в порядке
[ ] у всех <img> заполнен alt
[ ] формы: у каждого поля <label>, типы input адекватны
[ ] классы и id осмысленны, нет дублей id
[ ] box-sizing: border-box задан глобально
[ ] отступы консистентны (одна и та же переменная/принцип)
[ ] механизм layout — flex или grid, а не костыли с margin
[ ] адаптивность проверил: 360px, 768px, 1920px без горизонтального скролла
[ ] интерактивные элементы имеют :hover и :focus
[ ] фокус-стили не снесены по неосторожности outline: none (это анти-доступность)
[ ] цвета подписаны в переменных CSS (:root)
[ ] анимации — на transform/opacity, длительности разумные (0.15s–0.5s)
[ ] горизонтальный скролл отсутствует (проверяется увеличением вьюпорта в DevTools)
```

### Попробуй сам

Возьмите любую собранную вами страницу и прогоните её по чек-листу. Откройте вкладку **Lighthouse** в DevTools (или https://pagespeed.web.dev) и «нажмите» Generate report — красным отметятся реальные проблемы (доступность, производительность, SEO).

### Задание

Исправьте минимум 5 пунктов из чек-листа в своей странице и задокументируйте, что именно изменилось и почему.

### Самопроверка

**Развернуть ответы:**

1. **Почему `outline: none` без замены — плохо?** — Человек, навигация которого — клавиатура (или экранный ридер), лишается индикатора фокуса. Нужно оставить видимый `:focus-visible`-стиль.
2. **Что даёт `<html lang="ru">`?** — Сообщает браузерам и скринридерам язык, влияет на переводы и произношение.
3. **Почему `id` нельзя использовать для «всех карточек»?** — `id` обязан быть уникальным; для повторяющихся элементов — `class`.

## 20. Проекты-практикумы

Четыре проекта, в каждом из которых используется всё, что было выше. Работайте последовательно: каждый проект — отдельная папка (`projects/01-card/`, etc.).

### Проект 1. Страница-визитка

**Цель:** применить структуру документа, семантику, типографику, ссылки-якоря.

План:
1. `index.html` со структурой `header/nav/main/section/footer`, `<meta>` и `title`.
2. Hero-блок с аватаром (`<img>`) и краткой презентацией (`h1`, `p`, кнопка-ссылка).
3. Ссылка-якорь «Наверх» (`href="#top"` и `id="top"`).
4. Стили: переменные `:root`, `font-family` системная, отступы в `rem`, кнопки с `:hover` и `transition`.
5. Липкая шапка (`position: sticky; top: 0`).
6. Прогнать через чек-лист и Lighthouse.

### Проект 2. Лендинг курса (Flexbox/Grid)

**Цель:** полноценный макет страницы.

План:
1. Шапка-меню на flexbox с логотипом и 3 ссылками (`justify-content: space-between`).
2. Hero-блок на `100vh` с центровкой (`display: flex; align-items: center; justify-content: center`).
3. Секция «Преподаватели» — 3 карточки через `repeat(3, 1fr)`.
4. Секция «Тарифы» — таблица с `thead/tbody`.
5. Форма обратной связи (email + textarea + submit).
6. Медиа-запросы: при `max-width: 720px` колонки сетки схлопываются в одну.
7. Анимация появления секции через `@keyframes` + `animation-delay`.

### Проект 3. Интернет-магазин карточек

**Цель:** переиспользование классов, data-атрибуты, бейджи.

План:
1. Сетка карточек товара: `<article class="product" data-category="socks" data-price="490">`.
2. Внутри карточки — изображение, название, описание, цена, кнопка «В корзину».
3. Бейдж «Хит» через `.product::after` (только для `.product[data-badge="hit"]`).
4. Фильтры-подсветка при наведении на карточку (`:hover`).
5. `:nth-child` раскрасить чётные товары одинаковым фоном.
6. Адаптивность: `repeat(auto-fit, minmax(220px, 1fr))`.
7. Производительность: `loading="lazy"` у картинок.

### Проект 4. Адаптивный сайт-портфолио

**Цель:** собрать всё: грид-контекст + тема + анимации + доступность.

План:
1. Макет на `grid-template-areas` (header/nav/main/aside/footer).
2. Темы: переменные в `:root` и `[data-theme="dark"]`, переключатель (кнопка, меняющая `data-theme` через JS).
3. Галерея проектов: сетка `grid`, карточки с `figure > img + figcaption`.
4. Липкие элементы: шапка `sticky`, плавающая кнопка «Вверх» `fixed`.
5. Мобильная версия: переключение grid-областей в одну колонку.
6. `:focus-visible` стили для всех интерактивных элементов.
7. Финальный прогон: чек-лист + Lighthouse > 90 по доступности и производительности.
